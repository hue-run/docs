In a Hue evaluation your agent runs in your process. A case with app calls gets a fresh simulated world; an answer-only case gets reviewed task and context without one. Hue never executes the agent, intercepts traffic or adds tools. Commit one helper to point the agent's own app clients at mirrors.

Connect agents calling apps over MCP or REST. Examples use the pinned `@hue-run/sdk`; `--command` supports any language without a Hue package. See [simulations](/evaluations/simulations) for callbacks and [`hue eval`](/sdks/cli#run-an-evaluation) for commands.

<Note>
Preview: Hue's mirrors answer at `https://app.hue.run/api/sim/…`, but the simulation gateway is not yet a released Hue Cloud capability. Gmail (MCP, REST) and Slack (Web API, MCP) are its established mirrors; other apps' mirrors are experimental and certify no fidelity.
</Note>

## How mirrors work

Each app has a stable mirror URL:

```text
https://app.hue.run/api/sim/<real host>/<real path>
```

A Gmail REST mirror is `https://app.hue.run/api/sim/gmail.googleapis.com/gmail/v1`; Gmail MCP is `https://app.hue.run/api/sim/gmailmcp.googleapis.com/mcp/v1`. The agent calls the mirror with a per-run **world token** instead of the real credential. Hue answers in the app's format, records calls in the world's ledger, seals it at case end and scores it.

Mirrors serve the app's captured catalog or the tool list recorded by the source trace, so the agent sees production's tools. Hue adds none: an eval-ready agent receives neither deprecated `context.tools`/`context.mcp` nor the Hue MCP server or evaluation-only tool.

## Point clients at Hue

Read each app URL and credential through a helper that detects evaluation and otherwise returns production values. `hue eval --command` sets `HUE_EXECUTION_ID`; world cases also set `HUE_WORLD_TOKEN`. Connect optional apps only when `appInWorld(variable)` is true. Required app or MCP connections **fail closed** without a world token or mirror URL, before requests and without reading the real credential. With neither variable, production values are unchanged.

Functions default to the process environment; tests and in-process adapters can pass a mapping or world's `env`. Copy only needed functions, commit them with call sites and an optional entry point or test, and test without Hue credentials. Never commit variable-name diagnostics.

```ts title="hue-eval.ts"
// Commit once. No Hue SDK is needed. Node 24 runs this file as is; Node 22 needs
// --experimental-strip-types or a build step.
import { mkdtempSync, readFileSync, rmSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";

export type Env = Record<string, string | undefined>;

/**
 * Detect an evaluation with or without a world. A world passed to an in-process adapter
 * carries HUE_WORLD_TOKEN; the command always receives HUE_EXECUTION_ID.
 */
export function inHueEval(env: Env = process.env): boolean {
  return Boolean(env.HUE_EXECUTION_ID || env.HUE_WORLD_TOKEN);
}

/** Whether to connect an app at all: always in production, in an evaluation only when the world mirrors it. */
export function appInWorld(variable: string, env: Env = process.env): boolean {
  return !inHueEval(env) || Boolean(env.HUE_WORLD_TOKEN && env[variable]);
}

/**
 * One app's URL and bearer: the Hue mirror during an evaluation, production otherwise.
 * `production` is a function so the real credential is never read during an evaluation.
 */
export function appEndpoint(
  variable: string,
  production: () => { url: string; token: string },
  env: Env = process.env,
): { url: string; token: string } {
  if (!inHueEval(env)) return production();
  if (!env.HUE_WORLD_TOKEN) {
    throw new Error("Hue eval: this case has no world handoff (HUE_WORLD_TOKEN is not set); refusing to connect the app");
  }
  const url = env[variable];
  if (!url) {
    const present = Object.keys(env).filter((key) => /^HUE_SIM_.*_URL$/.test(key)).sort();
    throw new Error(`Hue eval: ${variable} is not set, so this world has no mirror for the app; refusing to call the real one. Present: ${present.join(", ") || "none"}`);
  }
  return { url, token: env.HUE_WORLD_TOKEN! };
}

/**
 * An `mcpServers` file for a framework that loads one. Production: your file, untouched.
 * Evaluation: a private copy that keeps your server names, so tool names stay what production
 * has, and replaces each HTTP server's connection settings with its mirror's. `mirrors` maps
 * every server name to its `HUE_SIM_<SURFACE>_URL` variable; an unmapped server, a stdio server
 * (`command`) and a client-specific URL field (`serverUrl`, `httpUrl`) all fail closed.
 * Call `dispose()` when the agent exits: it removes the copy and the world token in it.
 */
export function mcpServersFile(
  production: string,
  mirrors: Record<string, string>,
  env: Env = process.env,
): { path: string; dispose(): void } {
  if (!inHueEval(env)) return { path: production, dispose() {} };
  if (!env.HUE_WORLD_TOKEN) {
    throw new Error("Hue eval: this case has no world handoff (HUE_WORLD_TOKEN is not set); refusing to load MCP servers");
  }
  const config = JSON.parse(readFileSync(production, "utf8")) as {
    mcpServers: Record<string, Record<string, unknown>>;
  };
  const known = new Set(["type", "url", "headers"]);
  for (const [name, server] of Object.entries(config.mcpServers)) {
    if ("command" in server) throw new Error(`Hue eval: MCP server ${name} is a stdio server; route its own app client through the helper`);
    const unknown = Object.keys(server).filter((key) => !known.has(key));
    if (unknown.length) throw new Error(`Hue eval: MCP server ${name} uses ${unknown.join(", ")}; rewrite that field for your client`);
    const variable = mirrors[name];
    if (!variable) throw new Error(`Hue eval: MCP server ${name} has no mirror variable; refusing to reach the real one`);
    const mirror = appEndpoint(variable, () => ({ url: "", token: "" }), env);
    config.mcpServers[name] = { type: "http", url: mirror.url, headers: { Authorization: `Bearer ${mirror.token}` } };
  }
  const directory = mkdtempSync(join(tmpdir(), "hue-mcp-"));
  const path = join(directory, "mcp.json");
  writeFileSync(path, JSON.stringify(config), { mode: 0o600 });
  return { path, dispose: () => rmSync(directory, { recursive: true, force: true }) };
}
```

```python title="hue_eval.py"
# Commit once. No Hue SDK is needed.
import json
import os
import re
import shutil
import tempfile
from collections.abc import Callable, Iterator, Mapping
from contextlib import contextmanager


def in_hue_eval(env: Mapping[str, str] = os.environ) -> bool:
    """Detect an evaluation with or without a world."""
    return bool(env.get("HUE_EXECUTION_ID") or env.get("HUE_WORLD_TOKEN"))


def app_in_world(variable: str, env: Mapping[str, str] = os.environ) -> bool:
    """Connect an app always in production, and in an evaluation only when mirrored."""
    return not in_hue_eval(env) or bool(env.get("HUE_WORLD_TOKEN") and env.get(variable))


def app_endpoint(
    variable: str,
    production: Callable[[], tuple[str, str]],
    env: Mapping[str, str] = os.environ,
) -> tuple[str, str]:
    """One app's (url, bearer): the Hue mirror in an evaluation, production otherwise.

    `production` is a function; the real credential is not read in an evaluation.
    """
    if not in_hue_eval(env):
        return production()
    if not env.get("HUE_WORLD_TOKEN"):
        raise RuntimeError(
            "Hue eval: this case has no world handoff (HUE_WORLD_TOKEN is not set); "
            "refusing to connect the app"
        )
    url = env.get(variable)
    if not url:
        present = sorted(k for k in env if re.fullmatch(r"HUE_SIM_.*_URL", k))
        names = ", ".join(present) or "none"
        raise RuntimeError(
            f"Hue eval: {variable} is not set, so this world has no mirror for the app;"
            f" refusing to call the real one. Present: {names}"
        )
    return url, env["HUE_WORLD_TOKEN"]


@contextmanager
def mcp_servers_file(
    production: str,
    mirrors: dict[str, str],
    env: Mapping[str, str] = os.environ,
) -> Iterator[str]:
    """An `mcpServers` file for a framework that loads one, as a context manager.

    Production: yields your file, untouched. Evaluation: yields a private copy that
    keeps your server names, so tool names stay what production has, and replaces each
    HTTP server's connection settings with its mirror's, then removes the copy and the
    world token in it when the block ends. An unmapped server, a stdio server
    (`command`) and a client-specific URL field (`serverUrl`, `httpUrl`) fail closed.
    """
    if not in_hue_eval(env):
        yield production
        return
    if not env.get("HUE_WORLD_TOKEN"):
        raise RuntimeError(
            "Hue eval: this case has no world handoff (HUE_WORLD_TOKEN is not set); "
            "refusing to load MCP servers"
        )
    with open(production, encoding="utf-8") as file:
        config = json.load(file)
    known = {"type", "url", "headers"}
    for name, server in config["mcpServers"].items():
        if "command" in server:
            raise RuntimeError(
                f"Hue eval: MCP server {name} is a stdio server; "
                "route its own app client through the helper"
            )
        unknown = sorted(set(server) - known)
        if unknown:
            raise RuntimeError(
                f"Hue eval: MCP server {name} uses {', '.join(unknown)}; "
                "rewrite that field for your client"
            )
        variable = mirrors.get(name)
        if not variable:
            raise RuntimeError(
                f"Hue eval: MCP server {name} has no mirror variable; "
                "refusing to reach the real one"
            )
        url, token = app_endpoint(variable, lambda: ("", ""), env)
        config["mcpServers"][name] = {
            "type": "http",
            "url": url,
            "headers": {"Authorization": f"Bearer {token}"},
        }
    directory = tempfile.mkdtemp(prefix="hue-mcp-")
    try:
        path = os.path.join(directory, "mcp.json")
        descriptor = os.open(path, os.O_WRONLY | os.O_CREAT, 0o600)
        with open(descriptor, "w", encoding="utf-8") as file:
            json.dump(config, file)
        yield path
    finally:
        shutil.rmtree(directory, ignore_errors=True)
```

### Environment variables

Each mirror's variable is `HUE_SIM_<SURFACE>_URL`, where the surface is the app's provider surface id in upper case with every other character replaced by `_`. Its value is the mirror base that replaces the real base:

| App | Surface id | Variable | Mirror base | Replaces |
| --- | --- | --- | --- | --- |
| Gmail MCP | `google.gmail/mcp` | `HUE_SIM_GOOGLE_GMAIL_MCP_URL` | `https://app.hue.run/api/sim/gmailmcp.googleapis.com/mcp/v1` | `https://gmailmcp.googleapis.com/mcp/v1` |
| Gmail REST | `google.gmail/rest` | `HUE_SIM_GOOGLE_GMAIL_REST_URL` | `https://app.hue.run/api/sim/gmail.googleapis.com/gmail/v1` | `https://gmail.googleapis.com/gmail/v1` |
| Slack Web API | `slack/web-api` | `HUE_SIM_SLACK_WEB_API_URL` | `https://app.hue.run/api/sim/slack.com/api/` (keep the trailing slash) | `https://slack.com/api/` |
| Slack MCP | `slack/mcp` | `HUE_SIM_SLACK_MCP_URL` | `https://app.hue.run/api/sim/mcp.slack.com/mcp` | `https://mcp.slack.com/mcp` |

Experimental mirrors follow the same rule, one variable per surface: Linear has `HUE_SIM_LINEAR_GRAPHQL_URL` and `HUE_SIM_LINEAR_MCP_URL`, and HubSpot has one per service, such as `HUE_SIM_HUBSPOT_CRM_OBJECTS_URL`. A replay-only surface has no URL. For an SDK whose base option is an origin, such as HubSpot's `basePath`, pass the value up to and including the real host (`https://app.hue.run/api/sim/api.hubapi.com`).

`HUE_MCP_CONFIG` names an owner-only `mcpServers` file for every MCP mirror of the world, keyed by Hue's provider instance (such as `gmail-primary`) rather than by your server names, with `HUE_WORLD_TOKEN` as the bearer; it fits as-is only when those keys are the names your production configuration uses, since a framework derives tool names from them. `HUE_MCP_URL`, `HUE_MCP_TOKEN` and `HUE_MCP_EXPIRES_AT` carry the first MCP mirror under the names older adapters read. `hue eval` prints `world created` per case, not the variable names. To learn a case's exact names, have the agent log the `HUE_SIM_` variable names, never their values, to stderr during one local trial run, and don't commit the line; the helper's fail-closed error also lists the names present.

### Multiple apps

A world includes only pinned apps; answer-only cases have no mirrors. Resolve required apps at startup, outside tool error handling, so refusal stops the run before requests. Connect optional apps only when `appInWorld(variable)` is true and log skipped names to stderr. In production it is always true; included apps expose production's tools.

## Framework setup

Point each app client at the helper's result. Find each call site—MCP configuration or code, hosted connector, REST base URL, raw HTTP, meta-tool or model-written code—and replace the Gmail examples' variables and credential readers.

### MCP configuration files

For an `mcpServers` file, preserve production server names and let the helper write an evaluation copy with mirror URLs and credentials. Missing mirrors or client-specific URL fields fail closed; remove the copy on exit. Claude Code reads it with `--mcp-config`:

```sh title="claude-code.sh"
#!/usr/bin/env bash
# The agent's start command. Reads the case from stdin, answers on stdout.
set -euo pipefail
# Fail closed: when the helper throws, this assignment fails and the script stops before Claude starts.
# Node 22.6 or later with the flag; Node 24 strips types without it.
CONFIG="$(node --experimental-strip-types -e 'import("./hue-eval.ts").then((m) => console.log(m.mcpServersFile("./mcp.production.json", { gmail: "HUE_SIM_GOOGLE_GMAIL_MCP_URL" }).path))')"
# During an evaluation the copy holds the world token: remove it when the agent exits.
if [ -n "${HUE_WORLD_TOKEN:-}" ]; then trap 'rm -rf "$(dirname "$CONFIG")"' EXIT; fi
# The prompt is the task, preceded by the earlier turns when the case includes them.
PROMPT="$(jq -r '.inputs | if type == "object" and has("task") then ((.priorContext // []) | map(tostring) | join("\n\n")) + "\n\n" + (.task | tostring) else tostring end')"
claude -p "$PROMPT" --mcp-config "$CONFIG" --strict-mcp-config
```

`HUE_MCP_CONFIG` has the same shape; pass it directly only when its keys match your server names:

```json title="mcp.json"
{
  "mcpServers": {
    "gmail-primary": {
      "type": "http",
      "url": "https://app.hue.run/api/sim/gmailmcp.googleapis.com/mcp/v1",
      "headers": { "Authorization": "Bearer <world token>" }
    }
  }
}
```

### Stdio MCP servers

A `command` and `args` entry starts a local server, so the helper refuses to rewrite it to avoid changing tools. Keep it and use `appEndpoint` to resolve both the REST mirror URL and world token. Pass them through the server's own base-URL and credential settings; without a base-URL override it cannot run in a world.

### Meta-tools and code execution

Some agents reach apps through a tool proxy such as `mcp_effect({ serverId, tool, argumentsJson })`, `mcp_read`, or model-written code in a sandbox. The model's tool list stays unchanged; only server-id resolution changes to the mirror URL and credential.

- Resolve each app on the host before the run.
- Give a sandbox only the resolved client, generated module or host proxy—not credentials, open `fetch` or `process.env`.
  - Key cached clients by `HUE_WORLD_ID`; remote sandboxes need an injected mirror URL and token, mirror-only egress and blocked real hosts.
- Provider-hosted interpreters cannot reach the world directly; host-routed tools can. Test that model-written code fails closed against the real host.

A tool-proxy agent resolves every server once at startup and answers each `mcp_effect` call from that table:

```ts title="meta-tool.ts"
// The wrapper behind mcp_effect({ serverId, tool, argumentsJson }). Servers are resolved once,
// at startup; a missing mirror throws here, not inside a tool call the model reads.
import { appEndpoint, appInWorld } from "./hue-eval";

const SERVERS = {
  gmail: { variable: "HUE_SIM_GOOGLE_GMAIL_MCP_URL", production: () => productionServer("gmail") },
  linear: { variable: "HUE_SIM_LINEAR_MCP_URL", production: () => productionServer("linear") },
} as const; // productionServer reads your existing server configuration and credential store.

const endpoints = new Map<string, { url: string; token: string }>();
for (const [serverId, server] of Object.entries(SERVERS)) {
  if (!appInWorld(server.variable)) {
    console.error(`skipping ${serverId}: this world has no mirror for it`);
    continue;
  }
  endpoints.set(serverId, appEndpoint(server.variable, server.production));
}

export async function mcpEffect(input: { serverId: string; tool: string; argumentsJson: string }) {
  const endpoint = endpoints.get(input.serverId);
  if (!endpoint) throw new Error(`mcp_effect: server ${input.serverId} is not available in this run`);
  const client = await connectMcp(endpoint.url, endpoint.token); // your existing MCP client factory
  return client.callTool({ name: input.tool, arguments: JSON.parse(input.argumentsJson) });
}
```

A code-execution agent hands the sandbox that same resolved function and nothing else:

```ts title="code-mode.ts"
// Code mode: the model writes JavaScript that calls tools.mcp_effect(...). The sandbox gets the
// bound function, no network, no environment and no credentials, so model-written code can
// reach an app only through the resolved endpoint.
import { mcpEffect } from "./meta-tool";

export async function runModelCode(code: string) {
  const sandbox = createSandbox({
    globals: { tools: { mcp_effect: mcpEffect } },
    allowNetwork: false,
    allowEnv: false,
  }); // your sandbox runtime; a remote sandbox instead receives the resolved URL and token and an egress allowlist of the mirror origin
  return sandbox.run(code);
}
```

### Deployed agents

`hue eval` runs the agent where started. For a deployed agent, run locally with `--command` or forward case variables through a thin entry point to a non-production deployment for that request only. Never put mirror URLs, world tokens or connection keys in production configuration.

### Relative dates

A world's clock is the source trace start, not wall time; `hue eval` passes RFC 3339 `HUE_WORLD_NOW` for relative dates. Without the SDK, use `inHueEval() && process.env.HUE_WORLD_NOW ? new Date(process.env.HUE_WORLD_NOW) : new Date()` in TypeScript; Python parses with `datetime.fromisoformat(value.replace("Z", "+00:00"))` and otherwise uses `datetime.now(timezone.utc)` (Python 3.10 needs `+00:00`). SDK helpers `worldNow() ?? new Date()` and `world_now() or datetime.now(timezone.utc)` fall back when unset; adapters use `worldNow(context.world)` or `context.world.env`. Ignore if the agent never reads a clock.

## Run it

`hue eval` starts your command once per case. World cases get world variables; answer-only cases get execution and case variables only. Read `{"inputs","config"}` from stdin, run once, print the answer to stdout and exit. Answer-only cases retain generated checks and required judges; see [Trace to case](/evaluations/case-from-trace#answer-only-cases).

Use an absolute entry path for one-shot runs; private case directories cannot resolve repository-relative paths. Workers keep the CLI's starting directory. Examples expand `$PWD` before launch.

`inputs` is the trace or reviewer input; earlier turns use `{"task": ..., "priorContext": [...]}`. `get_case` with `include_content` shows it. Map it to your entry argument and pass `priorContext`. JSON stdout is parsed, other output is text (up to 4 MiB); nonzero exit or timeout (default 600 seconds) errors the case.

When your production entry point is a server or takes another input shape, add a thin entry point and commit it with the helper:

```js title="agent.js"
import { text } from "node:stream/consumers";
import { runMyAgent } from "./agent-core.js"; // your unchanged production agent

const { inputs } = JSON.parse(await text(process.stdin));
process.stdout.write(JSON.stringify(await runMyAgent(inputs)));
```

```python title="agent_entry.py"
import asyncio

from agent_core import run_my_agent  # your unchanged production agent

payload = json.load(sys.stdin)
answer = asyncio.run(run_my_agent(payload["inputs"]))

```

Run with a **Read and write** key that `hue login` stored in an ignored env file:

```sh
npx -y @hue-run/sdk@0.16.0 eval --case "<name>" --command "node \"$PWD/agent.js\""
```

`hue eval` needs Node.js 22 or 24, even for Python. npx caches the CLI without changing the repository. Always pin the SDK: an unpinned `npx @hue-run/sdk` can select an older local copy. See [Run an eval with your agent](/evaluations/run-your-agent) for `--check`, one run per command and resuming.

Every case receives execution and case variables. Only a case with a world receives the world and mirror variables:

| Variable | Meaning |
| --- | --- |
| `HUE_WORLD_ID`, `HUE_WORLD_TOKEN` | The world and the bearer the mirrors accept for it. |
| `HUE_WORLD_NOW` | The world's clock at creation, RFC 3339, when Hue sends it. |
| `HUE_SIM_<SURFACE>_URL` | One per mirror; see [environment variables](#environment-variables). |
| `HUE_MCP_CONFIG` | An owner-only `mcpServers` file for the world's MCP mirrors, removed after the case. |
| `TRACEPARENT`, `BAGGAGE` | A world case's trace context and `hue-world=<id>`. |
| `HUE_EXECUTION_ID`, `HUE_CASE_ID`, `HUE_CASE_KEY` | The execution and the case, including answer-only cases. |
| `HUE_ENVIRONMENT_RUN_ID` | The world, only for a case with a world. |
| `HUE_CASE_DIR`, `HUE_CASE_INPUTS`, `HUE_CASE_OUTPUT_DIR` | A private case directory: the inputs file, the case's input files under `files/<role>/`, and `output/`, whose files are uploaded after the case. |
| `HUE_MCP_URL`, `HUE_MCP_TOKEN`, `HUE_MCP_EXPIRES_AT` | Legacy names for the first MCP mirror. |

`hue eval` removes `HUE_API_KEY` and Hue-key-shaped values; other shell and `--env-file` variables pass through. Do not reload a file containing `HUE_API_KEY`. Store checkpoints under `.hue/eval/<agent-key>` and ignore `.hue/`; case files are under `HUE_CASE_DIR/files/<role>/`. Logs go to stderr; stdout is stored. A case passes only after each required evaluator decides; undecided results leave it inconclusive. Exit codes: 0 pass, 1 failure, error, inconclusive or incomplete, 2 usage, 130 interrupt. Compare with `--baseline <previous run id>`.

For the **Run** button and `launch_local_run` to use one agent for answer-only or world-backed cases, start a command worker. It claims queued runs and uses the same stdin handoff:

```sh
npx -y @hue-run/sdk@0.16.0 eval --worker --command "node \"$PWD/agent.js\"" --revision "<new-agent-revision>"
```

Command workers register `direct:v1` and `environment:v1`. Adapter-file workers register world support by default; add `--capability direct:v1` only after the adapter supports direct cases. Change `--revision` when capabilities change; otherwise keep it stable.

TypeScript adapters lack `HUE_WORLD_TOKEN` and `HUE_EXECUTION_ID`: pass `context.world.env` or spawn with [`agentEnvironment(context.world)`](/reference/typescript#world-handoff). Reject missing worlds; direct adapters pass `{ HUE_EXECUTION_ID: context.executionId }` and connect no apps. Adapter-file workers register world support by default; add `--capability direct:v1` only after the adapter supports direct cases. Never mutate `process.env`; concurrency can leak worlds. Python uses [`hue_sdk.environment`](/reference/python#world-handoff) helpers. Unsupported gateway worlds have no handoff or token; required connections refuse them. See [world handoff](/evaluations/simulations#world-handoff).

## Verify the setup

- **Production:** With world variables unset, helpers return production values; tests pass.
- **Answer-only and fail-closed:** Execution-only cases skip optional apps. Missing required worlds or mirrors fail before requests or credential reads; sandboxes cannot reach real hosts.
- **Tools and adapters:** Expose production tools without Hue-native tools; pass world env or direct execution ID, reject missing worlds and connect no apps for direct mode.
- **Diff and run:** Commit only helper, call sites and an optional entry point or test; commit no Hue variable values. Keep the run URL, verdicts, divergence for failures and credential-free stdout.

## Production safety

- World variables exist only in `hue eval`; it removes `HUE_MCP_CONFIG` after each case. Production lacks world variables and keeps real credentials.
- Never copy world URL or token values into production config. Tokens expire with one simulated world and cannot reach the real app.
- `hue eval` strips `HUE_API_KEY` and Hue-key-shaped values; self-tracing exports only the case span. Safe constructors disable without a key; strict constructors throw. Use `--allow-hue-credentials` only when permitting project-key access; inspect via `get_run_execution`/`get_case_divergence`.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Exit 1 with an unsaved eval-set version | Rerun with `--save-version`. |
| The helper throws "no world handoff" | Required app or MCP connections need a world token; answer-only cases skip optional apps. |
| The helper throws "`HUE_SIM_…_URL` is not set" | The world does not include that app; connect it only where `appInWorld` is true. |
| 501 `surface_unavailable` | The case needs a mirror this deployment does not serve. |
| `no_calls` on a case that needed app calls | Check where the agent's requests went before changing a call site; see below. |
| Telemetry not accepted in time | Rerun with `--trace-not-accepted pending`. |

## Hard-coded URLs

Hard-coded URLs bypass the world: Hue records nothing and real apps may receive writes. Route URLs and credentials through the helper. `no_calls` is advisory; inspect logs before changing code to distinguish real requests from an early stop or invented answer.
