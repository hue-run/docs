In a Hue evaluation your agent runs in your process. A case with app calls gives it a fresh simulated world; an answer-only case gives it the reviewed task and context without a world. Hue never executes the agent, intercepts its network traffic or adds tools. For a case with a world, a helper you commit once points your agent's own app clients at its mirrors.

This guide is for any agent that talks to apps such as Gmail, Slack or Notion over MCP or REST, in any language, including agents that reach apps through their own meta-tools or through code the model writes. It describes the current `@hue-run/sdk` release, which the commands below pin; a `--command` agent in any language needs no Hue package. For the TypeScript callback path and what a world is, see [simulations](/evaluations/simulations); for the command reference, see [`hue eval`](/sdks/cli#run-an-evaluation).

<Note>
Preview: Hue's mirrors answer at `https://app.hue.run/api/sim/…`, but the simulation gateway is not yet a released Hue Cloud capability. Gmail (MCP, REST) and Slack (Web API, MCP) are its established mirrors; other apps' mirrors are experimental and certify no fidelity.
</Note>

## How a mirror works

Each app the agent uses has a mirror at a stable Hue URL:

```text
https://app.hue.run/api/sim/<real host>/<real path>
```

A Gmail REST mirror is `https://app.hue.run/api/sim/gmail.googleapis.com/gmail/v1`, and a Gmail MCP mirror is `https://app.hue.run/api/sim/gmailmcp.googleapis.com/mcp/v1`. The agent calls the mirror exactly as it calls the real app, with a per-run **world token** in place of the real credential. Hue answers from that run's private world in the real app's format, records every call in the world's ledger, then seals the world when the case ends and scores it.

The mirrors serve the real app's captured catalog, or the tool list the trace the case was built from recorded, so the agent sees what production sees. Hue adds no tool of its own. An eval-ready agent therefore never receives Hue-native tools: not the deprecated `context.tools` or `context.mcp` of a world without a handoff, not the Hue MCP server, not a tool added for the evaluation.

## The one-time change

Read each app's URL and credential through a helper that detects an evaluation and falls back to the production values otherwise. `hue eval --command` always sets `HUE_EXECUTION_ID`; a case with a world also sets `HUE_WORLD_TOKEN`. During an evaluation, connect optional apps only where `appInWorld(variable)` is true. An answer-only case skips those apps and can answer without tools. A required app connection or MCP configuration **fails closed** without a world token or its mirror URL, before any request and without reading the real credential. With neither evaluation variable set, the helper returns the production URL and credential unchanged.

Every function takes the environment as an argument that defaults to the process environment, so a test can pass a mapping and an in-process adapter can pass a world's `env`. Copy the helper into your package, import it the way the package imports its other modules, and trim the functions no call site uses. Commit it with its call sites, an optional thin entry point and an optional test of the [checks below](#verify-before-you-finish), run without Hue credentials. A temporary stderr line that logs variable names is not committed. Nothing else changes: not the prompts, the model, the tools or the dependencies.

```ts title="hue-eval.ts"
// Commit once. No Hue SDK is needed. Node 24 runs this file as is; Node 22 needs
// --experimental-strip-types or a build step.
import { mkdtempSync, readFileSync, rmSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";

export type Env = Record<string, string | undefined>;

/**
 * Detect an evaluation with or without a world. A world passed to an in-process adapter
 * carries HUE_WORLD_TOKEN; the command always receives HUE_EXECUTION_ID.
 */
export function inHueEval(env: Env = process.env): boolean {
  return Boolean(env.HUE_EXECUTION_ID || env.HUE_WORLD_TOKEN);
}

/** Whether to connect an app at all: always in production, in an evaluation only when the world mirrors it. */
export function appInWorld(variable: string, env: Env = process.env): boolean {
  return !inHueEval(env) || Boolean(env.HUE_WORLD_TOKEN && env[variable]);
}

/**
 * One app's URL and bearer: the Hue mirror during an evaluation, production otherwise.
 * `production` is a function so the real credential is never read during an evaluation.
 */
export function appEndpoint(
  variable: string,
  production: () => { url: string; token: string },
  env: Env = process.env,
): { url: string; token: string } {
  if (!inHueEval(env)) return production();
  if (!env.HUE_WORLD_TOKEN) {
    throw new Error("Hue eval: this case has no world handoff (HUE_WORLD_TOKEN is not set); refusing to connect the app");
  }
  const url = env[variable];
  if (!url) {
    const present = Object.keys(env).filter((key) => /^HUE_SIM_.*_URL$/.test(key)).sort();
    throw new Error(`Hue eval: ${variable} is not set, so this world has no mirror for the app; refusing to call the real one. Present: ${present.join(", ") || "none"}`);
  }
  return { url, token: env.HUE_WORLD_TOKEN! };
}

/**
 * An `mcpServers` file for a framework that loads one. Production: your file, untouched.
 * Evaluation: a private copy that keeps your server names, so tool names stay what production
 * has, and replaces each HTTP server's connection settings with its mirror's. `mirrors` maps
 * every server name to its `HUE_SIM_<SURFACE>_URL` variable; an unmapped server, a stdio server
 * (`command`) and a client-specific URL field (`serverUrl`, `httpUrl`) all fail closed.
 * Call `dispose()` when the agent exits: it removes the copy and the world token in it.
 */
export function mcpServersFile(
  production: string,
  mirrors: Record<string, string>,
  env: Env = process.env,
): { path: string; dispose(): void } {
  if (!inHueEval(env)) return { path: production, dispose() {} };
  if (!env.HUE_WORLD_TOKEN) {
    throw new Error("Hue eval: this case has no world handoff (HUE_WORLD_TOKEN is not set); refusing to load MCP servers");
  }
  const config = JSON.parse(readFileSync(production, "utf8")) as {
    mcpServers: Record<string, Record<string, unknown>>;
  };
  const known = new Set(["type", "url", "headers"]);
  for (const [name, server] of Object.entries(config.mcpServers)) {
    if ("command" in server) throw new Error(`Hue eval: MCP server ${name} is a stdio server; route its own app client through the helper`);
    const unknown = Object.keys(server).filter((key) => !known.has(key));
    if (unknown.length) throw new Error(`Hue eval: MCP server ${name} uses ${unknown.join(", ")}; rewrite that field for your client`);
    const variable = mirrors[name];
    if (!variable) throw new Error(`Hue eval: MCP server ${name} has no mirror variable; refusing to reach the real one`);
    const mirror = appEndpoint(variable, () => ({ url: "", token: "" }), env);
    config.mcpServers[name] = { type: "http", url: mirror.url, headers: { Authorization: `Bearer ${mirror.token}` } };
  }
  const directory = mkdtempSync(join(tmpdir(), "hue-mcp-"));
  const path = join(directory, "mcp.json");
  writeFileSync(path, JSON.stringify(config), { mode: 0o600 });
  return { path, dispose: () => rmSync(directory, { recursive: true, force: true }) };
}
```

```python title="hue_eval.py"
# Commit once. No Hue SDK is needed.
import json
import os
import re
import shutil
import tempfile
from collections.abc import Callable, Iterator, Mapping
from contextlib import contextmanager


def in_hue_eval(env: Mapping[str, str] = os.environ) -> bool:
    """Detect an evaluation with or without a world."""
    return bool(env.get("HUE_EXECUTION_ID") or env.get("HUE_WORLD_TOKEN"))


def app_in_world(variable: str, env: Mapping[str, str] = os.environ) -> bool:
    """Connect an app always in production, and in an evaluation only when mirrored."""
    return not in_hue_eval(env) or bool(env.get("HUE_WORLD_TOKEN") and env.get(variable))


def app_endpoint(
    variable: str,
    production: Callable[[], tuple[str, str]],
    env: Mapping[str, str] = os.environ,
) -> tuple[str, str]:
    """One app's (url, bearer): the Hue mirror in an evaluation, production otherwise.

    `production` is a function; the real credential is not read in an evaluation.
    """
    if not in_hue_eval(env):
        return production()
    if not env.get("HUE_WORLD_TOKEN"):
        raise RuntimeError(
            "Hue eval: this case has no world handoff (HUE_WORLD_TOKEN is not set); "
            "refusing to connect the app"
        )
    url = env.get(variable)
    if not url:
        present = sorted(k for k in env if re.fullmatch(r"HUE_SIM_.*_URL", k))
        names = ", ".join(present) or "none"
        raise RuntimeError(
            f"Hue eval: {variable} is not set, so this world has no mirror for the app;"
            f" refusing to call the real one. Present: {names}"
        )
    return url, env["HUE_WORLD_TOKEN"]


@contextmanager
def mcp_servers_file(
    production: str,
    mirrors: dict[str, str],
    env: Mapping[str, str] = os.environ,
) -> Iterator[str]:
    """An `mcpServers` file for a framework that loads one, as a context manager.

    Production: yields your file, untouched. Evaluation: yields a private copy that
    keeps your server names, so tool names stay what production has, and replaces each
    HTTP server's connection settings with its mirror's, then removes the copy and the
    world token in it when the block ends. An unmapped server, a stdio server
    (`command`) and a client-specific URL field (`serverUrl`, `httpUrl`) fail closed.
    """
    if not in_hue_eval(env):
        yield production
        return
    if not env.get("HUE_WORLD_TOKEN"):
        raise RuntimeError(
            "Hue eval: this case has no world handoff (HUE_WORLD_TOKEN is not set); "
            "refusing to load MCP servers"
        )
    with open(production, encoding="utf-8") as file:
        config = json.load(file)
    known = {"type", "url", "headers"}
    for name, server in config["mcpServers"].items():
        if "command" in server:
            raise RuntimeError(
                f"Hue eval: MCP server {name} is a stdio server; "
                "route its own app client through the helper"
            )
        unknown = sorted(set(server) - known)
        if unknown:
            raise RuntimeError(
                f"Hue eval: MCP server {name} uses {', '.join(unknown)}; "
                "rewrite that field for your client"
            )
        variable = mirrors.get(name)
        if not variable:
            raise RuntimeError(
                f"Hue eval: MCP server {name} has no mirror variable; "
                "refusing to reach the real one"
            )
        url, token = app_endpoint(variable, lambda: ("", ""), env)
        config["mcpServers"][name] = {
            "type": "http",
            "url": url,
            "headers": {"Authorization": f"Bearer {token}"},
        }
    directory = tempfile.mkdtemp(prefix="hue-mcp-")
    try:
        path = os.path.join(directory, "mcp.json")
        descriptor = os.open(path, os.O_WRONLY | os.O_CREAT, 0o600)
        with open(descriptor, "w", encoding="utf-8") as file:
            json.dump(config, file)
        yield path
    finally:
        shutil.rmtree(directory, ignore_errors=True)
```

### Variable names

Each mirror's variable is `HUE_SIM_<SURFACE>_URL`, where the surface is the app's provider surface id in upper case with every other character replaced by `_`. Its value is the mirror base that replaces the real base:

| App | Surface id | Variable | Mirror base | Replaces |
| --- | --- | --- | --- | --- |
| Gmail MCP | `google.gmail/mcp` | `HUE_SIM_GOOGLE_GMAIL_MCP_URL` | `https://app.hue.run/api/sim/gmailmcp.googleapis.com/mcp/v1` | `https://gmailmcp.googleapis.com/mcp/v1` |
| Gmail REST | `google.gmail/rest` | `HUE_SIM_GOOGLE_GMAIL_REST_URL` | `https://app.hue.run/api/sim/gmail.googleapis.com/gmail/v1` | `https://gmail.googleapis.com/gmail/v1` |
| Slack Web API | `slack/web-api` | `HUE_SIM_SLACK_WEB_API_URL` | `https://app.hue.run/api/sim/slack.com/api/` (keep the trailing slash) | `https://slack.com/api/` |
| Slack MCP | `slack/mcp` | `HUE_SIM_SLACK_MCP_URL` | `https://app.hue.run/api/sim/mcp.slack.com/mcp` | `https://mcp.slack.com/mcp` |

Experimental mirrors follow the same rule, one variable per surface: Linear has `HUE_SIM_LINEAR_GRAPHQL_URL` and `HUE_SIM_LINEAR_MCP_URL`, and HubSpot has one per service, such as `HUE_SIM_HUBSPOT_CRM_OBJECTS_URL`. A replay-only surface has no URL. For an SDK whose base option is an origin, such as HubSpot's `basePath`, pass the value up to and including the real host (`https://app.hue.run/api/sim/api.hubapi.com`).

`HUE_MCP_CONFIG` names an owner-only `mcpServers` file for every MCP mirror of the world, keyed by Hue's provider instance (such as `gmail-primary`) rather than by your server names, with `HUE_WORLD_TOKEN` as the bearer; it fits as-is only when those keys are the names your production configuration uses, since a framework derives tool names from them. `HUE_MCP_URL`, `HUE_MCP_TOKEN` and `HUE_MCP_EXPIRES_AT` carry the first MCP mirror under the names older adapters read. `hue eval` prints `world created` per case, not the variable names. To learn a case's exact names, have the agent log the `HUE_SIM_` variable names, never their values, to stderr during one local trial run, and don't commit the line; the helper's fail-closed error also lists the names present.

### Agents that use several apps

A world includes only the apps its case pins, so a Gmail-only case has no Slack mirror. An answer-only case has no app mirrors. Resolve every required app at startup, before the first model or app request and outside tool error handling, so a refusal ends the process instead of becoming a tool error the model reads. Connect optional apps only where `appInWorld(variable)` is true, and log each skipped app's name to stderr. In production `appInWorld` is always true, so production connects everything as before. "Same tools" then means every app the world includes exposes the tools production has.

## Call sites

Point each app client at the helper's result. First find how the codebase reaches each app: an `mcpServers` file, an MCP client in code, a hosted connector, a REST SDK with a base URL option, raw HTTP calls, or the agent's own meta-tools and model-written code. Each is a call site. The snippets use a Gmail MCP mirror and a placeholder `readGoogleAccessToken()` for the production credential; replace the variable and the production values with your app's.

### An MCP configuration file

For a framework that loads an `mcpServers` file, keep your production file and its server names, and let the helper write the evaluation copy with each server's URL and credential replaced by its mirror's. Tool names stay what production has, a server without a mirror or with a client-specific URL field (such as `serverUrl` or `httpUrl`) fails closed, and the copy is removed when the agent exits (`dispose()` in TypeScript, the end of the `with` block in Python). Claude Code reads the result with `--mcp-config`:

```sh title="claude-code.sh"
#!/usr/bin/env bash
# The agent's start command. Reads the case from stdin, answers on stdout.
set -euo pipefail
# Fail closed: when the helper throws, this assignment fails and the script stops before Claude starts.
# Node 22.6 or later with the flag; Node 24 strips types without it.
CONFIG="$(node --experimental-strip-types -e 'import("./hue-eval.ts").then((m) => console.log(m.mcpServersFile("./mcp.production.json", { gmail: "HUE_SIM_GOOGLE_GMAIL_MCP_URL" }).path))')"
# During an evaluation the copy holds the world token: remove it when the agent exits.
if [ -n "${HUE_WORLD_TOKEN:-}" ]; then trap 'rm -rf "$(dirname "$CONFIG")"' EXIT; fi
# The prompt is the task, preceded by the earlier turns when the case includes them.
PROMPT="$(jq -r '.inputs | if type == "object" and has("task") then ((.priorContext // []) | map(tostring) | join("\n\n")) + "\n\n" + (.task | tostring) else tostring end')"
claude -p "$PROMPT" --mcp-config "$CONFIG" --strict-mcp-config
```

Hue's own file at `HUE_MCP_CONFIG` has the same common shape, one Streamable HTTP server per provider instance; pass it directly only when its keys are your server names:

```json title="mcp.json"
{
  "mcpServers": {
    "gmail-primary": {
      "type": "http",
      "url": "https://app.hue.run/api/sim/gmailmcp.googleapis.com/mcp/v1",
      "headers": { "Authorization": "Bearer <world token>" }
    }
  }
}
```

### Stdio MCP servers

A production entry with `command` and `args` starts a local server process that itself calls the app. The helper refuses to rewrite it, because swapping in the hosted MCP mirror would change the tool list. Keep the stdio server process and give it the REST mirror and world token through its own environment variables, if it supports a base-URL override; route that override through `appEndpoint`. A server with neither option can't run in a world.

### Direct REST clients

A REST mirror takes the same paths as the real API under its base URL. Give an SDK the mirror as its base URL option, or build requests on it:

```ts title="direct-rest.ts"
import { appEndpoint } from "./hue-eval";

const gmail = appEndpoint("HUE_SIM_GOOGLE_GMAIL_REST_URL", () => ({
  url: "https://gmail.googleapis.com/gmail/v1",
  token: readGoogleAccessToken(),
}));
const response = await fetch(`${gmail.url}/users/me/messages?q=is:unread`, {
  headers: { Authorization: `Bearer ${gmail.token}` },
});
```

Google's Python client appends the service path itself, so give it the mirror base without its trailing `gmail/v1`. The Node `googleapis` client drops a path prefix from `rootUrl` and needs a mirror alias host, which production does not serve yet; use raw `fetch` or the MCP mirror there.

```python title="gmail_rest.py"
from google.oauth2.credentials import Credentials
from googleapiclient.discovery import build
from hue_eval import app_endpoint

url, token = app_endpoint(
    "HUE_SIM_GOOGLE_GMAIL_REST_URL",
    lambda: ("https://gmail.googleapis.com/gmail/v1", read_google_access_token()),
)
gmail = build(
    "gmail",
    "v1",
    credentials=Credentials(token=token),
    client_options={"api_endpoint": url.removesuffix("gmail/v1")},
)
```

### Meta-tools and code execution

Some agents reach apps through their own tool proxy, such as `mcp_effect({ serverId, tool, argumentsJson })` or `mcp_read`, through a tool-search proxy, or through code the model writes (code mode, or an E2B, Modal or Vercel sandbox) that calls those tools. The model's tool list does not change; the one place that changes is where the wrapper resolves a server id to the server's URL and credential.

- Resolve each app through the helper on the host, before the run, as in [agents that use several apps](#agents-that-use-several-apps).
- Give the sandbox only the resolved client, a generated module or a host-side proxy. Never give it real app credentials, an open `fetch` or `process.env`.
- Key any cached client by `HUE_WORLD_ID`, so one case's connection is never reused by the next.
- A remote sandbox inherits none of the world's variables: inject the resolved URL and token, allow egress to the mirror origin, and block the real app's hosts during an evaluation.
- A provider-hosted code interpreter cannot reach the world. Tool calls it routes back through your host's tools can.
- Include a fail-closed check in which model-written code tries the real host.

A tool-proxy agent resolves every server once at startup and answers each `mcp_effect` call from that table:

```ts title="meta-tool.ts"
// The wrapper behind mcp_effect({ serverId, tool, argumentsJson }). Servers are resolved once,
// at startup; a missing mirror throws here, not inside a tool call the model reads.
import { appEndpoint, appInWorld } from "./hue-eval";

const SERVERS = {
  gmail: { variable: "HUE_SIM_GOOGLE_GMAIL_MCP_URL", production: () => productionServer("gmail") },
  linear: { variable: "HUE_SIM_LINEAR_MCP_URL", production: () => productionServer("linear") },
} as const; // productionServer reads your existing server configuration and credential store.

const endpoints = new Map<string, { url: string; token: string }>();
for (const [serverId, server] of Object.entries(SERVERS)) {
  if (!appInWorld(server.variable)) {
    console.error(`skipping ${serverId}: this world has no mirror for it`);
    continue;
  }
  endpoints.set(serverId, appEndpoint(server.variable, server.production));
}

export async function mcpEffect(input: { serverId: string; tool: string; argumentsJson: string }) {
  const endpoint = endpoints.get(input.serverId);
  if (!endpoint) throw new Error(`mcp_effect: server ${input.serverId} is not available in this run`);
  const client = await connectMcp(endpoint.url, endpoint.token); // your existing MCP client factory
  return client.callTool({ name: input.tool, arguments: JSON.parse(input.argumentsJson) });
}
```

A code-execution agent hands the sandbox that same resolved function and nothing else:

```ts title="code-mode.ts"
// Code mode: the model writes JavaScript that calls tools.mcp_effect(...). The sandbox gets the
// bound function, no network, no environment and no credentials, so model-written code can
// reach an app only through the resolved endpoint.
import { mcpEffect } from "./meta-tool";

export async function runModelCode(code: string) {
  const sandbox = createSandbox({
    globals: { tools: { mcp_effect: mcpEffect } },
    allowNetwork: false,
    allowEnv: false,
  }); // your sandbox runtime; a remote sandbox instead receives the resolved URL and token and an egress allowlist of the mirror origin
  return sandbox.run(code);
}
```

### Deployed agents

`hue eval` runs the agent where you start it. To evaluate a deployed agent, run its code locally with `--command`, or have a thin entry point forward the case's world variables to a separate non-production deployment that uses them for that request only. Never put a mirror URL, world token or connection key in a production deployment's configuration.

### Date-relative tasks

A world's clock is the recorded start of the trace it was built from, not the wall clock, so "today", "tomorrow" or `newer_than:7d` should be computed from the world's date. `hue eval` passes that date to the agent as `HUE_WORLD_NOW`, an RFC 3339 timestamp, when Hue sends it with the world. Replace the agent's own clock reads with a read that prefers the world's date: without any Hue package, `inHueEval() && process.env.HUE_WORLD_NOW ? new Date(process.env.HUE_WORLD_NOW) : new Date()` in TypeScript, or `datetime.fromisoformat(os.environ["HUE_WORLD_NOW"].replace("Z", "+00:00")) if in_hue_eval() and os.environ.get("HUE_WORLD_NOW") else datetime.now(timezone.utc)` in Python (Python 3.10 accepts neither `UTC` nor a trailing `Z`); the `inHueEval()` gate keeps a stray value from changing production. An agent that already depends on the SDK can use `worldNow() ?? new Date()` from `@hue-run/sdk/environment` (requires TypeScript 0.13.0) or `world_now() or datetime.now(timezone.utc)` from `hue_sdk.environment` (requires Python 0.7.0); both return `null` or `None` without `HUE_WORLD_NOW`, so the fallback to the wall clock stays explicit. An in-process adapter reads the supplied world, `worldNow(context.world) ?? new Date()`, or gives the copied helper `context.world.env`, because the process environment holds no world there. If production already puts today's date in the prompt, take it from the same function. If the model infers dates and the agent never reads the clock, change nothing.

## Run it

`hue eval` starts your agent's own command once per case. A case with a world sets its world variables; an answer-only case sets the execution and case variables without a world token or app mirrors. Nothing is edited per run. The command contract is small: read `{"inputs","config"}` as JSON from stdin, run your agent once, print the answer on stdout and exit. Answer-only cases keep their generated answer checks and required judge; see [trace to case](/evaluations/case-from-trace#answer-only-cases).

Use an absolute path to the command's entry point for a one-shot run. A one-shot direct case starts the command in a private case directory, so a path relative to your repository will not resolve there. A command worker keeps the directory where you started the CLI for both answer-only and world cases. The examples below expand `$PWD` in your shell before starting the CLI.

`inputs` is the input your agent's root span recorded in the source trace (a string, an object such as `{task}`, `{query}` or `{prompt}`, or a messages array), or what the reviewer authored. When earlier turns were included it is `{"task": <that input>, "priorContext": [<earlier inputs>]}`. `get_case` with `include_content` shows it. Map it to your production entry argument, and pass `priorContext` through as earlier turns. Stdout is parsed as JSON when it is valid JSON, otherwise stored as text, at most 4 MiB. A non-zero exit, or a timeout (default 600 seconds, `--timeout`), errors the case.

When your production entry point is a server or takes another input shape, add a thin entry point and commit it with the helper:

<Tabs>
<Tab title="Node.js">

```js title="agent.js"
import { text } from "node:stream/consumers";
import { runMyAgent } from "./agent-core.js"; // your unchanged production agent

const { inputs } = JSON.parse(await text(process.stdin));
process.stdout.write(JSON.stringify(await runMyAgent(inputs)));
```

</Tab>

```python title="agent_entry.py"
import asyncio
import json
import sys

from agent_core import run_my_agent  # your unchanged production agent

payload = json.load(sys.stdin)
answer = asyncio.run(run_my_agent(payload["inputs"]))
print(json.dumps(answer))  # logs go to stderr, never stdout
```

Run with a **Read and write** key that `hue login` stored in an ignored env file:

```sh
npx --yes --package @hue-run/sdk@0.13.2 --package "zod@^4.6.5" hue eval --case "<name>" --command "node \"$PWD/agent.js\"" --env-file .env.hue
```

`hue eval` needs Node.js 22 or 24, even for a Python agent. The two `--package` flags put the CLI and its `zod` peer in npx's cache, so the agent's repository gains no package.json or dependency. Always pin the version: in a project that already depends on `@hue-run/sdk`, an unpinned `--package @hue-run/sdk` runs that local, possibly older, copy. Installing zod in the project does not help when the SDK itself is not installed there: the CLI exits with `hue eval needs zod`, even for `--help`.

Every case receives execution and case variables. Only a case with a world receives the world and mirror variables:

| Variable | Meaning |
| --- | --- |
| `HUE_WORLD_ID`, `HUE_WORLD_TOKEN` | The world and the bearer the mirrors accept for it. |
| `HUE_WORLD_NOW` | The world's clock at creation, RFC 3339, when Hue sends it. |
| `HUE_SIM_<SURFACE>_URL` | One per mirror; see [variable names](#variable-names). |
| `HUE_MCP_CONFIG` | An owner-only `mcpServers` file for the world's MCP mirrors, removed after the case. |
| `TRACEPARENT`, `BAGGAGE` | A world case's trace context and `hue-world=<id>`. |
| `HUE_EXECUTION_ID`, `HUE_CASE_ID`, `HUE_CASE_KEY` | The execution and the case, including answer-only cases. |
| `HUE_ENVIRONMENT_RUN_ID` | The world, only for a case with a world. |
| `HUE_CASE_DIR`, `HUE_CASE_INPUTS`, `HUE_CASE_OUTPUT_DIR` | A private case directory: the inputs file, the case's input files under `files/<role>/`, and `output/`, whose files are uploaded after the case. |
| `HUE_MCP_URL`, `HUE_MCP_TOKEN`, `HUE_MCP_EXPIRES_AT` | Legacy names for the first MCP mirror. |

`HUE_API_KEY` and any other Hue-key-shaped value are removed from the command's environment. Other variables in your shell and in `--env-file` reach the command, so the model key can live in either; don't reload a file that contains `HUE_API_KEY` inside the command (for example `uv run --env-file .env`). `hue eval` writes checkpoints to `.hue/eval/<agent-key>`; add `.hue/` to `.gitignore`. World cases with input files put them under `HUE_CASE_DIR/files/<role>/`; a worker registers `--capability environment-files:v1` (and `input:pdf`). Keep logs on stderr: stdout is stored, with the credentials `hue eval` handed it redacted. For a one-shot run, exit code 0 means every case passed; 1 means a case failed, errored, is inconclusive or is incomplete; 2 is a usage error; 130 is an interrupt. Rerun with `--baseline <previous experimentId>` to compare.

To let the **Run** button in Hue and the `launch_local_run` MCP tool use the same agent for answer-only cases, world cases or an eval set containing both, start a command worker. It claims runs Hue queues and executes them on your machine with the same stdin handoff:

```sh
npx --yes --package @hue-run/sdk@0.13.2 --package "zod@^4.6.5" hue eval --worker --command "node \"$PWD/agent.js\"" --revision "<new-agent-revision>" --env-file .env.hue
```

TypeScript 0.13.2 command workers register both `direct:v1` and `environment:v1`. When upgrading an existing worker, use a new `--revision`: a registered revision's capabilities cannot change. Keep that revision stable for runs that should use the same agent code.

A TypeScript adapter runs inside `hue eval`'s own process, where `HUE_WORLD_TOKEN` and `HUE_EXECUTION_ID` are not set, so the helper would return production values. A world-only adapter must throw when `context.world` is missing, then either pass `context.world.env` as `env` to every helper call or spawn the agent with [`agentEnvironment(context.world)`](/reference/typescript#world-handoff). A direct adapter receives `context.mode: "direct"` and `context.executionId`; pass `{ HUE_EXECUTION_ID: context.executionId }` to the helper and do not connect apps. Adapter-file workers register only world support by default; add `--capability direct:v1` only after the adapter handles that direct context. Never set `process.env` yourself: with `--concurrency` above 1 that leaks one case's world into another. Prefer `--command`, which supplies the correct case environment. Python drives worlds with the [`hue_sdk.environment`](/reference/python#world-handoff) helpers `agent_environment` and `mcp_config_file`. A world the simulation gateway does not serve has no handoff and sets no `HUE_WORLD_TOKEN`; a required app connection refuses it. See [worlds with a handoff](/evaluations/simulations#worlds-with-a-handoff).

## Verify before you finish

- **Production unchanged.** With both `HUE_WORLD_TOKEN` and `HUE_EXECUTION_ID` unset, the helper returns the production URL and credential for every call site, and the application's existing tests pass.
- **Answer-only.** With `HUE_EXECUTION_ID` set and no world token, evaluation detection succeeds, optional apps are skipped and the agent can answer without tools.
- **Fail closed.** A required app or MCP connection without a world token, or an app without its mirror URL, throws before any request is sent and never reads production credentials. Code the model writes cannot reach the real host.
- **Same tools.** Every app the world includes exposes the tools production has. Nothing was added or removed, and nothing Hue-native was handed to the agent.
- **Adapter**, when you use one. Pass the supplied world's environment for world cases and the execution identity for direct cases. A world-only adapter refuses a missing world; a direct adapter connects no apps.
- **Clean diff.** The change is the helper, its call sites, an optional entry point and an optional test, and no Hue variable or value is in production configuration, secrets or a committed file.
- **A real run.** You have the run URL, the printed verdicts, `get_case_divergence` on a failing case, and stdout that carried no credential.

## Production safety

- The world variables exist only in the process `hue eval` starts, and `hue eval` removes the `HUE_MCP_CONFIG` file after each case. Production never sets `HUE_WORLD_TOKEN` or `HUE_EXECUTION_ID`, so the helper takes the production branch there and reads your real credential exactly as before.
- Never copy `HUE_WORLD_TOKEN`, `HUE_SIM_*` or `HUE_MCP_*` values into production secrets or a committed file. They belong to one case and are useless and misleading anywhere else.
- A world token reaches only one simulated world in one project and expires with it. It is never a credential for the real app, and the real app never sees it.
- Keep the project key out of the agent: `hue eval` strips `HUE_API_KEY` and any Hue-key-shaped value from the command's environment by default, so an agent that traces itself with Hue exports nothing during an evaluation and the run's trace holds only the CLI's case span. Build the tracing client with `createHueSafe` / `create_hue_safe`, which fall back to a disabled client; strict `createHue` / `Hue` throw without a key. Pass `--allow-hue-credentials` only when you need the agent's own spans and accept that the agent then holds the project key. Read what the agent did from `get_run_execution` and `get_case_divergence`.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Exit 1 with an unsaved eval-set version | Rerun with `--save-version`. |
| `hue eval needs zod` | Use the two-package `npx` form above. |
| The helper throws "no world handoff" | A required app or MCP connection has no world token. An answer-only case should skip optional apps; a case that needs apps requires a world with a gateway handoff. |
| The helper throws "`HUE_SIM_…_URL` is not set" | The world does not include that app; connect it only where `appInWorld` is true. |
| 501 `surface_unavailable` | The case needs a mirror this deployment does not serve. |
| `no_calls` on a case that needed app calls | Check where the agent's requests went before changing a call site; see below. |
| Telemetry not accepted in time | Rerun with `--trace-not-accepted pending`. |

## If the agent hard-codes real URLs

An agent that keeps a real URL calls the real app during the evaluation, outside the world. Hue records none of those calls, so the world seals with nothing to score, while the real app receives the writes. Make every app URL and credential configurable through the helper above. The world's `no_calls` flag is advisory: an agent can also stop before its first request or invent an answer without using an app. On a case that needed app calls, a `no_calls` world together with an answer that claims the agent acted has two possible causes, a call site that still points at production or an agent that made no request. Check where the agent's requests went, from its own logs, before changing a call site.
