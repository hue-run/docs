Hue gives a coding agent three surfaces. They are complementary: the skill teaches the agent how to integrate Hue well, the MCP server gives it live data inside your project, and the SDKs and REST API are the scriptable path for CI and shell-capable agents.

The installable project-data server runs at `https://mcp.hue.run/mcp`. A separate documentation-only MCP runs at `https://docs.hue.run/mcp`; it cannot read your Hue project. Simulations can also provide an execution-scoped MCP connection for one disposable world. That short-lived connection is passed to the simulation callback and is not a replacement for the project-data server.

| Surface | Use it when | It owns | It never does |
| --- | --- | --- | --- |
| [Hue skill](/guides/invited-setup) | The agent is adding or troubleshooting tracing in an application | How to install the SDK, choose a capture policy, keep serving requests independent of telemetry and verify a real request | Grant credentials, read your project's data |
| [Hue MCP server](/agents/mcp-server) | The agent needs live project data: find failing traces, inspect a span, check a receipt, read or author evaluations, inspect reviewed cases, or inspect settings | Project-scoped tools with pagination, deep links and documentation search. Writes appear only with **Read and write** access. IAM, AI-processing consent, taxonomy and managed-target writes need an owner or admin; through sign-in, trace-check changes do too | Billing and plan changes; OTLP ingest; artifact bytes; org invites or role changes; access to other projects |
| [SDKs](/sdks/typescript) and REST | CI jobs and agents that can run a shell and prefer to filter data in code | Tracing, receipts, datasets, scorers, experiments and evaluation runs | Browse traces — the clients expose no trace-search API |

## Which one to reach for

- **The agent can run a shell and is changing application code.** Install the skill and let it use the SDK. Add the MCP server when the agent should also confirm what Hue stored without asking you to open the UI.
- **The agent cannot run a shell**, for example a hosted assistant, **or you want several connected actions in one conversation** ("find yesterday's failing traces, show me the slowest span, compare the last two experiments"). Connect the MCP server; a hosted assistant that supports MCP sign-in adds the URL and signs in with Hue. Hue has not yet verified claude.ai or ChatGPT end to end.
- **You are automating in CI.** Use the SDK evaluation clients and the receipt endpoint directly.

## Authentication

Application telemetry and agent access have different authentication needs:

- The application's `HUE_API_KEY` uses **Tracing only** for telemetry and known-trace receipts. Use **Read and write** only when that process also manages datasets, scorers, experiments, simulations, environments, or managed runs.
- For MCP access, [sign in with Hue](/agents/mcp-server#sign-in-with-hue-instead-of-a-key) and approve **Read** or **Read and write** for one project. Clients that accept project keys can instead use `HUE_MCP_KEY` with the same access choices. Configure that key in the MCP client, never in application code. The [MCP connection guide](/agents/mcp-server) covers both methods and client setup.

See [project keys](/guides/project-keys) for the presets and rotation.

## What the agent sees

Everything the MCP server returns from your traced application is treated as data: names, generated titles, metadata and judge explanations are length-capped and labelled untrusted, recorded prompts and outputs appear only when a tool is called with `include_content: true`, and credential-shaped strings are redacted. Each result carries a link that opens the object in Hue for a signed-in member of the project.
