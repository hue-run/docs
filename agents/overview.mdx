Hue gives coding agents three complementary surfaces: the skill teaches integration, the MCP server provides project data, and the SDKs provide a scriptable path.

The installable project-data server runs at `https://mcp.hue.run/mcp`. A separate documentation-only MCP runs at `https://docs.hue.run/mcp`; it cannot read your Hue project. Simulations can also provide an execution-scoped MCP connection for one disposable world. That short-lived connection is passed to the simulation callback and is not a replacement for the project-data server.

| Surface | Use it when | It owns | It never does |
| --- | --- | --- | --- |
| [Hue skill](https://docs.hue.run/skill.md?v=0.6.9&release=3ec5394) | Adding or troubleshooting tracing | SDK setup, capture policy, safe exports, and request verification | Grant credentials or read project data |
| [Hue MCP server](/agents/mcp-server) | Inspecting project data or production traces | Project tools, pagination, deep links, and documentation search. Writes need **Read and write**; admin settings need an owner or admin ([permissions](/agents/mcp-tools#permissions)) | Billing, OTLP ingest, artifact bytes, org invites or role changes, or access outside the key's project or signed-in organization |
| [SDKs](/sdks/typescript) and REST | Automating tracing or evaluations in CI | Tracing, receipts, eval sets, evaluators, runs, and scoring runs | Browse traces; clients expose no trace-search API |

## Install the Hue skill

Run this from your application's repository and select your coding agent:

```sh
npx skills add hue-run/hue-sdk --skill hue
```

Then send the prompt from [Agent setup](/guides/agent-setup). Your agent guides you through storing a key, adding tracing, verifying a real request, and connecting the Hue MCP server.

## Skill or MCP

- **Changing application code.** Install the skill and use the SDK. Add the MCP server when the agent should confirm what Hue stored.
- **Investigating production.** Connect the MCP server and ask what needs attention, what failed, or which requests are slow. Start with [Recipes](/agents/mcp-tools#recipes).
- **Debugging a simulated app.** Build a Linear environment from a trace, connect your agent, and inspect each attempt in [Environments from traces](/agents/debug-environment).
- **Working without a shell or combining project actions.** Connect the MCP server; clients with sign-in use Hue OAuth, while other clients use a **Read** or **Read and write** key.
- **Automating in CI.** Use the SDK evaluation clients and receipt endpoint directly.

For a coding agent implementing content scrubbing, use [Redaction](/guides/redaction). It includes email examples, exporter attachment points and a synthetic verification checklist. The [Hue skill](https://docs.hue.run/skill.md?v=0.6.9&release=3ec5394) routes agents to the same guide.

## Authentication

Application telemetry and agent access have different authentication needs:

- The application's `HUE_API_KEY` uses **Tracing only** for telemetry and known-trace receipts. Use **Read and write** only when it also manages eval sets, evaluators, runs, simulations, environments, or managed runs.
- For MCP access, [sign in with Hue](/agents/mcp-server#sign-in-with-hue) for projects in one organization. Use `HUE_MCP_KEY` for a **Read** connection or for clients and runs without a browser; use **Read and write** when the client writes project data.

See [Project keys](/quickstart#project-keys) for the presets and rotation.

## Available data

Everything the MCP server returns from your traced application is treated as data: names, generated titles, metadata and judge explanations are length-capped and labelled untrusted, recorded prompts and outputs appear only through `get_span_content` or a tool called with `include_content: true`, and credential-shaped strings are redacted. Each result carries a link that opens the object in Hue for a signed-in member of the project.
