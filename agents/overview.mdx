Hue gives a coding agent three complementary surfaces. One-command setup and the skill teach a shell-capable agent how to integrate Hue safely, the MCP server gives it live data inside a linked project, and the SDKs and REST API are the scriptable path for CI.

The installable project-data server runs at `https://mcp.hue.run/mcp`. A separate documentation-only MCP runs at `https://docs.hue.run/mcp`; it cannot read your Hue project. Simulations can also provide an execution-scoped MCP connection for one disposable world. That short-lived connection is passed to the simulation callback and is not a replacement for the project-data server.

| Surface | Use it when | It owns | It never does |
| --- | --- | --- | --- |
| [One-command setup and Hue skill](/guides/agent-setup) | The agent is adding or troubleshooting tracing in an application | Supported repository detection, dependency installation, metadata-only integration, a real request and exact receipt verification | Guess through an ambiguous repository, expose credentials or read linked project data |
| [Hue MCP server](/agents/mcp-server) | The agent needs live project data: find failing traces, inspect a span, check a receipt, read or author evaluations, review work, or inspect settings | Project-scoped tools with pagination, deep links and documentation search. Writes appear only for a **Coding agent (read + evaluations)** key. IAM, consent, taxonomy and managed-target writes need an owner or admin creator | Billing and plan changes; OTLP ingest; artifact bytes; org invites or role changes; access to other projects |
| [SDKs](/sdks/typescript) and REST | CI jobs and agents that can run a shell and prefer to filter data in code | Tracing, receipts, datasets, scorers, experiments and evaluation runs | Browse traces — the clients expose no trace-search API |

## Which one to reach for

- **The agent can run a shell and is changing application code.** Give it the [one-command setup prompt](/guides/agent-setup#give-the-agent-one-prompt) once that unpublished 0.4.0 flow is on `@hue-run/sdk@latest`. A supported repository can start a bounded metadata-only trial without an account. Add the MCP server after account linkage when the agent should inspect project data. Until then, use the [manual SDK guides](/installation).
- **The agent cannot run a shell**, for example a hosted assistant, **or you want several connected actions in one conversation** ("find yesterday's failing traces, show me the slowest span, compare the last two experiments"). Connect the MCP server.
- **You are automating in CI.** Use the SDK evaluation clients and the receipt endpoint directly.

## Keys

Each surface uses a different key so that a leaked credential has the smallest possible blast radius:

- The one-command trial keeps a bounded metadata-only credential in an ignored owner-only local file. It can send setup traces and verify only its installation's receipts; setup log export is rejected. Account linkage replaces it and Hue refuses the old value.
- The application's `HUE_API_KEY` uses **Tracing only** for telemetry and known-trace receipts. Use **Tracing and evaluations** only when that process also manages datasets, scorers, experiments, simulations, environments, or managed runs.
- The agent's `HUE_MCP_KEY` uses **Coding agent (read-only)** for inspection, or **Coding agent (read + evaluations)** when it should also write project data. Configure it in the MCP client, never in application code.

See [project keys](/guides/project-keys) for the presets and rotation.

## What the agent sees

Everything the MCP server returns from your traced application is treated as data: names, generated titles, metadata and judge explanations are length-capped and labelled untrusted, recorded prompts and outputs appear only when a tool is called with `include_content: true`, and credential-shaped strings are redacted. Each result carries a link that opens the object in Hue for a signed-in member of the project.
