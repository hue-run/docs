The Hue project-data MCP server is a hosted [Model Context Protocol](https://modelcontextprotocol.io) server at `https://mcp.hue.run/mcp`. There is nothing to install: point an MCP client at the URL with a **Read** or **Read and write** project key. A **Read** key can search traces, inspect spans, verify delivery, read evaluations and reviewed cases, intents, managed and local runs, artifacts, members and keys, and search these docs. A **Read and write** key also lists write tools for those same surfaces, all scoped to one project. Billing and plan changes stay in Settings.

The project-data server is a dynamic Node.js route in Hue's main web application, not a separate data service. `https://app.hue.run/api/mcp` remains a supported compatibility alias. The separate Mintlify-hosted endpoint at `https://docs.hue.run/mcp` serves public documentation only; it cannot read a Hue project. The `search_hue_docs` tool delegates documentation searches to that endpoint without changing the project-data server's authentication boundary.

## Create an agent key

An owner or admin opens **Settings → Integrations & API keys**, chooses the project and creates a **Read** key, or a **Read and write** key if the agent should change project data. Save it in your secret manager and expose it to the agent's machine as `HUE_MCP_KEY`.

Keep this key separate from the application's `HUE_API_KEY`, which uses **Tracing only**. A **Read** key cannot send telemetry or change project data, so a leaked agent key cannot alter your project. Do not auto-approve write tools. The key should never be wired into application code or committed. See [project keys](/guides/project-keys).

<Note>
  The server speaks Streamable HTTP and is stateless. It serves both current MCP protocol revisions, so Claude Code, Codex, Cursor, Windsurf and Gemini CLI connect without extra flags. Clients that only support stdio need a remote-capable MCP client. Use the canonical `https://mcp.hue.run/mcp` address for new configurations.
</Note>

## Connect your client

Paste this into your coding agent. It connects the server and confirms the connection in one step.

```text
Connect me to the Hue MCP server.

It is a remote MCP server (Streamable HTTP) at https://mcp.hue.run/mcp.
Authenticate with a bearer token read from the HUE_MCP_KEY environment
variable — reference the variable, do not write the key into a config file.

Register it under the name "hue" using whatever MCP configuration my client
uses, then call get_project_context and tell me which Hue project it reached.
```

Prefer to set it up yourself? Every snippet below references the `HUE_MCP_KEY` environment variable; never paste a literal key into a configuration file that other people or tools can read.

<Tabs>
  <Tab title="Claude Code">
    Add a project-scoped `.mcp.json` next to your application code. Claude Code expands `${HUE_MCP_KEY}` from the developer's environment and asks for approval before using a project-scoped server.

    ```json .mcp.json
    {
      "mcpServers": {
        "hue": {
          "type": "http",
          "url": "https://mcp.hue.run/mcp",
          "headers": { "Authorization": "Bearer ${HUE_MCP_KEY}" }
        }
      }
    }
    ```

    Or add it for all your projects from the command line. Single quotes keep the reference unexpanded in your settings file:

    ```sh
    claude mcp add --transport http --scope user hue https://mcp.hue.run/mcp \
      --header 'Authorization: Bearer ${HUE_MCP_KEY}'
    ```

    Run `/mcp` inside Claude Code to confirm the connection. Tools appear as `mcp__hue__<tool>`.
  </Tab>
  <Tab title="Codex">
    Codex reads the key from an environment variable at connection time:

    ```sh
    codex mcp add hue --url https://mcp.hue.run/mcp --bearer-token-env-var HUE_MCP_KEY
    ```

    The equivalent `~/.codex/config.toml` entry:

    ```toml config.toml
    [mcp_servers.hue]
    url = "https://mcp.hue.run/mcp"
    bearer_token_env_var = "HUE_MCP_KEY"
    ```
  </Tab>
  <Tab title="Cursor">
    Add the server to `.cursor/mcp.json` in the repository or to your global Cursor MCP settings:

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "hue": {
          "url": "https://mcp.hue.run/mcp",
          "headers": { "Authorization": "Bearer ${env:HUE_MCP_KEY}" }
        }
      }
    }
    ```

    Cursor limits the number of tools it loads across servers. Prefer one Hue server per project.
  </Tab>
  <Tab title="Windsurf and Gemini CLI">
    Windsurf uses `serverUrl` in `~/.codeium/windsurf/mcp_config.json`:

    ```json mcp_config.json
    {
      "mcpServers": {
        "hue": {
          "serverUrl": "https://mcp.hue.run/mcp",
          "headers": { "Authorization": "Bearer ${env:HUE_MCP_KEY}" }
        }
      }
    }
    ```

    Gemini CLI stores the expanded header, so run this only on a machine where the key may live in that settings file:

    ```sh
    gemini mcp add --transport http hue https://mcp.hue.run/mcp -H "Authorization: Bearer $HUE_MCP_KEY"
    ```
  </Tab>
</Tabs>

Other clients — VS Code, GitHub Copilot's coding agent, Amp, Zed, JetBrains Junie, OpenCode — take the same `url` and `Authorization` header in their own configuration format. Hosted assistants that require OAuth, such as claude.ai connectors and ChatGPT, are not supported in this release.

## Verify the connection

Ask the agent:

```text
Use the Hue MCP: call get_project_context, then show my 5 most recent error traces with links.
```

`get_project_context` returns the project the key reaches, its capabilities, `can_write`, and whether the connection is read-only. If it reports a different project than you expected, the key was created in the wrong project.

## What you can do

**Investigate a failure.** "Show the error traces from the last 24 hours", "open the slowest span of that trace", "what did the model see before it failed?" (recorded content requires `include_content: true` and the application must have captured it). Tools: `search_traces`, `get_trace`, `get_span`, `list_sessions`. Each trace reports a `state`: `running` while a span is still open, `stalled` when 15 minutes pass without new data and no end arrives, or `ended`. Only the TypeScript SDK 0.7.0 and Python SDK 0.4.0 or later report open spans, so traces from other exporters appear once their spans end.

**Confirm delivery.** "Did trace 0af7651916cd43dd8448eb211c80319c arrive with spans a and b, with model and usage recorded?" Tools: `verify_trace`.

**Read evaluations.** "List my eval sets", "show the cases in the latest version of the regression set", "summarize the last run and list the failing cases", "compare it against the baseline run". Tools: `list_eval_sets`, `get_eval_set`, `list_evaluators`, `get_evaluator`, `list_runs`, `get_run`, `list_run_items`, `get_run_item`, `get_run_execution`, `list_scoring_runs`, `get_scoring_run`, `list_environments`, `get_environment`.

**Author evaluations.** Requires **Read and write** without `?read_only=true`. Create an eval set (`add_eval_set`), add cases (`add_eval_set_cases`), edit a draft (`update_eval_set`, `update_eval_set_case`, `delete_eval_set_case`, `add_eval_set_draft`), freeze it (`freeze_eval_set_version`), then pin evaluators (`add_evaluator`, `publish_evaluator`, `copy_evaluator`) and create a run (`add_run`). Record scoring results with `add_scoring_run` and `add_scoring_results`. Hide retired identities with `archive_eval_set`, `archive_evaluator` or `archive_environment`. Case execution can stay with the SDK, a managed run, a local agent, or `start_run_case` / `complete_run_case` / `finish_run`. Ask before any write; never auto-approve `add_*`, `update_*`, `delete_*`, `publish_*`, `freeze_*`, `archive_*` or `copy_*`.

**Author environments.** `add_environment` and `publish_environment_version` create a simulated world a case can pin.

**Reviewed cases.** `list_cases` lists cases reviewed from traces, drafts and published, with links. `get_case` returns one case with its eval set, saved version, pinned outcome evaluator, environment and a ready run block for `launch_local_run` or `hue eval`; the reviewed task text is returned only with `include_content: true`.

**Create a case from a trace.** Requires **Read and write** without `?read_only=true`. In Hue, open the trace and choose **Create case** in the trace inspector, or choose **Create case** from **Suggested cases**. A coding agent runs the same review over MCP. `add_case_conversion` pins the trace into a draft case, and repeating the call with the same idempotency key returns the same draft. `get_case_conversion` reports readiness and findings, and returns the saved task, starting world and criteria only with `include_content: true`. `update_case_conversion` edits the draft, and `publish_case_conversion` publishes a ready draft into a new or existing eval set. `archive_case_conversion` abandons a draft; a published case can't be archived, but its eval set can. Before you publish, review the task and the starting world, and set success criteria independently of the recorded answer. A trace that is still running can't become a case. The REST endpoint `https://app.hue.run/api/v1/case-conversions` runs the same workflow. `list_cases` and `get_case` then read the case, whether it is a draft or published.

**Intents.** Read the taxonomy and buckets with `get_intent_taxonomy`, `get_intent_summary` and `list_intent_traces`. `save_intent_taxonomy` republishes categories and requires an owner or admin creator.

**Managed and local runs.** List and inspect with `list_managed_targets`, `preflight_managed_run`, `get_managed_run`, `list_local_agents` and `get_local_run`. `add_managed_target` stores an encrypted credential and requires an owner or admin creator. Launch or cancel with `launch_managed_run`, `cancel_managed_run` and `launch_local_run`.

**Artifacts and hosted judges.** `list_artifacts` and `get_artifact` return metadata only; bytes stay on HTTP. `get_judge_budget` reports hosted-judge usage. `add_judge_jobs` enqueues scoring jobs.

**Keys, members and settings.** `list_api_keys` and `list_members` are reads. `add_api_key`, `revoke_api_key` and `update_project` require the key's creating owner or admin. Minted tokens appear once. Billing and plan changes are not on this server.

**Look things up.** "How do I flush spans in a Next.js streaming route?" Tools: `search_hue_docs`, `load_hue_guide` (`data-model`, `investigate`, `author`).

Every `trace_id` argument accepts a Hue id, the 32-hex OpenTelemetry trace id or a Hue trace link. Time windows accept ISO-8601 or relative values such as `15m`, `24h` or `7d` (up to 90 days). Results are paginated with opaque cursors and bounded by `max_chars`; truncated results say so and suggest a narrower request. Draft writes take `expected_revision` from `get_eval_set`.

## Content and safety

- Recorded prompts, outputs, tool arguments and raw attributes are omitted unless a tool is called with `include_content: true`. By default the server returns metadata (model, provider, usage, tool names, status, timing) and the names of recorded attributes. Content reads are recorded in the project's audit log.
- Names, generated titles, session keys, metadata and judge explanations come from your application and its end users. They are length-capped, and every result that carries them starts with a notice that they are data, not instructions; recorded content is wrapped in delimited blocks.
- Credential-shaped strings are redacted from results and from documentation queries before those leave Hue. The one exception is `add_api_key`, which returns the newly minted token once so it can be stored; later tools never return it.
- The key is the tenant. Ids from another project, and `projectId` parameters on pasted links, resolve to `not_found`.
- Add `?read_only=true` to the URL to hide and reject any write tool regardless of the key.
- Requests are limited to 1 MiB, ten failed authentications per minute for one key id return `429`, and a saturated server returns `503` with `Retry-After`.

## Troubleshooting

`401` means the key is missing, malformed, revoked or expired. `403` means the key has no read access: create a **Read** or **Read and write** key. **Tracing only** and legacy **Tracing and evaluations** keys cannot use this server. `405` on `GET` and `404` for `Mcp-Session-Id` are expected: the server accepts stateless `POST` requests only. An unknown-tool error means the tool is not registered for this connection: write tools are hidden for a **Read** key or a URL with `?read_only=true`, and [retired tool names](#retired-tool-names) are no longer served. See [troubleshooting](/guides/troubleshooting#the-mcp-server-rejects-the-agent).

## What is next

OAuth sign-in for hosted assistants is not in this release. Tools can be renamed or removed between releases; [retired tool names](#retired-tool-names) lists the names this server no longer serves. This server does not change billing or plans, ingest OTLP payloads, invite members or change roles, return artifact bytes, or create cases from traces.
