Start with the [Python guide](/sdks/python) for installation and a runnable trace, and [compatibility](/sdks/compatibility) for supported runtimes and instrumentation. Use the [installation guide](/installation) for the available package release.

## Create a tracing client

```python
import os
from hue_sdk import Hue

hue = Hue(
    api_key=os.environ["HUE_API_KEY"],
    capture_content=True,  # Record supported input/output content.
    service_name="my-agent",
)
```

```python
Hue(
    base_url: str = "https://app.hue.run",
    api_key: str | None = None,
    *,
    capture_content: bool,
    service_name: str = "hue-python-agent",
    tracer_provider: TracerProvider | None = None,
    logger_provider: LoggerProvider | None = None,
    redactor: Redactor | None = None,
    export_timeout_seconds: float = 10,
    enabled: bool = True,
    max_queue_size: int = 2048,
    max_queue_bytes: int = 8388608,
    live_spans: bool = True,
)
```

| Option | Behavior |
| --- | --- |
| `base_url` | Optional origin; defaults to `https://app.hue.run`. Do not append an API path. HTTPS is required except for loopback HTTP; credentials, query strings and fragments are rejected. |
| `api_key` | Required project service key. Use **Tracing only** for tracing and known-trace receipts; use **Read and write** when this process also calls evaluation APIs. Keep it in the server environment. |
| `capture_content` | Required explicit `True` or `False`; there is no default. `True`, the recommended setting, records supported content; `False` sends metadata only. See [content policy](#content-policy). |
| `service_name` | Default `"hue-python-agent"`; configures the resource when Hue creates both providers. |
| `tracer_provider` | Optional OpenTelemetry SDK `TracerProvider` to borrow. Hue adds its span processor without replacing the global provider. |
| `logger_provider` | Optional OpenTelemetry SDK `LoggerProvider` to borrow for correlated logs. Hue adds its log record processor without replacing the global provider. |
| `redactor` | Optional `Callable[[str, Any], Any]`: receives a field name and helper content, and returns a JSON-serializable replacement. |
| `export_timeout_seconds` | Default `10`; positive finite number. Configures export HTTP I/O and project validation; it is distinct from a flush wait budget. |
| `enabled` | Default `True`; must be a boolean. `False` creates a disabled client without requiring a key or attaching to a supplied provider. |
| `max_queue_size` | Default `2048`; positive integer limiting pending records per signal, including admissions and active export batches. |
| `max_queue_bytes` | Default `8388608`; positive integer limiting encoded queue bytes per signal, including active export batches. |
| `live_spans` | Default `True`; must be a boolean. Sends placeholders for open Hue and AI spans. A span still open when its placeholder is exported, usually about 1.5 s after it starts, shows as running. Setup keys never send placeholders. See [live spans](#live-spans). |

Use the `api_key=` keyword when omitting the origin. The first positional parameter is `base_url`, so `Hue("<key>")` raises `TypeError` naming `api_key=`; existing `Hue(base_url, api_key, ...)` calls are unchanged. When enabled, the key is required and validated even though the signature permits `None`. Disabled clients do not require a key. The constructor does not load environment variables or an environment file automatically. Invalid options raise `TypeError` or `ValueError`.

With a borrowed tracer or logger provider, your application owns that provider's resource and other processors, and the provider Hue creates for the other signal reuses the borrowed provider's resource, so spans and correlated logs report one `service.name`. Borrowed providers are not shut down by the client. Use one Hue instance for its provider lifecycle; OpenTelemetry has no public processor-removal API. See [existing OpenTelemetry](/integrations/opentelemetry).

## Spans and context

Use `with` for the context managers below. They are ordinary synchronous context managers that may surround work inside an async function.

```python
with hue.context(session_id="conversation-1", user_id="application-user"):
    with hue.span("request") as run:
        with hue.tool("uppercase") as tool:
            tool.set_input("hello")
            result = "hello".upper()
            tool.set_output(result)
        run.set_output(result)
```

| Method | Parameters and behavior |
| --- | --- |
| `hue.context(*, session_id=None, user_id=None, workspace_id=None)` | Adds task-local identifiers inherited by nested Hue helpers. Maps to `gen_ai.conversation.id`, `user.id` and `hue.workspace.id` (the application workspace or tenant); does not modify global baggage. |
| `hue.span(name, *, attributes=None, kind=SpanKind.INTERNAL, parent_context=None)` | Yields `HueSpan`, activates its OpenTelemetry context and ends it on exit. Explicit attributes override inherited attributes with the same name. |
| `hue.model(model, *, provider, operation="chat", name=None, system_instructions=..., tools=...)` | Yields a client span with model/provider/operation attributes. Default name is `"{operation} {model}"`. Optional `system_instructions` and `tools` (any JSON value, ideally in the GenAI shapes) are recorded as `gen_ai.system_instructions` and `gen_ai.tool.definitions` when content is captured; omit them to record nothing. It does not invoke a model or estimate usage. |
| `hue.tool(name, *, call_id=None, mcp=None)` | Yields a tool span named `"execute_tool {name}"`, with an optional tool-call identifier. `mcp` is a mapping with optional `name`, `version`, `provider` and `surface`, recorded as `mcp.server.name`, `mcp.server.version`, `hue.mcp.provider` and `hue.mcp.surface`; an invalid value is omitted and counted as an instrumentation failure. |
| `Hue.inject(headers)` | Adds the active W3C trace context to a mutable string mapping. Does not insert the Hue key or baggage. |
| `Hue.extract(headers)` | Returns an OpenTelemetry `Context` to pass as `parent_context`. |

An exception escaping a Hue span records error type/status, then propagates unchanged. Python helpers always omit exception messages and stacks, including when capture is enabled. Initialize the client once, keep spans open until their work ends, and shut down when the process stops.

### HueSpan

| Member | Behavior |
| --- | --- |
| `trace_id` / `span_id` | Hexadecimal OpenTelemetry identifiers. |
| `otel_span` | Underlying OpenTelemetry span for standard attributes, events and context APIs. |
| `set_attribute(name, value)` | Sets caller-owned OpenTelemetry metadata. |
| `set_input(value)` / `set_output(value)` | Captures JSON helper content according to `capture_content` and the redactor. Model/tool helpers choose their corresponding GenAI field names. |
| `set_usage(*, input_tokens=None, output_tokens=None)` | Sets known nonnegative integer token counts. `None` omits a count; booleans and negative counts are rejected. |
| `record_error(error)` | Records error type and status without exception text. Does not raise the supplied error itself. |
| `record_file(*, role, media_type, sha256=None, data=None, byte_size=None, name=None)` | Adds a `hue.file` event for a file the work read, received or produced. `role` is `input`, `attachment` or `output`. `data` is hashed and measured locally and never exported (a `str` is hashed as UTF-8); pass `sha256` and `byte_size` instead when you already have them. The event carries `hue.file.sha256`, `hue.file.role`, `hue.file.media_type`, `hue.file.size` when known and, only when content is captured, `hue.file.name`. It is recorded in both capture modes; an invalid record is omitted and counted. |
| `log_inference(...)` | Accepts optional keyword-only `input`, `output`, `operation`, `provider`, `model` and `system_instructions`. Emits an inference-details log correlated to this span, even outside its active scope, with a structured body and `gen_ai.*` request attributes from the enclosing `model()` block or those keywords plus `gen_ai.conversation.id` from `context()`. Omit a content keyword for an absent field; passing `None` keeps the key with an empty value. Nothing is emitted when `capture_content` is False. |

Choose logs or span attributes for the same content event to avoid duplicate storage. `log_inference` emits no record when content capture is disabled. `hue.tracer`, `hue.tracer_provider` and `hue.logger_provider` expose the configured OpenTelemetry objects for integrations that accept explicit instances.

## Content policy

`capture_content=False` omits input/output content from Hue's helpers **before it enters an OpenTelemetry queue** and, at export, strips recognized GenAI, OpenInference, OpenLLMetry and Vercel AI SDK content attributes, legacy `gen_ai.*` message events, log bodies and status descriptions from every record on Hue's export path, including spans from third-party instrumentors on a borrowed provider. The key list is identical to TypeScript's `contentPrefixes` and is reproduced in the [compatibility matrix](/sdks/compatibility). `True` permits that content. The policy does not classify arbitrary attribute names, span names, session identifiers or another exporter's records; unrecognized custom keys pass through. Configure an external instrumentor's own content policy before enabling it.

When content is captured, export replaces hosted-tool credentials (such as `authorization`, `authorization_token`, `headers` and `api_key`) in recorded tool definitions and in the `tools` and `mcp_servers` entries of recorded raw requests with `"[redacted]"`, and exports a `blob` or `file` message part over 64 KiB as its `sha256` and `size` instead of its payload; a message attribute over 8 MiB is dropped by the snapshot budget instead. When `capture_content=False` removes tool definitions, the record keeps `hue.tool.names` and `hue.tool.definitions.sha256`. The [compatibility matrix](/sdks/compatibility) lists the exact fields.

`redactor(field, value)` receives a bounded, detached content snapshot before helper JSON serialization. Supported inputs are ordinary built-in JSON-compatible scalars, dictionaries and lists, plus built-in tuples and scalar dictionary keys accepted by Python's JSON encoder. Container shape and nested values are preserved without sharing mutable application containers. Custom objects and subclasses, cycles, non-finite numbers, integers above 14,000 bits, depth beyond 64, more than 65,536 visited values/keys, or a conservative value budget above 1 MiB are rejected before the callback. The budget counts UTF-8 string bytes plus value overhead; it is not a process-memory limit. The initial snapshot also runs when no redactor is configured. A redactor's returned value passes through a fresh snapshot with the same independent bounds before JSON encoding, so oversized nested output or custom serialization hooks cannot bypass this check.

A snapshot, redaction or serialization failure omits that field and increments `export_status.instrumentation_failures` without raising into application work. A redactor may mutate its copy without changing application inputs or results, but must not mutate globals or objects obtained through captured references. Final captured fields are limited to 256 KiB of UTF-8 JSON. JSON `None`, `False`, `0` and `""` remain distinct from omitted content. Received content is stored by Hue; the SDK does not set a retention timer.

## Delivery and shutdown

```python
hue.validate_project() -> Project
hue.force_flush(timeout_millis: int = 30_000) -> bool
hue.shutdown(timeout_millis: int = 30_000) -> bool
hue.export_status -> ExportStatus
```

`validate_project()` returns a frozen `Project` with `id`, `name`, `slug` and `organization_id`. Authentication, connection or invalid-response failures raise `ProjectValidationError`; the exception does not contain the key. Validation sends no trace.

`force_flush()` drains traces and logs. It returns `False` on timeout, a processor failure, a closed client, or **any recorded failed export batch, dropped record or instrumentation failure during this client's lifetime**. Inspect `export_status.failed_trace_batches`, `failed_log_batches` and `ok`; these are cumulative batch failure counters, not accepted-span counts.

A flush timeout bounds how long the caller waits; it does not cancel network work already running in the background. Timeout values must be positive integers. Queues are bounded and in memory; termination or overflow can lose telemetry. A successful flush does not prove that every operation was instrumented or that all parents have arrived.

`shutdown()` stops new helpers, drains and closes Hue-owned resources. Borrowed tracer and logger providers and their other processors remain usable. A timeout returns `False` while shutdown continues; repeated calls wait for the same shutdown work. A `with Hue(...) as hue:` block calls `shutdown_safe(timeout_millis=1000)` on exit, but does not raise if that boolean is false. Use a checked flush when command success must require delivery:

```python
if not hue.force_flush():
    raise RuntimeError("Hue did not acknowledge all telemetry.")
```

Exports use the official OTLP HTTP/protobuf exporters and their retry policy. Request bodies are gzip-compressed and carry a `hue-sdk-python/<version>` User-Agent ahead of the exporter's own token. HTTP errors, malformed acknowledgements and OTLP partial rejections count as failed batches. Partial rejections are not resent as a whole batch. Stop producing spans before shutdown; shared server clients should remain alive between requests.

## Live spans

OpenTelemetry exports a span only when it ends, so a long agent turn or model call would otherwise stay invisible until it finishes. When a Hue helper span or an AI span is still open at the export worker's next 0.5 s tick, Hue queues a placeholder: a standard OTLP span whose parent is the running span, with its name, kind, start time and current attributes and an end time of `0`. Hue shows the span, and its trace, as running and replaces the placeholder when the finished span arrives. Input set right after entering, such as `set_input`, is included. A placeholder whose span ends before it is exported is not sent.

A placeholder usually reaches Hue about 1.5 s after its span starts: up to 0.5 s until the next tick, then about 1 s while the export worker batches it. It arrives sooner when a batch is already scheduled and later while an earlier export is still in flight, because the worker runs the next tick and starts the next 1 s batch only after that export returns. A span shorter than about 1.5 s therefore usually never shows as running and appears only when it ends.

- Only spans from `hue.tracer` (every helper) and spans with a `gen_ai.`, `ai.`, `llm.` or `traceloop.` attribute at start, or a name starting with `ai.`, are announced. HTTP, database and other framework spans are not.
- Placeholders follow the same `capture_content` policy as finished spans. Tool definitions, system instructions and any value over 64 KiB are left out; the finished span still carries them.
- Placeholders carry the running span's name and attributes as set when the export worker builds them, so a value you overwrite before the span ends can still reach Hue. `capture_content=False` strips recognized content keys from them, and `redactor` rewrites helper content before the helper sets it on the span. Scrub any other sensitive attribute where you record it, or pass `live_spans=False`.
- Placeholders are advisory. A placeholder is queued only while the queue is under a quarter of its record and byte budgets and is skipped silently otherwise. While queued they count in `queued_trace_records` and `queued_trace_bytes`, but never as dropped or failed telemetry.
- A receiver that does not accept placeholders, such as a generic collector, rejects them only in the first export that carries them. The SDK then sets `export_status.live_spans_rejected`, a warning that does not affect `ok`, and stops announcing spans for the rest of that client's life.
- Pass `live_spans=False` to send none.
- The SDK registers its span processor on the tracer provider itself and exports no processor to wrap. A provider that wraps it anyway never sees placeholders, so Hue still receives the running span's name and attributes even when the wrapper later drops or edits the span; such a wrapper should forward `on_end` for every span whose `on_start` it forwarded. A placeholder already sent for a span whose finished record never reaches Hue, for example because the span never ends, a wrapper withholds its end or the process exits before flushing it, leaves the span shown as running until Hue marks the trace stalled.

## Trace verification

```python
confirmation = hue.verify_trace(
    trace_id,
    expected_span_ids=[request_span_id],
    required_fields=["model"],
    timeout_millis=10_000,
)
```

Returns a typed `TraceVerificationResult` with `verified` and `receipt: TraceReceipt | None`. A `TraceReceipt` has `trace_id`, `span_count`, `revision`, `fields`, `matched_span_ids`, `missing_span_ids`, and `trace_url`. `fields` is a `TraceReceiptFields` dataclass with `input`, `output`, `model`, `usage` and `session` booleans; it reports the presence of received fields without exposing their captured values. `verified` requires a stored receipt, every supplied expected span, and every required field. Timeout returns `verified=False` with the latest partial receipt, or `None` if none arrived. Other failures raise exported `TraceVerificationError`, with `code` and optional `status_code`, without response bodies or credentials.

`expected_span_ids` and `required_fields` accept sequences. `required_fields` takes `TraceReceiptField` names: `"input"`, `"output"`, `"model"`, `"usage"` and `"session"`.

Trace IDs are 32 lowercase hexadecimal characters; expected span IDs are 16. All IDs must be nonzero. Supply at most 100 unique expected span IDs and unique required field names. The timeout defaults to 10,000 ms and must be positive, finite, and at most 60,000 ms. The receipt response is limited to 64 KiB.

Missing spans or required fields keep polling until the deadline. Only recognized trace-not-found responses, HTTP 429, and HTTP 503 are retried; connection failures, unsupported endpoints, redirects, and malformed responses raise a safe typed error. Verification reads stored normalized field presence across the trace, including supported correlated logs. It does not inspect values or prove that unlisted application operations were instrumented.

[Flush the owning providers before verification](/sdks/python#verify-stored-trace-evidence); this method never flushes implicitly. An in-flight network read may finish in the background after the caller times out.

## Evaluation client

```python
from hue_sdk.evals import EvaluationClient

client = EvaluationClient(
    api_key=os.environ["HUE_API_KEY"],
    timeout_seconds=10,
)
```

`EvaluationClient(base_url: str = "https://app.hue.run", api_key: str | None = None, *, timeout_seconds: float = 10)` requires a valid **Read and write** project service key. Use `api_key=` for Hue Cloud or retain `EvaluationClient(base_url, api_key)` for an explicit origin; a bare key in the first position raises `TypeError` naming `api_key=`. Timeouts must be positive and finite.

Client methods are synchronous and return dictionaries. **Arguments use snake_case; response fields and low-level completion payloads use HTTP camelCase.** `check_connection()` returns the current project. List methods accept keyword-only `after=None, limit=100`; limits are 1–100. Responses contain `items` and `nextCursor`.

Evaluation responses are limited to **4 MiB**. `list_cases(version_id, ...)` includes case content, so a valid row limit can still produce an oversized response when cases are large. Request a smaller page, such as `limit=1`, and pass each non-null `nextCursor` as `after`. The client does not automatically split or retry an oversized page.

#### Scorer declarations and metrics

Scorer `definition` dictionaries use **camelCase** keys, even when supplied to a Python method.

| Definition | Required fields |
| --- | --- |
| Built-in | Use `builtin_scorers.exact_match()`, `builtin_scorers.includes(case_sensitive)` or `builtin_scorers.json_schema(schema)` for the exact versioned declaration. |
| Local code | `kind: "local_code"`, `language: "python"` or `"typescript"`, `entrypoint`, `sourceDigest`, `metrics`. `define_local_scorer` creates the Python declaration and binds the callback. |
| Manual | `kind: "manual"`, `metrics`. Completion requires the platform's human workflow. |
| Hosted judge | `kind: "llm_judge"`, `metrics`, `config`. Hosted dispatch is separate from a local run. |

Import the built-in bundle as `from hue_sdk.evals import builtin_scorers`. `builtins` remains an alias, but it shadows the standard-library module of the same name in any file that imports it. `builtin_scorers.json_schema` needs the optional `hue-run[evals]` extra (`jsonschema` and `referencing`); without it the helper raises `ImportError` and stored schema scorers report `SchemaValidatorUnavailable`.

Each metric definition has a `name` and `type`: `boolean`, `text`, `number` (optional `min`/`max`), or `category` (required `categories`, a list of strings). Results must match the pinned definitions exactly.

Hosted `config` requires `model`, `provider`, `rubric`, `bindings` (a list of dictionaries with `name`, `path`, `required`), `maxOutputTokens` and `timeoutMs`; `temperature` is optional. The declaration states the requested policy; the server validates supported values and project execution settings when it is used.

`complete_execution` accepts a camelCase payload: required `idempotencyKey` and terminal `state` (`succeeded`, `error` or `cancelled`), with optional `output`, `error`, `expectedTraceRevision`, `traceEvidence` (`required` or `omit`) and `omissionReason`. It returns `executionId`, `subjectId`, `traceSnapshotId` and `evaluationItemId`.

Each submitted result requires `evaluationItemId`, `scorerVersionId` and the `Score` fields described below; a local-code result also carries `sourceDigest`. A scored result has `metrics` entries with `name`, `value` and optional `passed`, plus a nonempty `explanation` or an `evidence` value. Error results contain `error` with `type` and optional `message`; skipped results contain an `explanation`.

Mutations do not retry implicitly. Preserve idempotency keys and returned IDs across retries after a lost response. `HueApiError.status` is the HTTP status when available; errors do not echo server bodies. The client rejects invalid JSON before writes, does not follow redirects, and limits request/response bodies to 1 MiB/4 MiB.

Runner target outputs and built-in JSON Schema declarations are limited to 200,000 serialized bytes. JSON validation also enforces nesting depth 32 and 20,000 nodes; for an HTTP write, those structural limits apply to the complete request body. Values must use finite JSON numbers, valid Unicode without NUL, string dictionary keys, lists and dictionaries without cycles. Python integers outside `-(2**53 - 1)` through `2**53 - 1` are rejected; use strings for larger exact integers. The server can apply additional field-specific limits.

### Hosted judge jobs

`get_judge_budget()` reads configured allowance and availability. Call `create_judge_jobs(run_id, *, idempotency_key, jobs)` with `jobs` entries containing `evaluationItemId` and `scorerVersionId`; the result contains `ids`. Inspect `list_judge_jobs(run_id, ...)` or `get_judge_job(job_id)`, and request cancellation with `cancel_judge_job(job_id, *, reason)`.

Submitting hosted jobs is explicit and can consume the project's allowance. Method availability does not establish that the project has a configured provider or budget. Local runners leave hosted and manual pins for their owning workflows.

## Run locally and rescore

```python
run_experiment(
    *, client, hue, experiment_id, target,
    checkpoint_directory, persist_result_content, trace_evidence,
    scorers=None, concurrency=1, schema_timeout_millis=2000,
) -> RunnerReport

rescore(
    *, client, run_id, checkpoint_directory, persist_result_content,
    scorers=None, concurrency=1, schema_timeout_millis=2000,
) -> RunnerReport
```

Both are exported from `hue_sdk.evals` and are synchronous entry points. They support sync or async target/scorer callbacks inside worker threads. From an async application, call the runner through `asyncio.to_thread`.

| Option | Behavior |
| --- | --- |
| `checkpoint_directory` | Required `str` or `Path`, dedicated to this run. Preserve it for upload recovery; keep it out of Git. Checkpoint guarantees require a POSIX filesystem with private permissions and no-follow opens. |
| `persist_result_content` | Required boolean, independent of telemetry capture. |
| `trace_evidence` | Required for `run_experiment`: `TraceEvidence("required")` or `TraceEvidence("omit", "reason")`. |
| `target` | Receives `(inputs, TargetContext)` and returns the output or an awaitable. `TargetContext` has `config`, `item` and `span`. |
| `scorers` | Optional list of bound `LocalScorer` objects. |
| `concurrency` | Default `1`; integer `1–64`. |
| `schema_timeout_millis` | Default `2000`; integer `100–60000`; bounds JSON Schema validation, not arbitrary callbacks. |

Telemetry and evaluation clients must use the same project and origin. `rescore` requires an evaluation run created from saved subject IDs and has **no target callback**. `RunnerReport` exposes `run_id`, `subject_ids`, `result_ids` and `deferred_scorer_version_ids`.

Returning `MISSING` means unavailable output; returning `None` is JSON null. With `persist_result_content=False`, completions and local checkpoints omit raw output, target error messages, scorer evidence and arbitrary explanations. Typed metric values, including custom text values, remain stored. Existing dataset inputs/references are independent of this setting. Historical scoring skips unavailable output without invoking a scorer callback.

### Local scorer exports

| Export | Behavior |
| --- | --- |
| `builtin_scorers.exact_match()` | Publishable typed JSON equality definition. |
| `builtin_scorers.includes(case_sensitive=True)` | Publishable string-inclusion definition. |
| `builtin_scorers.json_schema(schema)` | Publishable JSON Schema draft 2020-12 definition; requires the `hue-run[evals]` extra. |
| `define_local_scorer(*, source, entrypoint, metrics, score)` | Returns `LocalScorer`; source is text or bytes. |
| `score_locally(version, context, *, scorers=None, schema_timeout_millis=2000)` | Returns `Score` without uploading it. |

`ScoreContext` contains `inputs`, `has_output`, `has_expected`, optional `output`/`expected`, `metadata` and `execution_state`. A `Score` is `scored` with declared metrics and explanation/evidence, `error` with a typed error, or `skipped` with an explanation. A false quality verdict remains a scored result, with `passed: False`.

The source digest binds an explicitly supplied source declaration to the local scorer; it does not attest closures or installed dependencies. Custom callbacks have no general execution timeout or side-effect cancellation. JSON Schema uses an isolated subprocess with a deadline and no remote schema fetches. Hosted pins require judge-job dispatch; `score_locally` does not run a hosted judge.

### Recovery errors

| Error | Meaning |
| --- | --- |
| `UncertainExecutionError` | No durable outcome is available. Exposes `case_id` and optional `execution_id`; the runner refuses to repeat potentially completed work. |
| `OutcomeSerializationError` | The target returned, but its outcome could not be saved as JSON. Exposes `execution_id`; the runner does not invoke the target again. |
| `TelemetryExportError` | A saved target outcome lacks required trace acknowledgement. Exposes `execution_id`; a new empty exporter cannot prove prior receipt. |

Use one checkpoint directory per experiment or rescore run. Checkpoint files contain allowed result content and are private local files, not encrypted storage. Resume an upload failure with the same run, directory and options so saved payloads and idempotency keys are reused. After a process crash, confirm its recorded owner has stopped before removing `.lock`; removing the lock never authorizes another target invocation.

For uncertain work, investigate side effects before starting another attempt. The low-level `start_execution` method requires the latest `previous_execution_id` for a replacement attempt and `allow_uncertain_retry=True` to replace a still-started attempt. Restarting a runner does not grant either permission or automatically adopt an externally created attempt. Use a new experiment for an intentional fresh target run after investigating.

Required evidence waits for both signals after the root span ends. Omission is an explicit policy, never an automatic fallback after export failure. For a runnable example, see the public [first evaluation guide](/evaluations/first-evaluation).

## Environment client

```python
import os

from hue_sdk.environment import EnvironmentClient

environments = EnvironmentClient(api_key=os.environ["HUE_API_KEY"])
```

`hue_sdk.environment` is a synchronous client for Hue's simulated worlds. Pass a **Read and write** project service key as `api_key=`; `base_url` defaults to Hue Cloud, and a bare key in the first position raises `TypeError`. `timeout_seconds` (default `10`) bounds each request and `max_attempts` (default `4`, integer `1–10`) bounds retries. It creates, drives, seals and reads worlds of published environment versions; it does not publish environments, bind tools or run your agent. `run_simulation` has no Python counterpart.

| Method | Result or purpose |
| --- | --- |
| `create_run(*, idempotency_key, environment_version_id, execution_id=None, seed=None, max_steps=None, ttl_seconds=None, traceparent=None, agent_revision=None)` | `EnvironmentRun`. Creates or replays one fresh isolated world. `traceparent` is the case span's version-00 W3C trace context, whose trace ID must be the trace the execution declared; `agent_revision` (1–256 characters) joins the world's fingerprint. |
| `get_run(run_id)` | `RunState`, the current or sealed world. Missing coverage fields read as `validity: "not_assessed"` and `coverageGap: None`. |
| `act(run_id, *, invocation_id, action, args=None)` | `ActionResult`. Repeat the same UUID invocation ID and arguments to replay a recorded result. |
| `list_steps(run_id, *, after=None, limit=None)` | `StepPage`. Pages the journal by step ordinal; `limit` is 1–100. |
| `finish_run(run_id, *, idempotency_key, status)` | `SealedRun`. Seals the world as `"completed"` or `"abandoned"`. |
| `record_coverage_gap(run_id, *, idempotency_key, provider, operation, code, args, description)` | `CoverageGapResult`. Records a known coverage gap; `idempotency_key` is a UUID and `args` at most 16,000 JSON bytes. |
| `get_evidence(run_id, *, section="all", bodies=True)` | A dictionary with the sealed world's evaluator-only evidence. `section` is `"all"`, `"start"`, `"end"`, `"diff"` or `"ledger"`; `bodies` includes ledger request and response bodies. |

Responses are typed dictionaries that keep the API's camelCase keys, with the same fields as the [TypeScript types](/reference/typescript#runs-actions-and-journals): `EnvironmentRun`, `RunState`, `ActionResult`, `ActionDefinition`, `ActionParameter`, `ActionSchema`, `Observation` (`OkObservation` or `ErrorObservation`), `Effect`, `Step`, `StepPage`, `SealedRun`, `CoverageGap`, `CoverageGapReporter`, `CoverageGapResult` and `EnvironmentCoverage`. `Json`, `RunStatus` and `FinishStatus` are the matching aliases.

Unlike `EvaluationClient`, this client retries every call, including mutations, because each carries an identity Hue deduplicates. It retries transport failures and HTTP 408, 429, 500, 502, 503 and 504 with backoff, and waits Hue's `Retry-After` on 429 and 503, at most 10 seconds. Failures raise `HueEnvironmentError`, whose message never includes response text or credentials; `status` is the HTTP status or `None`, and `retry_after` is the bounded wait in seconds. Responses are limited to 4 MiB and request bodies to 1 MiB.

### World handoff

Where Hue's simulation gateway serves a world, `create_run` also returns its handoff: a world token, one mirror URL per pinned provider surface, environment variables and an MCP configuration. Hand these to the agent instead of the project key. Hue Cloud does not serve gateway worlds yet, so today `world_handoff` returns `None` and `get_evidence` fails with `HueEnvironmentError` status `404`.

```python
import subprocess

from hue_sdk.environment import agent_environment, mcp_config_file, world_handoff

run = environments.create_run(
    idempotency_key=f"execution:{execution_id}",
    environment_version_id=version_id,
    execution_id=execution_id,
    traceparent=f"00-{trace_id}-{span_id}-01",
    agent_revision="my-agent@1.4.2",
)
status = "abandoned"
try:
    world = world_handoff(run)  # None when the world has no handoff
    if world is None:
        raise RuntimeError("This deployment does not serve gateway worlds.")
    with mcp_config_file(world) as path:  # removed after the block
        child = {**agent_environment(world), "MCP_CONFIG": path}
        subprocess.run(agent_command, env=child, check=True)
    status = "completed"
finally:
    # Seal a failed or unrun attempt as abandoned, never as completed.
    environments.finish_run(
        run["id"], idempotency_key=f"execution:{execution_id}:{status}", status=status
    )
```

| Function | Behavior |
| --- | --- |
| `world_handoff(run)` | The `WorldHandoff` of a create or replay response, or `None` for a world without one. |
| `agent_environment(world, *, parent=None, include_hue_credentials=False, legacy_mcp_variables=True)` | Environment variables for the agent's child process: `parent` (default `os.environ`) without Hue control-plane credentials, then the world's `env`, which wins. `legacy_mcp_variables` also sets `HUE_MCP_URL`, `HUE_MCP_TOKEN` and `HUE_MCP_EXPIRES_AT` from the first MCP mirror. |
| `mcp_config_file(world, *, directory=None)` | Context manager that writes `mcpConfig` to an owner-only `mcp.json` in a private directory, yields its path and removes the directory afterwards. |
| `legacy_mcp_capability(world)` | `LegacyMcpCapability`, `{"url", "token", "expiresAt"}` for the first MCP mirror, or `None` without an MCP surface. |
| `strip_hue_control_plane_credentials(parent)` | A copy of `parent` without Hue control-plane credentials. |
| `is_hue_control_plane_credential(name, value)` | `True` for a name in `HUE_CONTROL_PLANE_VARIABLES` (`HUE_API_KEY`, `HUE_MCP_KEY`, `HUE_PROJECT_KEY`, `HUE_SERVICE_KEY`) or a value that starts with `hue_sk_`, `hue_mcp_` or `hue_attempt_`. |

`WorldHandoff` has `id`, `token` (a `hue_world_` credential that lives as long as the world), `expiresAt`, `lifecycle` (`WorldLifecycle`: `pending`, `live`, `completing` or `sealed`), `completingUntil`, `traceparent`, `baggage`, `surfaces` (`WorldSurface` entries with `provider`, `surface`, `providerInstanceKey`, `url` and `alias`), `env` (`HUE_WORLD_ID`, `HUE_WORLD_TOKEN`, `BAGGAGE`, `TRACEPARENT` and one `HUE_SIM_<SURFACE ID>_URL` per surface) and `mcpConfig` (`WorldMcpConfig`, the common `mcpServers` shape of `WorldMcpServer` entries with the token as a bearer). `RunState` of a gateway world adds advisory `flags` (`WorldFlag`: `no_calls` or `fingerprint_differs`) and never returns the token; `WorldEvidenceSection` names the evidence sections.

Finishing a gateway world answers `lifecycle: "completing"` with `sealedAt: None`; the seal follows a 5-second grace. `get_evidence` needs the project key, and an open world answers `409` until it is sealed. Nothing in these helpers logs the token. Keep the handoff out of your own logs and checkpoints.

## Managed target adapter

`ManagedTargetHandler` from `hue_sdk.managed` requires `machine_credential`, a synchronous `target` callback and `flush_telemetry`. Optional arguments are `tracer`, `base_url`, `max_execution_millis` (default 90000, at most 90000) and `finalization_millis` (default 30000, at most 30000). Pass `tracer=hue.tracer` with a Hue-owned client; without it the handler falls back to the global tracer, its span is not recorded and every invocation returns `uncertain`.

`handle(payload, headers)` accepts bounded raw JSON bytes or a dictionary and returns `ManagedResponse` with `status_code`, `body` and `headers`. The target receives a `ManagedTargetContext` with `execution_id`, `attempt`, `input`, `config`, `input_files`, the `cancelled` event, `deadline_monotonic` and `trace_id`; `input_files` is a tuple of `ManagedInputFile` entries with `artifact_id`, `filename`, `content_type`, `byte_size`, `sha256`, `role` and the verified `data` bytes. It returns `ManagedTargetResult`; generated files use `ManagedOutputFile`. Calls use the existing tracing providers. A false flush result leaves telemetry pending. See [managed runs](/evaluations/managed-runs) for framework integration, cancellation and recovery.

## Safe serving lifecycle

Import `create_hue_safe` from `hue_sdk`. It accepts the same constructor arguments as `Hue`, catches ordinary initialization failures and returns a disabled client with an instrumentation failure. `enabled=False` needs no API key and does not attach to a supplied provider. Initialize once per serving process after fork; inherited clients no-op instead of reusing parent worker locks.

`force_flush_safe(timeout_millis=1000)` and `shutdown_safe(timeout_millis=1000)` return booleans without raising. Observe `export_status`; it includes `instrumentation_failures`, `dropped_trace_records`, `dropped_log_records`, `queued_trace_records`, `queued_log_records`, `queued_trace_bytes` and `queued_log_bytes`. Queued counts include in-flight records; health is cumulative.

Constructor options `max_queue_size=2048` and `max_queue_bytes=8388608` bound each signal's retained telemetry. Encoded bytes are not total process RSS. HTTP acknowledgements are capped at 64 KiB; 429 and Retry-After are honored within the transport budget. One retained network worker per signal bounds blocked network work, although Python cannot forcibly cancel every blocked system call. After a request timeout, that worker may retain up to 1 MiB of encoded request data per signal outside queue counters. Later batches stay queued within their limits until transport recovery; shutdown counts any queued records it must discard. See [production safety](/guides/production-safety).
