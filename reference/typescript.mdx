## Create a tracing client

```ts
import { createHue } from "@hue-run/sdk";

const hue = createHue({
  apiKey: process.env.HUE_API_KEY!, // Read the key from server configuration.
  serviceName: "my-agent",
  captureContent: true, // Record supported input/output content.
});
```

`createHue(options: HueOptions | ExistingHueProviders): HueClient` and `new HueClient(options)` accept the same configuration. `HueOptions` is `SharedHueOptions`, the options every client and transport accepts, plus `enabled`, `apiKey` and `serviceName`.

### HueOptions

| Option | Type | Default and behavior |
| --- | --- | --- |
| `apiKey` | `string` | Required when enabled; ignored for `enabled: false`. Use **Tracing only** for tracing and known-trace receipts; use **Read and write** when this process also calls evaluation APIs. Keep it in server-only configuration. |
| `serviceName` | `string` | Required when enabled; 1–256 characters with non-whitespace content. Sets `service.name` on providers created by Hue. |
| `enabled` | `boolean` | `true`; `false` creates a disabled client without attaching processors or requiring a key. |
| `captureContent` | `boolean` | Required explicit choice for an enabled client; there is no default. `true`, the recommended setting, records supported content; `false` sends metadata only. See [content policy](#content-policy). A disabled client defaults it to `false`. |
| `baseUrl` | `string` | `https://app.hue.run`. Supply an origin, without an API path, query, fragment or credentials. HTTPS is required except for loopback HTTP. |
| `allowInsecureHttp` | `boolean` | `false`. `true` permits `http://` to hosts other than loopback, for example a docker-compose or in-cluster collector, and records a one-time `warning` issue because the key then travels unencrypted. |
| `serviceVersion` | `string` | Optional `service.version` on providers created by Hue. |
| `resourceAttributes` | `Attributes` | Optional additional resource attributes for an owned client, for example `deployment.environment.name` or `service.namespace`; `serviceName` and `serviceVersion` take precedence over same-named keys. Ignored with a `warning` issue in attach mode. |
| `maxQueueBytes` | `number` | `8388608`; 1024–67108864. Shared estimated trace/log queue bytes, including in-flight work. Not total process RSS. |
| `timeoutMillis` | `number` | `10000`; integer from `100` through `60000`. Configures transport requests and the project connection check; it is not an overall `flush()` deadline. |
| `liveSpans` | `boolean` | `true`. Sends placeholders for open Hue and AI spans. A span still open when its placeholder is exported, usually about 1.5 s after it starts, shows as running. Setup credentials never send placeholders. See [live spans](#live-spans). |
| `redact` | `(value: string, path: string) => string` | Optional string transformation on Hue's export path. See [content policy](#content-policy). |
| `onExportIssue` | `(issue: ExportIssue) => void \| Promise<void>` | Optional callback for sanitized export diagnostics, called at most once per second. |

Invalid configuration throws `TypeError`. Environment variables are read by your application and passed to the client; these constructors do not automatically load an environment file, and `OTEL_EXPORTER_OTLP_*` variables do not reach Hue's exporters. Owned providers export the OpenTelemetry default resource (`telemetry.sdk.language`, `telemetry.sdk.name`, `telemetry.sdk.version`) beside `service.name`, `service.version` and `resourceAttributes`. Export requests carry a `hue-sdk-typescript/<version>` User-Agent.

### ExistingHueProviders

Use `createHueTransport(options: HueOptions): HueTransport` when your application owns OpenTelemetry setup. Attach its `spanProcessor` and `logRecordProcessor` during provider construction, then pass:

```ts
createHue({ transport, tracerProvider, loggerProvider });
```

`tracerProvider` is a `FlushableTracerProvider` and `loggerProvider` a `FlushableLoggerProvider`: the OpenTelemetry API provider types plus `forceFlush(): Promise<void>`, which the OpenTelemetry SDK providers satisfy. Your application owns their resources, registration and shutdown; `resourceAttributes` is ignored with a warning issue in this mode. Hue never replaces the global tracer provider, logger provider or context manager. See the complete [existing-provider recipe](/integrations/opentelemetry).

## Trace application work

The signatures below use types exported by `@hue-run/sdk` and standard OpenTelemetry types.

```ts
hue.withSpan<T>(
  name: string,
  callback: (span: HueSpan) => T | Promise<T>,
  options?: SpanOptions,
): Promise<T>

hue.tool<T>(
  name: string,
  input: unknown,
  execute: () => T | Promise<T>,
  options?: ToolOptions,
): Promise<T>

hue.model<T>(
  model: string,
  callback: (span: HueSpan) => T | Promise<T>,
  options: ModelOptions,
): Promise<T>

hue.getContext(): Context
hue.inject(carrier: Record<string, string>, activeContext?: Context): void
hue.extract(carrier: Record<string, string | string[] | undefined>): Context
hue.recordError(span: Span, error: unknown): void
hue.recordMessages(
  messages: {
    input?: unknown;
    output?: unknown;
    systemInstructions?: unknown;
    operation?: string;
    provider?: string;
    model?: string;
  },
  explicitContext?: Context,
): void
hue.recordProviderToolCalls(response: unknown, options?: ProviderToolCallOptions): void
hue.recordFile(file: FileRecord, explicitContext?: Context): void
```

`withSpan` returns the callback's result, ends the span after the callback settles, and records then rethrows an escaping application error. Consume streams inside the callback if their work belongs to that span. A returned streaming `Response` is not evidence that the stream has finished.

`tool` runs `execute` inside a span named `execute_tool {name}` with `gen_ai.tool.name`, records `input` and a defined result as `gen_ai.tool.call.arguments` / `gen_ai.tool.call.result` according to your content policy, and returns the tool result. An `undefined` result omits result content. `options.parentContext` supplies an explicit parent for the tool span. `ToolOptions` extends `Pick<SpanOptions, "parentContext">` with `callId`, the provider-issued tool-call id recorded as `gen_ai.tool.call.id`, and `mcp`, an `McpServerInfo` (the MCP `initialize` `serverInfo`, passed as `client.getServerVersion()` after connect) recorded as `mcp.server.name` / `mcp.server.version` so a generic tool name is attributed to the server that handled the call. When the server is a Hue surface, `McpServerInfo` also takes `provider` and `surface` (for example `google.gmail` and `google.gmail/mcp`), recorded as `hue.mcp.provider` / `hue.mcp.surface`. A blank, over-256-character or otherwise invalid label is omitted and counted as an instrumentation failure; the tool still runs.

`model` runs `callback` inside a GenAI client span for one direct provider call, named `{operation} {model}` unless `options.name` is given, with `gen_ai.operation.name`, `gen_ai.request.model` and `gen_ai.provider.name`. The argument order matches `withSpan`. Inside it, the handle's `setInput` and `setOutput` record `gen_ai.input.messages` / `gen_ai.output.messages`, which should use the GenAI semantic-convention message shape; `recordMessages` inside the callback inherits the request metadata. When you send system instructions or tools separately from the messages, pass them as `systemInstructions` and `tools` in [ModelOptions](#modeloptions).

Content helpers (`setInput`, `setOutput`, `tool` arguments and results, `recordMessages` and `SpanOptions.input`) accept `unknown` and encode plain JSON data (`JsonValue`) at runtime. A value that is not JSON, such as a `Date` or a class instance, is omitted with an instrumentation failure while the callback result is returned unchanged.

`recordMessages` emits a correlated `gen_ai.client.inference.operation.details` log record with the messages, and optional `systemInstructions` as `gen_ai.system_instructions`, in its body. `gen_ai.operation.name`, `gen_ai.provider.name` and `gen_ai.request.model` are set as record attributes from the caller's `operation`, `provider` and `model` or from the enclosing `model()` span, and `gen_ai.conversation.id` from the active session. With content capture enabled, it requires an active span or explicit span context. With capture disabled, it emits nothing. Use logs or span attributes for the same content event to avoid storing duplicate copies.

`recordError` marks a span failed the way every helper does: `error.type` (the error's `name`), an ERROR status without a description and an `exception` event carrying only `exception.type`. Exception messages and stack traces are never recorded, whatever `captureContent` is.

`inject` writes W3C `traceparent` for the active span into a carrier, never the API key or baggage, and also propagates when the client is disabled or closed. `extract` reads W3C trace context from a carrier for use as `parentContext`. Hue registers no global propagator.

### SpanOptions and context

| Option | Default and behavior |
| --- | --- |
| `kind?: SpanKind` | `SpanKind.INTERNAL`. |
| `attributes?: Attributes` | Additional OpenTelemetry attributes; arbitrary names and values are caller-owned. |
| `input?: unknown` | Optional root input, recorded as `input.value`. Omitted when content capture is disabled. |
| `sessionId?: string` | Inherits from the surrounding Hue callback; maps to `gen_ai.conversation.id`. |
| `userId?: string` | Inherits from the surrounding Hue callback; maps to `user.id`. This is your application identity, not a Hue account. |
| `workspaceId?: string` | Inherits from the surrounding Hue callback; maps to `hue.workspace.id`. The workspace or tenant in your application that the work runs in. |
| `parentContext?: Context` | Explicit parent, for example from `hue.extract()`; otherwise the surrounding Hue context or active OpenTelemetry context. |

Session, user and workspace identifiers must contain 1–4096 valid characters. `hue.tracer` is an OpenTelemetry tracer that preserves Hue's local async context; spans other instrumentations create through it parent under `withSpan` and inherit identifiers. `hue.getContext()` supplies the helper's current context to an integration that accepts an explicit parent. When your application has registered a context manager, `withSpan`, `tool`, `model` and `hue.tracer.startActiveSpan` also make their span the active OpenTelemetry span while the callback runs; Hue registers none itself.

### ModelOptions

`ModelOptions` extends the `sessionId`, `userId`, `workspaceId`, `input` and `parentContext` members of `SpanOptions`.

| Option | Behavior |
| --- | --- |
| `provider: string` | Required. Recorded as `gen_ai.provider.name`, for example `"openai"`. |
| `operation?: string` | Recorded as `gen_ai.operation.name`; defaults to `"chat"`. |
| `name?: string` | Span name; defaults to `"{operation} {model}"`. |
| `input?: unknown` | Recorded as `gen_ai.input.messages` when `captureContent` is true. |
| `systemInstructions?: unknown` | System instructions sent separately from the messages, for example `[{ type: "text", content: instructions }]`. Recorded as `gen_ai.system_instructions` when `captureContent` is true. |
| `tools?: unknown` | Tool definitions offered to the model, for example `[{ type: "function", name, description, parameters }]`. Recorded as `gen_ai.tool.definitions` when `captureContent` is true, after [credential scrubbing](#content-policy). |

Labels must be non-empty strings of at most 256 characters; other values fall back to `"unknown"` or `"chat"` and count as instrumentation failures.

### HueSpan

The callback receives `span` (the underlying OpenTelemetry span), `context`, `traceId`, `spanId`, `setInput(value: unknown)`, `setOutput(value: unknown)` and `setUsage(usage: TokenUsage)`. Inside `model()`, `setInput` and `setOutput` record `gen_ai.input.messages` and `gen_ai.output.messages`; elsewhere they record `input.value` and `output.value`. `TokenUsage` is `{ inputTokens?: number; outputTokens?: number }`, recorded as `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens`; invalid values are omitted and counted as instrumentation failures. IDs are all zeros for a disabled client.

Use `span.setAttribute(...)`, `span.addEvent(...)` and the other standard OpenTelemetry APIs for additional metadata. Hue does not estimate absent token counts or cost. Captured JSON `null`, `false`, `0` and `""` remain present values; they are distinct from an omitted field. Helper content must serialize as JSON and fit within 256 KiB per field.

### Provider-executed tools

Tools the provider runs itself, such as OpenAI hosted MCP, web search, file search and code interpreter, or Anthropic's MCP connector and server tools, never pass through `hue.tool()`. Inside the same `model()` callback, hand the response to `recordProviderToolCalls`:

```ts
await hue.model(
  "gpt-5-mini",
  async (span) => {
    const response = await openai.responses.create(request);
    span.setOutput(response.output_text);
    hue.recordProviderToolCalls(response, { request });
    return response;
  },
  { provider: "openai" },
);
```

Each OpenAI Responses `mcp_call`, `web_search_call`, `file_search_call` or `code_interpreter_call` item, and each Anthropic `mcp_tool_use` or `server_tool_use` block with its result, becomes an `execute_tool {name}` child span with `gen_ai.tool.type` `extension`, `gen_ai.tool.call.id` and, for MCP calls, `mcp.server.name` (the provider's label). Arguments and results follow `captureContent`; a failed call carries `error.type` (`mcp_error`, or the provider's status or error code) and an ERROR status. An OpenAI `mcp_list_tools` item becomes a `tools/list` child span with that server's `gen_ai.tool.definitions`. The spans have no duration of their own: the provider ran the tools inside the model request. Unreadable items are skipped and counted as instrumentation failures; nothing is thrown.

`ProviderToolCallOptions` extends `Pick<SpanOptions, "parentContext">`:

| Option | Behavior |
| --- | --- |
| `provider?: HostedToolProvider` | `"openai"` (Responses API) or `"anthropic"` (Messages API). Defaults to the enclosing `model()` call's provider when it is one of these. |
| `request?: unknown` | The request the response answers. Only hosted MCP server URLs are read from it, never credentials, to record each server's host as `server.address`. |
| `servers?: Record<string, HostedServerInfo>` | Identity of each hosted MCP server, keyed by the label the provider uses for it. `HostedServerInfo` has `name` (recorded as `mcp.server.name`, defaulting to the label), `version`, and the Hue `provider` and `surface`. |

### Files

`recordFile` adds a `hue.file` event to the active span, or to the span of an explicit context passed second, for a file the work read, received or produced. Files are linked by content hash, so a trace can be matched to the same file elsewhere without exporting its bytes:

```ts
import { readFile } from "node:fs/promises";

await hue.withSpan("review contract", async () => {
  const pdf = await readFile("contract.pdf");
  hue.recordFile({ role: "input", mediaType: "application/pdf", data: pdf, name: "contract.pdf" });
  // ...
});
```

A `FileRecord` has `role` (`"input"` given to the agent, `"attachment"` from a tool or message, or `"output"` produced by the agent), `mediaType`, and either `data` (a `Uint8Array`, or a string hashed as UTF-8) or `sha256`, with optional `byteSize` and `name`. `data` up to 25 MiB is hashed and measured locally and never exported; larger data is omitted and counted as an instrumentation failure, so pass `sha256` and `byteSize` when you already have them. A supplied `sha256` or `byteSize` must match `data`.

The event carries `hue.file.sha256`, `hue.file.role`, `hue.file.media_type` and, when known, `hue.file.size`. It is metadata, so it is recorded in both capture modes; `hue.file.name` is recorded only when `captureContent` is true. An invalid record, or one without an active span, is omitted and counted as an instrumentation failure.

## Vercel AI SDK adapter

```ts
import { hueTelemetry } from "@hue-run/sdk/ai-sdk";

// Pass to an AI SDK 7 agent or generation call:
const telemetry = hueTelemetry(hue);
```

`hueTelemetry(hue: HueClient): TelemetryOptions` enables telemetry, sets `recordInputs` and `recordOutputs` from `hue.captureContent`, and configures the AI SDK OpenTelemetry integration with `hue.tracer` and usage reporting.

Supported peer ranges are `ai@^7.0.99` and `@ai-sdk/otel@^1.0.99`. Installed-package tests cover pairs `7.0.99 / 1.0.99` and `7.0.100 / 1.0.100`; every later compatible release is not individually verified.

`hueTelemetry` reads the installed `ai` major version once per process and throws a `TypeError` below 7. For AI SDK 6, use `hueExperimentalTelemetry` from the core entry point instead:

```ts
import { hueExperimentalTelemetry } from "@hue-run/sdk";

const result = await generateText({
  model,
  prompt,
  experimental_telemetry: hueExperimentalTelemetry(hue),
});
```

`hueExperimentalTelemetry(hue: HueClient): ExperimentalTelemetrySettings` returns `{ isEnabled, recordInputs, recordOutputs, tracer }`: `isEnabled` mirrors the client's `enabled` flag, the record flags mirror `captureContent`, and `tracer` is Hue's tracer, so AI SDK 6 spans parent under `withSpan` and inherit identifiers. It needs no `@ai-sdk/otel` peer. Do not upgrade an existing app's AI SDK just to install Hue. For an app that already emits OpenTelemetry spans, assess the [existing-provider path](/integrations/opentelemetry) and its installed OpenTelemetry versions using the [compatibility guide](/sdks/compatibility).

Provider-executed tools, such as OpenAI hosted MCP (`openai.tools.mcp`), appear as `execute_tool mcp.<name>` spans with `gen_ai.tool.type` `extension`. The server is named only by `serverLabel` inside the recorded result, so before export the SDK copies it to `mcp.server.name`, and a result carrying an MCP `error` sets an ERROR status and `error.type` `mcp_error`. Both attributes survive metadata-only export. The label can only be read when AI SDK recorded the result: `hueTelemetry(hue)` with `captureContent: false` records none, whereas an application whose AI SDK integration records outputs and exports through Hue's attached processors keeps the label.

AI SDK per-call integrations replace the global integrations for that call. If your app already has telemetry, preserve its setup and attach Hue to the existing provider. See [OpenTelemetry](/integrations/opentelemetry) and the [reference chatbot](/integrations/reference-chatbot).

## Content policy

- `captureContent: false` disables Hue helper content and removes recognized GenAI, Vercel AI SDK, OpenInference and OpenLLMetry content, legacy GenAI content events, log bodies, status messages and exception text before Hue exports records, including records from other instrumentations on a shared provider. The exported `contentPrefixes` array lists the attribute keys, and their dotted children, that are removed; the [compatibility matrix](/sdks/compatibility) reproduces it. It does not classify every custom attribute name.
- `captureContent: true` permits supplied content. Received content is stored by Hue; the SDK does not set a retention timer. Helpers still omit exception messages and stack traces.
- With `captureContent: false`, a record whose tool definitions are removed keeps a summary of them: `hue.tool.names` lists each definition's `name` (Chat Completions `function.name`, or the `type` of an unnamed built-in tool such as `mcp`) in order, and `hue.tool.definitions.sha256` is the lowercase hex SHA-256 of the [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785) canonical JSON of the credential-scrubbed definition list. The digest does not change when a credential rotates. Only definitions another integration recorded can be summarized: `hueTelemetry(hue)` with `captureContent: false` records none.
- Hosted tools carry credentials in their definitions, such as the `authorization` and `headers` of an OpenAI hosted MCP tool. Before export, and before `redact`, Hue replaces the values of credential-like fields (`authorization`, `authorization_token`, `headers`, `api_key`, `access_token`, `x-api-key`, and keys ending in `token`, `secret`, `password`, `apikey` or `credential`, case-insensitively and ignoring `-` and `_`) with `"[redacted]"` in `gen_ai.tool.definitions`, `ai.prompt.tools` and `llm.tools.*.tool.json_schema`, and in the `tools` and `mcp_servers` entries of a raw provider request or response recorded as `input.value`, `output.value` or `llm.invocation_parameters`. Parameters named in a JSON Schema `properties` object keep their schemas, so a tool that takes a `headers` argument is still described. A definition nested more than 256 levels deep rejects its record.
- A `blob` part in `gen_ai.input.messages` / `gen_ai.output.messages` or a `file` part in `ai.prompt.messages` whose inline content is longer than 64 KiB is exported without its payload: Hue replaces its `content` or `data` with the file's `sha256` (of the decoded bytes for base64 and `data:` URLs, of the UTF-8 text otherwise) and `size`, and keeps the part's other fields. The digest matches `hue.file.sha256` from [`recordFile`](#files) for the same bytes. Smaller inline files are exported as recorded.
- `redact(value, path)` transforms supported strings in attributes, resources, event/link attributes and log bodies before Hue exports them. It must return a string. A redactor failure rejects the affected record and becomes an export issue.
- This policy applies to Hue's export path. Another exporter and arbitrary span/scope names remain your application's responsibility.

## Flush, shutdown and diagnostics

```ts
hue.checkConnection(): Promise<ProjectConnection>
hue.flush(): Promise<ExportReport>
hue.shutdown(): Promise<ExportReport>

hue.transport.getReport(): ExportReport
hue.transport.getIssues(): ExportIssue[]
hue.transport.getFailureSequence(): number
```

`checkConnection()` returns a `ProjectConnection`, `{ id, name, organizationId, slug }`, for the project associated with the key. It throws `HueConnectionError` on rejected authentication, network failure or an invalid response; `status` carries the HTTP status when Hue answered, and `cause` carries the underlying network, timeout or parsing error. Its message is fixed and safe to log. It sends no trace.

`flush()` drains traces and logs. Concurrent callers receive serialized drains that include their preceding emissions. Rejections, failed exports, queue drops and invalid acknowledgements throw `HueExportError`, whose `issues` and `report` contain sanitized diagnostics. A later non-overlapping flush reports new failures; counters remain cumulative. Overlapping calls also observe failures from shared in-flight work.

`ExportReport` contains `acceptedSpans`, `acceptedLogs`, `rejectedSpans`, `rejectedLogs`, `failedSpans`, `failedLogs`, `pendingSpans`, `pendingLogs`, `droppedSpans`, `droppedLogs`, `pendingBytes` and `instrumentationFailures`. Accepted, rejected, failed, dropped and instrumentation counts are cumulative; pending counts and bytes describe current queued/in-flight records. `getIssues()` returns the latest 128 `ExportIssue` values with `sequence`, `signal` (a `Signal`: `"traces"` or `"logs"`), `kind`, `count`, optional `status` and a sanitized `message`. Kinds are `rejected`, `failed`, `dropped`, `invalid` and `warning`. A warning with no rejection does not fail a flush.

The transport's `spanProcessor` and `logRecordProcessor` receive `RecordValue` records, the `ReadableSpan` or `ReadableLogRecord` the OpenTelemetry SDK hands to a processor. The exporter plumbing behind them is internal and not part of the published declarations; read `getReport()`, `getIssues()` and `getFailureSequence()` instead.

`shutdown()` stops new Hue helpers and flushes. It closes providers that Hue created; borrowed providers remain usable. Repeated calls share the same shutdown promise. If your application supplied the providers, close those providers and then call `transport.shutdown()` during process shutdown. Reuse a shared client across server requests.

Queues are in memory and bounded to 2,048 records per signal, including exports in flight. Export requests are sized from each record's own encoding and split at 1 MiB. Retryable failures use the OpenTelemetry retry policy; partial rejections are not retried wholesale. An acknowledgement means collector receipt, not that every span of a distributed trace has arrived. Stop producing spans before shutdown.

## Live spans

OpenTelemetry exports a span only when it ends, so a long streamed turn would otherwise stay invisible until it finishes. When a Hue or AI span is still open at the transport's next 500 ms tick, the transport queues a placeholder: an ordinary OTLP span whose parent is the running span, with its name, kind, start time and current attributes and an end time of 0. Hue shows the span, and its trace, as running and replaces the placeholder when the finished span arrives. A placeholder whose span has ended by the time it is exported is not sent.

A placeholder usually reaches Hue about 1.5 s after its span starts: up to 500 ms until the next tick, then about 1 s while the export queue batches it. It arrives sooner when a batch is already scheduled and later while an earlier export is still in flight, because the next 1 s batch is scheduled only after that export finishes. A span shorter than about 1.5 s therefore usually never shows as running and appears only when it ends.

- Only spans from the client's tracer (`withSpan`, `tool`, `model`, `hue.tracer` and the AI SDK adapters) and spans with a `gen_ai.`, `ai.`, `llm.` or `traceloop.` attribute at start, or a name starting with `ai.`, are announced. HTTP, database and other framework spans are not.
- Placeholder attributes follow `captureContent` and `redact` like the finished span. Tool definitions, system instructions and any value over 64 KiB are left out.
- A span processor that scrubs, renames or drops spans in `onEnd` never sees placeholders: the transport builds each one from the running span's current name and attributes. If a wrapper forwards `onStart` to Hue and the span is still open when its placeholder is exported, Hue receives the span's original name and its attributes after `redact`, even when the wrapper later edits, renames or drops the finished span. Remove sensitive attribute values with `redact` or where you record them. `redact` does not change span names, so keep a sensitive value out of the name where you create the span, or turn live spans off with `liveSpans: false`.
- Placeholders are advisory. They are queued only while the queue is under a quarter of its record and byte budgets, and skipped silently otherwise. While queued they count in `pendingSpans` and `pendingBytes`, but never as accepted, rejected, failed or dropped records. Losing only placeholders records a `warning` issue and does not make `flush()` throw.
- A receiver that does not accept placeholders, such as a generic collector, rejects them only in the first export that carries them. The transport then records one `warning` issue and stops sending placeholders for that client.
- Opt out with `liveSpans: false`.
- With an [existing provider](/integrations/opentelemetry), announcements start in `spanProcessor.onStart`. A wrapping processor that forwards `onStart` should forward `onEnd` for the same spans; a placeholder already sent for a span that never reaches Hue keeps it showing as running until Hue marks the trace stalled.

## Trace verification

```ts
await hue.verifyTrace(traceId, {
  expectedSpanIds: [requestSpanId],
  requiredFields: ["model"],
  timeoutMillis: 10_000,
});
```

`verifyTrace(traceId: string, options?: VerifyTraceOptions): Promise<TraceVerification>`. `VerifyTraceOptions` has `expectedSpanIds`, `requiredFields` (an array of `TraceReceiptField`: `"input"`, `"output"`, `"model"`, `"usage"` or `"session"`) and `timeoutMillis`. `TraceVerification` is `{ verified: boolean; receipt: TraceReceipt | null }`. A receipt contains `traceId`, `spanCount`, `revision`, `fields` (`Record<TraceReceiptField, boolean>`), `matchedSpanIds`, `missingSpanIds`, and `traceUrl`. `verified` requires a stored receipt, every supplied expected span, and every required field. Timeout returns `verified: false` with the latest partial receipt, or `null` if none arrived. Other failures throw exported `HueTraceVerificationError`, with `code` and optional HTTP `status`, without response bodies or credentials. A disabled client rejects with `HueConnectionError`.

Trace IDs are 32 lowercase hexadecimal characters; expected span IDs are 16. All IDs must be nonzero. Supply at most 100 unique expected span IDs and unique required field names. The timeout defaults to 10,000 ms and must be positive, finite, and at most 60,000 ms. The receipt response is limited to 64 KiB.

Missing spans or required fields keep polling until the deadline. Only recognized trace-not-found responses, HTTP 429, and HTTP 503 are retried; connection failures, unsupported endpoints, redirects, and malformed responses raise a safe typed error. Verification reads stored normalized field presence across the trace, including supported correlated logs. It does not inspect values or prove that unlisted application operations were instrumented.

[Flush the owning providers before verification](/sdks/typescript#verify-stored-trace-evidence); this method never flushes implicitly.

## Evaluation client

```ts
import { createEvaluationClient } from "@hue-run/sdk/evals";

const client = createEvaluationClient({ apiKey: process.env.HUE_API_KEY! });
```

`createEvaluationClient(options: EvaluationClientOptions): EvaluationClient` and `new EvaluationClient(options)` accept required `apiKey`, optional `baseUrl` (default `https://app.hue.run`) and optional `timeoutMillis` (default `10000`, range `100–60000`). `checkConnection()` returns the key's project. Evaluation registry writes require a **Read and write** key.

Methods below return promises. `PageOptions` is `{ after?: string; limit?: number }`, with a supplied limit from 1 through 100. Paged responses are `Page<T>`, `{ items, nextCursor }`; pass a non-null cursor as the next `after`. IDs are UUIDs. `Identity` is `{ name, slug, description? }`. `listEvalSets`, `listEvaluators`, `listDatasets` and `listScorers` accept `RegistryPageOptions`, `PageOptions` plus `includeArchived?: boolean`, which includes archived identities so callers can diagnose slug conflicts explicitly.

Evaluation responses are limited to **4 MiB**. `listCases(versionId, page?)` includes case content, so a valid row limit can still produce an oversized response when cases are large. Request a smaller page, such as `{ limit: 1 }`, and follow `nextCursor`; the client does not automatically split or retry an oversized page. Request bodies are limited to 1 MiB.

## Run locally and rescore

```ts
runExperiment(options: RunExperimentOptions): Promise<RunnerReport>
rescore(options: RescoreOptions): Promise<RunnerReport>
```

Both functions are exported from `@hue-run/sdk/evals`.

| Option | Required/default |
| --- | --- |
| `client` | Required `EvaluationClient`. |
| `checkpointDirectory` | Required dedicated local directory for this run. Preserve it for upload recovery; keep it out of Git. |
| `persistResultContent` | Required boolean, independent of telemetry capture. |
| `scorers` | Optional array of bound `LocalScorer` definitions/callbacks. |
| `concurrency` | Default `1`; integer `1–64`. |
| `schemaTimeoutMillis` | Default `2000`; integer `100–60000`; applies to JSON Schema validation, not arbitrary callbacks. |
| `environmentEvidence` | Optional `"required"`: resolve sealed world evidence for local scoring and historical rescoring. `runSimulation` sets it. `"when_pinned"` skips the read for cases that pin no world while still requiring it for cases that do. |
| `filesDirectory` | Default `<checkpointDirectory>/files`. Holds verified input copies and generated files. |
| `deferUnboundLocalScorers` | Optional. Reports pinned `local_code` versions this process has no binding for in `deferredScorerVersionIds`, leaving them to another executor, instead of refusing the run. |

`runExperiment` additionally requires `hue`, `experimentId`, `traceEvidence` and `target(inputs, context)`, where `context` is a `RunExperimentTargetContext`. The target may return a JSON value, a `TargetResult` from `withFiles`, `undefined`, or a promise of any of these. Evidence must be `{ mode: "required" }` or `{ mode: "omit", reason: "..." }`. Telemetry and evaluation clients must use the same project and origin.

`rescore` additionally requires `runId` and has **no target callback**. Create its evaluation run from existing subject IDs first. Both return a `RunnerReport`, `{ runId, subjectIds, resultIds, deferredScorerVersionIds }`.

With `persistResultContent: false`, completions and checkpoints omit raw output, target error messages, scorer evidence and arbitrary explanations. Declared metric values remain stored, including text metrics. Already stored dataset inputs/references are independent of this setting. Historical scoring skips unavailable output; it does not rerun a target to reconstruct it.

### File-based cases

`RunExperimentTargetContext` is what the `runExperiment` target receives for one frozen case:

| Field | Meaning |
| --- | --- |
| `config` / `item` | Frozen experiment configuration, validated as JSON / the frozen `ExperimentCase`, cloned before invocation. |
| `span` | The `hue.experiment.case` `HueSpan` this attempt runs inside. |
| `executionId` | Identity of this attempt. Derive an environment run's idempotency key from it to keep a resumed upload bound to the same world. |
| `files` | `LocalFile` copies of the case's pinned input files meant for the agent, verified by byte count and SHA-256. Evaluator-only roles are withheld. |
| `outputDirectory` | A private scratch directory for this case. |

To save generated documents, return `withFiles(output, files)`: it takes a JSON output (or `undefined` when the target produced only files) and an `OutputFile[]`, and returns a `TargetResult` with readonly `output` and `files`. Generated files are uploaded regardless of `persistResultContent`, and local scorers receive every input and generated file in `ScoreContext.files` as `LocalFile` entries, generated ones with `role: "output"`. `rescore` downloads a subject's frozen `files` for code evaluators.

| --- | --- |

### Local scorer exports

| Export | Behavior |
| --- | --- |
| `builtins.exactMatch()` | Publishable typed JSON equality definition. |
| `builtins.includes(caseSensitive = true)` | Publishable string-inclusion definition. |
| `builtins.jsonSchema(schema: JsonValue)` | Publishable JSON Schema draft 2020-12 definition. |
| `defineLocalScorer({ source, entrypoint, metrics, score })` | Returns a `LocalScorer`; source is `string` or `Uint8Array`. |
| `sourceDigest(source: string \| Uint8Array)` | SHA-256 declaration for supplied source bytes/text. |
| `scoreLocally(version, context, { scorers?, schemaTimeoutMillis? }?)` | Computes `Promise<Score>` without uploading it. |

`@hue-run/sdk/evals` uses `zod`, an optional peer dependency (4.6.5 or later), for its bounded runtime contracts; install it when you use evaluations or simulations. JSON Schema scoring uses `ajv`, a separate optional peer dependency (8.17 or later) loaded inside a worker only when `builtins.jsonSchema` scores a case; without it that scorer reports `SchemaValidatorUnavailable`. The tracing core depends only on `@opentelemetry/*` packages.

`ScoreContext` contains `inputs`, `hasOutput`, `hasExpected`, optional `output`/`expected`, `metadata`, `executionState` and, when the runner requires environment evidence, `environment` (an `EnvironmentEvidence`). With environment evidence present, a `local_code` scorer runs even when no output is stored. When required evidence cannot be read, `local_code` results record an `EnvironmentEvidenceUnavailable` error; a world marked `environment_incomplete` produces a skipped result with the fixed explanation `Environment incomplete: provider behavior is not implemented.` A `Score` is `scored` with declared metrics and explanation/evidence, `error` with a typed error, or `skipped` with an explanation. A failed quality metric is still `scored`, with `passed: false`.

Custom callbacks run locally, without a general execution timeout or side-effect cancellation. The source digest is a caller declaration, not attestation of dependencies or closures. Hosted judge pins must be dispatched through judge jobs; `scoreLocally` does not execute them.

### Recovery errors

- `UncertainExecutionError` exposes `caseId` and optional `executionId`: no durable outcome is available, so the runner refuses to repeat potentially completed work.
- `OutcomeSerializationError` exposes `executionId`: the target returned, but its outcome could not be saved as JSON. The runner does not invoke it again.
- `TargetCancelledError` is thrown when cooperative caller cancellation stops target execution; the runner records the execution as `cancelled`.
- `TargetOutcomeUncertainError` exposes `executionId`: the target or its simulated world may have committed but acknowledgement is unavailable, so a resume will not invoke the target again.
- Required trace export failures surface through `HueExportError` or recovery checks. A new empty exporter cannot prove receipt of an earlier trace.

Use one checkpoint directory per experiment or rescore run. Checkpoint files contain allowed result content and are private local files, not encrypted storage. After an upload failure, resume with the same run, directory and options so saved payloads and idempotency keys are reused. If a process crashes, confirm its recorded owner has stopped before removing the directory's `.lock` file. Removing a lock never authorizes another target invocation.

When a target's outcome is uncertain, restarting the runner will not repeat it. Investigate side effects first. The low-level `startExecution` API requires an explicit `previousExecutionId` for a replacement attempt and `allowUncertainRetry: true` to replace a still-started attempt. The convenience runner does not automatically adopt an externally created attempt; use a new experiment for an intentional fresh target run. Required evidence never silently changes to omitted evidence after an export failure.

For a runnable experiment and historical rescore, see the public [first evaluation guide](/evaluations/first-evaluation).

### Wait for results and verdicts

Scorers that Hue executes grade after the runner returns, so a caller that wants per-case verdicts waits for them. These functions are exported from `@hue-run/sdk/evals`.

| Function | Behavior |
| --- | --- |
| `waitForResults(client, options: WaitForResultsOptions)` | Polls an evaluation run until every item has a terminal (`scored`, `error` or `skipped`) result for every listed scorer version, or the budget elapses → `VerdictResults`. A timeout or abort returns the partial state with `complete: false`. |
| `summarizeVerdicts(results, { experimentItems, scorerVersionIds?, subjects? })` | Groups results by experiment case, in `experimentItems` order → `VerdictSummary`. Pass `subjects` when items do not carry `execution.subjectId`; `scorerVersionIds` defaults to the versions seen in `results`. |
| `compareVerdicts(current, baseline)` | Diffs two `VerdictSummary` values by case key → `VerdictComparison`. |
| `collectExperimentVerdicts(client, options: CollectExperimentVerdictsOptions)` | Reads an experiment's pinned scorer versions, waits for its results and summarizes them per case → `ExperimentVerdicts`. |
| `metricPassed(metric)` | Whether one `Metric` passes: its explicit `passed`, otherwise a boolean `value`; any other value counts as passing. |

`VerdictClient` is the subset of `EvaluationClient` that `waitForResults` uses: `listEvaluationItems`, `listResults` and `getResult`. `collectExperimentVerdicts` also needs `getExperiment`, `listExperimentItems` and `getSubject`.

`WaitForResultsOptions` requires `runId` (for example `report.runId`) and `scorerVersionIds`. Optional fields are `subjectIds` (restrict the wait, for example to `report.subjectIds`; defaults to every item), `timeoutMillis` (overall budget, default `300000`; `0` reads once), `pollIntervalMillis` (default `2000`; integer `250–60000`) and `signal`. `CollectExperimentVerdictsOptions` takes the same optional fields with `experimentId` in place of `runId` and `scorerVersionIds`. Runs of more than 5,000 items throw `RangeError`.

| Type | Meaning |
| --- | --- |
| `VerdictResults` | `complete`, the waited-for `items` (`{ id, subjectId }`) and `results`, one `VerdictResult` per item and scorer version read so far. |
| `VerdictResult` | `id`, `itemId`, `subjectId`, `scorerVersionId`, `state`, `metrics` (empty unless scored), `explanation` and `error` (`null` when absent). |
| `CaseVerdict` | One row per case: `caseId`, `externalKey`, `subjectId` (`null` before completion), `state` (`passed`, `failed`, `error`, `skipped` or `pending`), `passed`, `metrics` tagged with their `scorerVersionId`, the persisted `explanations` of results that did not pass and the `errors` types. A case passes only when every pinned scorer scored it without a failing metric. |
| `VerdictSummary` | `cases` (`CaseVerdict[]`) and `totals`: counts of `cases`, `passed`, `failed`, `error`, `skipped` and `pending`. |
| `VerdictComparison` | `improvements`, `regressions`, `unchanged` and `cases`, one `{ externalKey, before, after, change }` per case key in either run; `before` and `after` are `missing` for a case absent from that run, and `change` is `improved`, `regressed` or `unchanged`. |
| `ExperimentVerdicts` | `experimentId`, `runId`, the pinned `scorerVersionIds`, the raw `results` and the per-case `summary`. |

## Run a local agent worker

```ts
runLocalAgent(options: RunLocalAgentOptions): Promise<void>
```

`runLocalAgent` starts an outbound-only worker for one fixed local TypeScript agent entry point. Hue chooses only the registered key and revision; no command or source is received from the cloud. The worker is exported from `@hue-run/sdk/evals` and uses the same provider-aware world lifecycle as `runSimulation`. A matching Hue API deployment is required. Official Gmail and Slack registrations remain inactive.

Register the process first with `registerLocalAgent(input: LocalAgentRegistration)`, which returns a `RegisteredLocalAgent`. The worker then claims queued runs as a `LocalAgentClaim`. Candidate callbacks receive a `LocalAgentTargetContext`: case identity and cloned task inputs only, not expected criteria, case metadata or environment pins. Like `SimulationTargetContext`, it carries an optional `world` and an optional `mcp`. The worker sends the registered `agent.revision` as the agent revision of every world it creates.

### RunLocalAgentOptions

| Option | Required/default |
| --- | --- |
| `client` | Required `EvaluationClient` for the worker project. |
| `environmentClient` | Required `EnvironmentClient` for the same Hue origin and project. |
| `hue` | Required `HueClient` used for target and tool spans. |
| `checkpointDirectory` | Required private directory for worker identity and execution checkpoints. |
| `agent` | Required `LocalAgentRegistration`: `key`, `name`, `revision`, optional `capabilities` and `scorerDigests`. |
| `target(inputs, tools, context)` | Runs cases pinned to a hosted world (`environment:v1`). Invokes the existing local agent with isolated `EnvironmentTool`s and a `LocalAgentTargetContext`. Supply `target`, `directTarget` or both. |
| `directTarget(inputs, context)` | Runs ordinary cases without a world (`direct:v1`) with a `LocalAgentDirectContext`; returns a JSON value, a `TargetResult` from `withFiles`, `undefined` or a promise of any of these. |
| `scorers` | Optional `LocalScorer[]` matching published source digests. |
| `concurrency` | Default `1`; integer `1–64`. |
| `pollIntervalMillis` | Default `2000`; integer `250–60000`. |
| `signal` | Optional `AbortSignal`; stops polling cooperatively and does not cancel an active callback. |
| `maxRuns` | Optional. Useful for one-shot jobs; omit to keep polling. |
| `deprecationWarnings` | Default `true`. Emits a one-time `DeprecationWarning` when a case runs on a world without a [handoff](#world-handoff). |
| `actualAgentManifest` / `requestedProviders` / `mcpSurface` | Optional V2 provider-profile preflight, validated together before the worker polls. |

`LocalAgentDirectContext` carries `config` (cloned), `item` identity only (`id` and `externalKey`), `executionId`, `trace` (`{ traceId, spanId }`), `files` (verified `LocalFile` copies of the case's agent-visible input files), `outputDirectory` (a private scratch directory; return generated files with `withFiles`) and optional `signal`. Expected outcomes and case metadata stay with grading.

Hue offers a worker only the cases whose capabilities its registration declares. `localAgentCapabilities` is `{ environment: "environment:v1", direct: "direct:v1" }`. `registeredCapabilities({ agent, target?, directTarget? })` returns the registration's capabilities: the declared `agent.capabilities` plus one per supplied callback. It throws `TypeError` when neither callback is supplied or a declared `environment:v1` or `direct:v1` capability has no matching callback.

## Run a simulation

```ts

```

`runSimulation` runs an existing agent callback against one fresh hosted world per case. It owns immutable resolution, execution linkage, finalization, scoring and resumable uploads, and it is exported from `@hue-run/sdk/evals`. The environment client comes from `@hue-run/sdk/environment` and must use the same Hue origin as the evaluation client. For the workflow, see [simulations](/evaluations/simulations).

Provider-profile preflight is a control-plane contract. The provider-facade route is deployed, but official Gmail and Slack registrations remain inactive; Hue has not released hosted Gmail or Slack provider calls. The options, methods and credential types below do not establish provider parity.

| `persistResultContent` | Required boolean for saved target and scorer content. |

Requires `requestedProviders` and `mcpSurface`. Omitted evidence normalizes to explicit V2 missing evidence; it is never assumed equal to the baseline. |
| `requestedProviders` | Optional `RequestedAttemptProviderV2[]`: the exact provider instances and ordered surfaces asserted for strict preflight. Supplied together with `mcpSurface`. |

### SimulationDefinition

`SimulationDefinition` is a union of an app-authored reference, already published pins and a repository-authored definition. `SimulationScenario` is a deprecated alias for `SimulationDefinition`.

| Kind | Fields |
| --- | --- |
| `{ kind: "experiment", experimentId }` | Selects an existing app-authored immutable experiment template. Each completed invocation clones its frozen dataset version, configuration and scorer-version pins into a fresh experiment. |

### Attempt preflight

An experiment whose `config` carries an immutable `AttemptBaselineV2` can require strict provider-profile preflight before the callback runs. `runSimulation` performs it when `requestedProviders` and `mcpSurface` are supplied; the evaluation-client methods and validators below are exported for adapters that drive it directly.

| Method | Result or purpose |
| --- | --- |
| `prepareAttempt(input: PrepareAttemptRequestV2)` | Prepares the immutable provider-profile binding for one execution → `PrepareAttemptResultV2`. | `getAttemptBinding(bindingId)` | Coupled, secret-free V1 or V2 binding evidence → `AttemptBindingRead`. It never reacquires credentials. |

| Type | Meaning |
| --- | --- |

| `RequestedAttemptProviderV2` | Exact provider instance and surface selection requested for an attempt: `providerInstanceKey` and `surfaceKeys` in effective order. |

| `PreflightFindingV2` / `PreflightReportV2` | One strict parity, profile, binding or coverage finding with a stable `code`, nullable `component`, `providerInstanceKey` and `surfaceKey`, and a fixed nonsecret `message` / the credential-free decision: `status`, `evidenceSource: "caller_supplied"` and `findings`, empty when ready. |

| --- | --- |
| `agentManifestDigestV2(manifest)` | Computes the canonical `sha256:` digest shared by actual and expected V2 agent manifests. |

| `secretFreeBindingV2(bundle)` | Removes endpoints and bearers from a validated bundle, retaining its dependency identity as a `DependencyManifestV2`. |

## Environment client

```ts
import { createEnvironmentClient } from "@hue-run/sdk/environment";

const environments = createEnvironmentClient({ apiKey: process.env.HUE_API_KEY! });
```

`createEnvironmentClient(options: EnvironmentClientOptions): EnvironmentClient` and `new EnvironmentClient(options)` create a typed client for authored environments, isolated runs and immutable journals.

| Option | Type | Default and behavior |
| --- | --- | --- |
| `apiKey` | `string` | Required **Read and write** project service key sent as a bearer token; server-side only. |
| `baseUrl` | `string` | `https://app.hue.run`; the same origin rules as the tracing client. |
| `timeoutMillis` | `number` | `10000`. Per-request deadline in milliseconds, with the same range as the evaluation client. |
| `maxAttempts` | `number` | `4`; integer `1–10`. Attempts for idempotent run mutations. |

Run mutations retry on transport failure and on HTTP 408, 429, 500, 502, 503 and 504 with exponential backoff, reusing the same invocation or idempotency identity. When a 429 or 503 carries `Retry-After`, the client waits that long instead, at most 10 seconds. `createEnvironment` and `publishVersion` are non-idempotent registry writes and are not retried. Failures throw `HueEnvironmentError`, whose fixed message never includes response text or credentials; `status` carries the HTTP status when Hue answered and is absent for transport, timeout or parse failure, and `retryAfterMs` carries Hue's bounded `Retry-After` from a 429 or 503. Responses are limited to 4 MiB and request bodies to 1 MiB; a published definition may contain up to 240 KB.

### Environments and versions

| Method | Result or purpose |
| --- | --- |
| `createEnvironment(input: EnvironmentIdentity)` | `EnvironmentSummary`. Creates an environment identity; not retried. |
| `listEnvironments(page?: EnvironmentPageOptions)` / `getEnvironment(id)` | An `EnvironmentPage` of active identities / an `Environment` with its immutable version summaries. |
| `publishVersion(environmentId, definition: PublishableEnvironmentDefinition)` | `EnvironmentVersionSummary`. Publishes an immutable definition; not retried. |
| `getVersion(id)` | The full `EnvironmentVersion` with its generated action catalog. |

`EnvironmentIdentity` is `{ name, slug, description? }`; `EnvironmentSummary` adds `id` and `archivedAt` (`null` while active), and `Environment` adds `versions`. `EnvironmentVersionSummary` is `{ id, version, contentDigest, createdAt }`, where `contentDigest` is the canonical digest of the stored, defaulted definition; `EnvironmentVersion` adds `environmentId`, the stored `definition` and the generated `actions`. `EnvironmentPage` is `{ items, nextCursor }` and `EnvironmentPageOptions` is `{ after?, limit? }` with a limit from 1 through 100.

#### EnvironmentDefinition

`EnvironmentDefinition` is the complete V1 authored-world document stored as an immutable version. `EnvironmentDefinitionV1` is that same V1 document. `publishVersion` and `EnvironmentVersion.definition` accept a `PublishableEnvironmentDefinition`, the union of `EnvironmentDefinitionV1` and `EnvironmentDefinitionV2`. Narrow `definition.schemaVersion === 1` before reading V1-only fields. Use `EnvironmentDefinitionV2` only when supplying `providerInstances`.

| Field | Meaning |
| --- | --- |
| `schemaVersion: 1` | Definition schema discriminator. |
| `description?` | Human-readable world description. |
| `determinism?.clock` | Virtual clock: `startNs`, the initial virtual nanoseconds as a decimal string (default `"0"`), and `stepAdvanceNs`, the nanoseconds advanced after each recorded step (default `"1000000"`). |
| `state.collections` | Initial normalized state: collections keyed by collection, entity and field names, each field a `JsonValue`. |
| `actions` | The closed catalog of `EnvironmentActionDeclaration` values exposed by this world. |
| `provenance?` | `{ kind: "handwritten" }` (default), `{ kind: "synthetic", note? }` or `{ kind: "derived_from_trace", traceId, revision }`. |
| `metadata?` | Caller-owned immutable metadata. |

Each `EnvironmentActionDeclaration` has a unique `name`, an optional agent-visible `description`, flat `params`, `semantics` and an optional `observation` whose only V1 `projection` is `"identity"`. An `EnvironmentActionParameter` has `name`, `type` (`"string"`, `"number"`, `"boolean"` or `"string[]"`), `required` (default `true`), optional `description` and optional `enum`. `semantics.entry` is a `SemanticEntry`, a versioned deterministic semantic implemented by Hue's environment kernel: `hue.collection.get@1`, `hue.collection.list@1`, `hue.collection.search@1`, `hue.collection.create@1`, `hue.collection.update@1`, `hue.gmail.search_messages@1`, `hue.gmail.get_message@1`, `hue.gmail.get_thread@1`, `hue.gmail.create_draft@1`, `hue.gmail.update_draft@1`, `hue.slack.search@1`, `hue.slack.read_channel@1`, `hue.slack.read_thread@1`, `hue.slack.draft@1` or `hue.slack.destination@1`. `semantics.config` is an `EnvironmentSemanticConfig`: the primary `collection` plus optional `draftsCollection`, `slackActorId`, `slackWorkspaceId`, `mailboxAddress`, `idParam`, `queryParam`, `fields`, `filter` (`{ field, param }`), `limit`, `set`, `setFromParams`, `idPrefix`, `guards` (`{ field, equals, error }` entries, default `[]`) and `notFoundError` (default `"not_found"`).

Publishing generates one `ActionDefinition` per action: `name`, `description?` and `inputSchema`, an `ActionSchema`. That is the JSON Schema subset `{ type: "object", properties, required, additionalProperties: false }` whose properties are scalar types with an optional `enum` or bounded string arrays with `maxItems` and item `maxLength`. Unknown action arguments are rejected.

`EnvironmentDefinitionV2` extends that V1 document with `schemaVersion: 2` and `providerInstances: GmailProviderInstance[]`. Each `GmailProviderInstance` supplies `providerInstanceKey`, `providerId: "google.gmail"`, `syntheticPrincipalId` and a `GmailMailboxConfiguration`. That configuration is either `GmailMailboxConfigurationV1` (`kind: "gmail_mailbox/v1"`, `messagesCollection`, `draftsCollection`, `mailboxAddress`) or `GmailMailboxConfigurationV2` (`kind: "gmail_mailbox/v2"` with the additional `labelsCollection`). These are SDK configuration types; they do not establish that a hosted provider is available. Hue canonicalizes `syntheticPrincipalId` to a lowercase UUID. These bindings are immutable attempt-profile inputs; they do not establish hosted Gmail calls.

`isTransientEnvironmentError(error)` reports whether an environment error is a connection failure or a retryable HTTP status (`408`, `429`, `500`, `502`, `503`, `504`). It classifies a failure; calling it does not retry an action.

### Runs, actions and journals

| Method | Result or purpose |
| --- | --- |
| `createRun(input: CreateRunInput)` | `EnvironmentRun`. Creates or recovers one fresh isolated world using a stable idempotency key. |

| `getEvidence(runId, options?: WorldEvidenceOptions)` | `WorldEvidence`. Reads a sealed world's evaluator-only evidence; see [world handoff](#world-handoff). |

`CreateRunInput` requires `idempotencyKey` and `environmentVersionId`; optional fields are `executionId` (the target execution linked to this world), `seed` (32 lowercase hexadecimal characters), `maxSteps` (`1–500`), `ttlSeconds` (`1–86400`), `traceparent` (the case span's version-00 W3C trace context, whose trace ID must be the trace the execution declared; the world span is parented on it) and `agentRevision` (1–256 characters, part of the world's fingerprint). Invalid bounds throw `RangeError` or `TypeError` before any request. `ActionInput` is `{ invocationId, action, args? }`; omitted `args` means an empty object. `FinishRunInput` is `{ idempotencyKey, status }`, `completed` for accepted outcomes and `abandoned` for failures or cancellation. `StepPageOptions` is `{ after?, limit? }`: `after` is the last seen ordinal (`-1` starts at the first step) and `limit` is 1–100.

| Type | Meaning |
| --- | --- |
| `EnvironmentRun` | Newly created isolated world: `id`, `environmentVersionId`, `clockNs`, `stateDigest`, `maxSteps`, `expiresAt` and the closed generated `actions` catalog. A world the simulation gateway serves also carries `worldId`, `token`, `lifecycle`, `completingUntil`, `baggage`, `traceparent`, `surfaces`, `env` and `mcpConfig`; read them with `worldHandoff`. |
| `ActionResult` | `runId`, zero-based `stepOrdinal`, the `observation`, normalized `effects`, `stateDigest` and `clockNs` after the action, `replayed` and `stepsRemaining`. |

| `Effect` | One normalized world-state effect: `kind` (`created`, `updated` or `deleted`), `collection`, `entityId` and changed `fields`. |
| `RunState` | `id`, `environmentVersionId`, `executionId` (`null` for a standalone run), `seed`, `status` (`open`, `completed`, `abandoned` or `expired`), `stepCount`, `maxSteps`, `clockNs`, `expiresAt`, `createdAt`, `sealedAt`, `stateDigest`, `finalState` after sealing and the `EnvironmentCoverage` fields. | `Step` / `StepPage` | One immutable journal entry: `id`, `ordinal`, `invocationId`, `action`, validated `args`, `observation`, `effects`, `mutated`, `clockNs` and `stateDigest` / `{ items, nextCursor }` with a numeric cursor. |

### Bind local tools

```ts
bindEnvironmentTools(options: BindEnvironmentToolsOptions): Record<string, EnvironmentTool>
```

`bindEnvironmentTools` binds a run's generated catalog to plain local callables without changing the agent framework. `BindEnvironmentToolsOptions` requires `hue`, the client that records each action as tool telemetry, `client`, an environment client bound to the same Hue origin (only `act` is used), and `run`, the fresh `EnvironmentRun` whose closed catalog becomes callables. `parentContext` supplies an optional parent span context for the generated tool spans; `invocationId(action)` is an optional durable invocation-ID factory for caller-owned resume state, and without it each call uses a random UUID.

Each `EnvironmentTool` has `name`, `description?`, `inputSchema` (the action's `ActionSchema`) and `execute(args?)`, which runs the action inside `hue.tool(name, args, ...)` and resolves with the world's `Observation`. When the catalog entry names its MCP server, the tool span also carries `mcp.server.name` and `mcp.server.version`, plus `hue.mcp.provider` and `hue.mcp.surface` when the entry includes them. Transport failures reject with `HueEnvironmentError`.

### World handoff

Where Hue's simulation gateway serves a world, `createRun` also returns its handoff: a world token and one mirror URL per pinned provider surface, such as a Gmail MCP or REST mirror. Point the agent's own provider client at the mirror and pass the world token where the provider credential would go; the project key stays with the runner. Hue Cloud does not serve gateway worlds yet, so today `worldHandoff` returns `null`, callbacks receive `tools` and the `hue_sim_` MCP capability, and `getEvidence` answers `404`.

`runSimulation`, `runLocalAgent` and `hue eval` do this for you. They create each world with the execution, a stable idempotency key, the case span's trace context and the agent revision, pass the handoff as `context.world`, and finish the world before completing the execution. To drive a world yourself:

```ts
import { agentEnvironment, worldHandoff, writeMcpConfig } from "@hue-run/sdk/environment";

const run = await environments.createRun({
  idempotencyKey: `execution:${executionId}`,
  environmentVersionId,
  executionId,
  traceparent: `00-${span.traceId}-${span.spanId}-01`,
  agentRevision: "my-agent@1.4.2",
});
let status: "completed" | "abandoned" = "abandoned";
try {
  const world = worldHandoff(run); // null when the world has no handoff
  if (!world) throw new Error("This deployment does not serve gateway worlds");
  const config = await writeMcpConfig(world);
  try {
    // spawnAgent is your application function, not an SDK method.
    await spawnAgent({ env: agentEnvironment(world), mcpConfigPath: config.path });
    status = "completed";
  } finally {
    await config.dispose();
  }
} finally {
  // Seal a failed or unrun attempt as abandoned, never as completed.
  await environments.finishRun(run.id, {
    idempotencyKey: `execution:${executionId}:${status}`,
    status,
  });
}
```

| Function | Behavior |
| --- | --- |
| `worldHandoff(run)` | The `WorldHandoff` of a create or replay response, or `null` for a world without one. |
| `agentEnvironment(world, options?: AgentEnvironmentOptions)` | Environment variables for the agent's child process: `parent` (default `process.env`) without Hue control-plane credentials, then the world's `env`, which wins. Also sets `HUE_MCP_URL`, `HUE_MCP_TOKEN` and `HUE_MCP_EXPIRES_AT` from the first MCP mirror unless `legacyMcpVariables: false`. Pass `includeHueCredentials: true` only for an agent that must call Hue's own API. |
| `writeMcpConfig(world, { directory? }?)` | Writes `mcpConfig` to an owner-only `mcp.json` in a private directory → `McpConfigFile`, `{ path, dispose() }`. Call `dispose` after the run; it removes the file and directory. |
| `legacyMcpCapability(world)` | `LegacyMcpCapability`, `{ url, token, expiresAt }` for the first MCP mirror, the shape adapters written for `hue_sim_` read; `undefined` without an MCP surface. |
| `stripHueControlPlaneCredentials(parent)` | A copy of `parent` without Hue control-plane credentials or `undefined` values. |
| `isHueControlPlaneCredential(name, value)` | `true` for a name in `HUE_CONTROL_PLANE_VARIABLES` (`HUE_API_KEY`, `HUE_MCP_KEY`, `HUE_PROJECT_KEY`, `HUE_SERVICE_KEY`) or a value that starts with `hue_sk_`, `hue_mcp_` or `hue_attempt_`. |

| Type | Meaning |
| --- | --- |
| `WorldHandoff` | `id`, `token` (a `hue_world_` credential that lives as long as the world), `expiresAt`, `lifecycle`, `completingUntil`, `traceparent` (`null` when none was sent), `baggage` (`hue-world=<id>`), `surfaces`, `env` and `mcpConfig`. `env` holds `HUE_WORLD_ID`, `HUE_WORLD_TOKEN`, `BAGGAGE`, `TRACEPARENT` and one `HUE_SIM_<SURFACE ID>_URL` per surface. |
| `WorldLifecycle` / `WorldFlag` | `pending`, `live`, `completing` or `sealed` / advisory status flags, `no_calls` or `fingerprint_differs`. |
| `WorldSurface` | `provider` (such as `google.gmail`), `surface` (such as `google.gmail/mcp`), `providerInstanceKey`, the mirror `url` and `alias` (`null` while unavailable). |
| `WorldMcpConfig` / `WorldMcpServer` / `WorldMcpHeaders` | The common `mcpServers` shape, keyed by provider instance / one Streamable HTTP server, `{ type: "http", url, headers }` / `{ Authorization }`, the world token as a bearer. |
| `WorldEvidenceOptions` / `WorldEvidenceSection` | `{ section?, bodies? }`: one section or `all` (default), and whether to include ledger request and response bodies (default `true`) / `all`, `start`, `end`, `diff` or `ledger`. |
| `WorldEvidence` | The sealed world's evaluator-only evidence as Hue returns it: start and end state, the diff, the call ledger, coverage and the fingerprint. |

Finishing a gateway world answers `lifecycle: "completing"` with `sealedAt: null`; the seal follows a 5-second grace so in-flight calls land. A later finish answers `409`, which the runners treat as the seal they can no longer change. `getEvidence` needs the project key; a world token can never read evidence, and an open world answers `409` until it is sealed. Nothing in these helpers logs the token. Keep the handoff out of your own logs and checkpoints.

Hue-native `tools` and the `hue_sim_` capability are deprecated. When a case runs on a world without a handoff, `runSimulation` and `runLocalAgent` emit a one-time `DeprecationWarning` with code `HUE_NATIVE_SIMULATION_TOOLS`, and provider-profile preflight emits `HUE_PROVIDER_FACADE`; for a gateway world, provider-profile options are ignored with `HUE_PROVIDER_FACADE_IGNORED`. Because Hue Cloud does not serve gateway worlds yet, you see the first warning today; pass `deprecationWarnings: false` to silence it. `hue eval` never emits these warnings.

## Managed target adapter

`createManagedTargetHandler(options: ManagedTargetOptions)` from `@hue-run/sdk/managed` returns `(request: Request) => Promise<Response>`. Required options are `machineCredential`, `target` and `flushTelemetry`; optional options are `tracer`, `baseUrl`, `maxExecutionMillis` (default 90000, at most 90000) and `finalizationMillis` (default 30000, at most 30000). Pass `tracer: hue.tracer` with a Hue-owned client; without it the handler falls back to the global tracer, its span is not recorded and every invocation returns `uncertain`.

The target receives a `ManagedTargetContext`: `executionId`, `attempt`, `input`, `config`, verified `inputFiles` (`ManagedInputFile` entries with `artifactId`, `filename`, `contentType`, `byteSize`, `sha256` and `role`, plus their `data` bytes), an AbortSignal `signal` and the `traceId` of the `ai.managed_target` span. It returns a `ManagedTargetResult`: optional `state`, `output` JSON, a safe `error` summary, `files` (`ManagedOutputFile` entries with `filename`, `contentType`, `data` and optional `primary`) and provider-reported `usage`. `ManagedInvocation` describes the protocol-version-1 request body Hue POSTs. The helper claims before execution and saves outcomes before returning. It never automatically reruns the agent. See [managed runs](/evaluations/managed-runs) for the full setup and recovery flow.

## Safe serving lifecycle

`createHueSafe(options)` accepts the same options as `createHue`, catches initialization failures and returns a disabled client with an instrumentation failure; the caller's `onExportIssue` stays attached and receives the configuration error's message as the reported issue. Pass an empty string for an unset environment key; the safe constructor handles the invalid configuration. `enabled: false` needs neither a key nor a `captureContent` choice. `flushSafe(options?: SafeLifecycleOptions)` and `shutdownSafe(options?: SafeLifecycleOptions)` return `Promise<SafeLifecycleResult>`, `{ ok: boolean; timedOut: boolean; report: ExportReport }`, without rejecting. `SafeLifecycleOptions.timeoutMillis` is the caller deadline, 1–60000 ms, default 1000. A deadline does not cancel a borrowed provider.

The report also exposes `pendingBytes`, `droppedSpans`, `droppedLogs` and `instrumentationFailures`. Dropped records are subsets of failed records; do not add those counts together. Safe `ok` reflects cumulative failures for the client lifetime. Capture/setup/cleanup failures in Hue helpers omit telemetry and preserve the original callback result/error. Async `onExportIssue` rejections are contained and callbacks are rate-limited. See [production safety](/guides/production-safety).
