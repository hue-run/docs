This reference covers `@hue-run/sdk` **0.3.0** on Node.js 22 or 24 and Bun 1.4. For installation and a runnable first trace, use the [TypeScript guide](/sdks/typescript). See [compatibility](/sdks/compatibility) for supported runtimes and integration versions. Use the [installation guide](/installation) for the available package release.

## Imports

| Entry point | Use |
| --- | --- |
| `@hue-run/sdk` | `createHue`, `createHueSafe`, `HueClient`, `createHueTransport`, `HueTransport`, `hueExperimentalTelemetry`, `contentPrefixes`, `HueConnectionError`, `HueExportError`, `HueTraceVerificationError` and the tracing types below. |
| `@hue-run/sdk/ai-sdk` | `hueTelemetry` for Vercel AI SDK 7. Requires the optional `ai` and `@ai-sdk/otel` peers. |
| `@hue-run/sdk/evals` | Evaluation client, local runners including `runSimulation` and `runLocalAgent`, scorer definitions, attempt-preflight validators, evaluation errors and types. Requires the optional `zod` peer (4.6.5 or later). |
| `@hue-run/sdk/environment` | `createEnvironmentClient`, `EnvironmentClient`, `bindEnvironmentTools`, `HueEnvironmentError` and the simulated-environment types. |
| `@hue-run/sdk/managed` | `createManagedTargetHandler` and the managed-target types. |

The package is ESM; CommonJS applications on Node.js 22.12 or later load every entry point with `require()`. The SDK runs on the server. It does not call a model provider for you or automatically instrument provider calls that emit no telemetry. Every exported type, option and member carries API documentation in the published declarations.

## Create a tracing client

```ts
import { createHue } from "@hue-run/sdk";

const hue = createHue({
  apiKey: process.env.HUE_API_KEY!, // Read the key from server configuration.
  serviceName: "my-agent",
  captureContent: false, // Omit supported input/output content.
});
```

`createHue(options: HueOptions | ExistingHueProviders): HueClient` and `new HueClient(options)` accept the same configuration. `HueOptions` is `SharedHueOptions`, the options every client and transport accepts, plus `enabled`, `apiKey` and `serviceName`.

### HueOptions

| Option | Type | Default and behavior |
| --- | --- | --- |
| `apiKey` | `string` | Required when enabled; ignored for `enabled: false`. Use **Tracing only** for tracing and known-trace receipts; use **Tracing and evaluations** when this process also calls evaluation APIs. Keep it in server-only configuration. |
| `serviceName` | `string` | Required when enabled; 1–256 characters with non-whitespace content. Sets `service.name` on providers created by Hue. |
| `enabled` | `boolean` | `true`; `false` creates a disabled client without attaching processors or requiring a key. |
| `captureContent` | `boolean` | Required explicit choice for an enabled client; there is no default. A disabled client defaults it to `false`. |
| `baseUrl` | `string` | `https://app.hue.run`. Supply an origin, without an API path, query, fragment or credentials. HTTPS is required except for loopback HTTP. |
| `allowInsecureHttp` | `boolean` | `false`. `true` permits `http://` to hosts other than loopback, for example a docker-compose or in-cluster collector, and records a one-time `warning` issue because the key then travels unencrypted. |
| `serviceVersion` | `string` | Optional `service.version` on providers created by Hue. |
| `resourceAttributes` | `Attributes` | Optional additional resource attributes for an owned client, for example `deployment.environment.name` or `service.namespace`; `serviceName` and `serviceVersion` take precedence over same-named keys. Ignored with a `warning` issue in attach mode. |
| `maxQueueBytes` | `number` | `8388608`; 1024–67108864. Shared estimated trace/log queue bytes, including in-flight work. Not total process RSS. |
| `timeoutMillis` | `number` | `10000`; integer from `100` through `60000`. Configures transport requests and the project connection check; it is not an overall `flush()` deadline. |
| `redact` | `(value: string, path: string) => string` | Optional string transformation on Hue's export path. See [content policy](#content-policy). |
| `onExportIssue` | `(issue: ExportIssue) => void \| Promise<void>` | Optional callback for sanitized export diagnostics, called at most once per second. |

Invalid configuration throws `TypeError`. Environment variables are read by your application and passed to the client; these constructors do not automatically load an environment file, and `OTEL_EXPORTER_OTLP_*` variables do not reach Hue's exporters. Owned providers export the OpenTelemetry default resource (`telemetry.sdk.language`, `telemetry.sdk.name`, `telemetry.sdk.version`) beside `service.name`, `service.version` and `resourceAttributes`. Export requests carry a `hue-sdk-typescript/<version>` User-Agent.

### ExistingHueProviders

Use `createHueTransport(options: HueOptions): HueTransport` when your application owns OpenTelemetry setup. Attach its `spanProcessor` and `logRecordProcessor` during provider construction, then pass:

```ts
createHue({ transport, tracerProvider, loggerProvider });
```

`tracerProvider` is a `FlushableTracerProvider` and `loggerProvider` a `FlushableLoggerProvider`: the OpenTelemetry API provider types plus `forceFlush(): Promise<void>`, which the OpenTelemetry SDK providers satisfy. Your application owns their resources, registration and shutdown; `resourceAttributes` is ignored with a warning issue in this mode. Hue never replaces the global tracer provider, logger provider or context manager. See the complete [existing-provider recipe](/integrations/opentelemetry).

## Trace application work

The signatures below use types exported by `@hue-run/sdk` and standard OpenTelemetry types.

```ts
hue.withSpan<T>(
  name: string,
  callback: (span: HueSpan) => T | Promise<T>,
  options?: SpanOptions,
): Promise<T>

hue.tool<T>(
  name: string,
  input: unknown,
  execute: () => T | Promise<T>,
  options?: Pick<SpanOptions, "parentContext">,
): Promise<T>

hue.model<T>(
  model: string,
  callback: (span: HueSpan) => T | Promise<T>,
  options: ModelOptions,
): Promise<T>

hue.getContext(): Context
hue.inject(carrier: Record<string, string>, activeContext?: Context): void
hue.extract(carrier: Record<string, string | string[] | undefined>): Context
hue.recordError(span: Span, error: unknown): void
hue.recordMessages(
  messages: {
    input?: unknown;
    output?: unknown;
    operation?: string;
    provider?: string;
    model?: string;
  },
  explicitContext?: Context,
): void
```

`withSpan` returns the callback's result, ends the span after the callback settles, and records then rethrows an escaping application error. Consume streams inside the callback if their work belongs to that span. A returned streaming `Response` is not evidence that the stream has finished.

`tool` runs `execute` inside a span named `execute_tool {name}` with `gen_ai.tool.name`, records `input` and a defined result as `gen_ai.tool.call.arguments` / `gen_ai.tool.call.result` according to your content policy, and returns the tool result. An `undefined` result omits result content. `options.parentContext` supplies an explicit parent for the tool span.

`model` runs `callback` inside a GenAI client span for one direct provider call, named `{operation} {model}` unless `options.name` is given, with `gen_ai.operation.name`, `gen_ai.request.model` and `gen_ai.provider.name`. The argument order matches `withSpan`. Inside it, the handle's `setInput` and `setOutput` record `gen_ai.input.messages` / `gen_ai.output.messages`, which should use the GenAI semantic-convention message shape; `recordMessages` inside the callback inherits the request metadata.

Content helpers (`setInput`, `setOutput`, `tool` arguments and results, `recordMessages` and `SpanOptions.input`) accept `unknown` and encode plain JSON data (`JsonValue`) at runtime. A value that is not JSON, such as a `Date` or a class instance, is omitted with an instrumentation failure while the callback result is returned unchanged.

`recordMessages` emits a correlated `gen_ai.client.inference.operation.details` log record with the messages in its body. `gen_ai.operation.name`, `gen_ai.provider.name` and `gen_ai.request.model` are set as record attributes from the caller's `operation`, `provider` and `model` or from the enclosing `model()` span, and `gen_ai.conversation.id` from the active session. With content capture enabled, it requires an active span or explicit span context. With capture disabled, it emits nothing. Use logs or span attributes for the same content event to avoid storing duplicate copies.

`recordError` marks a span failed the way every helper does: `error.type` (the error's `name`), an ERROR status without a description and an `exception` event carrying only `exception.type`. Exception messages and stack traces are never recorded, whatever `captureContent` is.

`inject` writes W3C `traceparent` for the active span into a carrier, never the API key or baggage, and also propagates when the client is disabled or closed. `extract` reads W3C trace context from a carrier for use as `parentContext`. Hue registers no global propagator.

### SpanOptions and context

| Option | Default and behavior |
| --- | --- |
| `kind?: SpanKind` | `SpanKind.INTERNAL`. |
| `attributes?: Attributes` | Additional OpenTelemetry attributes; arbitrary names and values are caller-owned. |
| `input?: unknown` | Optional root input, recorded as `input.value`. Omitted when content capture is disabled. |
| `sessionId?: string` | Inherits from the surrounding Hue callback; maps to `gen_ai.conversation.id`. |
| `userId?: string` | Inherits from the surrounding Hue callback; maps to `user.id`. This is your application identity, not a Hue account. |
| `parentContext?: Context` | Explicit parent, for example from `hue.extract()`; otherwise the surrounding Hue context or active OpenTelemetry context. |

Session and user identifiers must contain 1–4096 valid characters. `hue.tracer` is an OpenTelemetry tracer that preserves Hue's local async context; spans other instrumentations create through it parent under `withSpan` and inherit identifiers. `hue.getContext()` supplies the helper's current context to an integration that accepts an explicit parent. When your application has registered a context manager, `withSpan`, `tool`, `model` and `hue.tracer.startActiveSpan` also make their span the active OpenTelemetry span while the callback runs; Hue registers none itself.

### ModelOptions

`ModelOptions` extends the `sessionId`, `userId`, `input` and `parentContext` members of `SpanOptions`.

| Option | Behavior |
| --- | --- |
| `provider: string` | Required. Recorded as `gen_ai.provider.name`, for example `"openai"`. |
| `operation?: string` | Recorded as `gen_ai.operation.name`; defaults to `"chat"`. |
| `name?: string` | Span name; defaults to `"{operation} {model}"`. |
| `input?: unknown` | Recorded as `gen_ai.input.messages` when `captureContent` is true. |

Labels must be non-empty strings of at most 256 characters; other values fall back to `"unknown"` or `"chat"` and count as instrumentation failures.

### HueSpan

The callback receives `span` (the underlying OpenTelemetry span), `context`, `traceId`, `spanId`, `setInput(value: unknown)`, `setOutput(value: unknown)` and `setUsage(usage: TokenUsage)`. Inside `model()`, `setInput` and `setOutput` record `gen_ai.input.messages` and `gen_ai.output.messages`; elsewhere they record `input.value` and `output.value`. `TokenUsage` is `{ inputTokens?: number; outputTokens?: number }`, recorded as `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens`; invalid values are omitted and counted as instrumentation failures. IDs are all zeros for a disabled client.

Use `span.setAttribute(...)`, `span.addEvent(...)` and the other standard OpenTelemetry APIs for additional metadata. Hue does not estimate absent token counts or cost. Captured JSON `null`, `false`, `0` and `""` remain present values; they are distinct from an omitted field. Helper content must serialize as JSON and fit within 256 KiB per field.

## Vercel AI SDK adapter

```ts
import { hueTelemetry } from "@hue-run/sdk/ai-sdk";

// Pass to an AI SDK 7 agent or generation call:
const telemetry = hueTelemetry(hue);
```

`hueTelemetry(hue: HueClient): TelemetryOptions` enables telemetry, sets `recordInputs` and `recordOutputs` from `hue.captureContent`, and configures the AI SDK OpenTelemetry integration with `hue.tracer` and usage reporting.

Supported peer ranges are `ai@^7.0.99` and `@ai-sdk/otel@^1.0.99`. Installed-package tests cover pairs `7.0.99 / 1.0.99` and `7.0.100 / 1.0.100`; every later compatible release is not individually verified.

`hueTelemetry` reads the installed `ai` major version once per process and throws a `TypeError` below 7. For AI SDK 6, use `hueExperimentalTelemetry` from the core entry point instead:

```ts
import { hueExperimentalTelemetry } from "@hue-run/sdk";

const result = await generateText({
  model,
  prompt,
  experimental_telemetry: hueExperimentalTelemetry(hue),
});
```

`hueExperimentalTelemetry(hue: HueClient): ExperimentalTelemetrySettings` returns `{ isEnabled, recordInputs, recordOutputs, tracer }`: `isEnabled` mirrors the client's `enabled` flag, the record flags mirror `captureContent`, and `tracer` is Hue's tracer, so AI SDK 6 spans parent under `withSpan` and inherit identifiers. It needs no `@ai-sdk/otel` peer. Do not upgrade an existing app's AI SDK just to install Hue. For an app that already emits OpenTelemetry spans, assess the [existing-provider path](/integrations/opentelemetry) and its installed OpenTelemetry versions using the [compatibility guide](/sdks/compatibility).

AI SDK per-call integrations replace the global integrations for that call. If your app already has telemetry, preserve its setup and attach Hue to the existing provider. See [OpenTelemetry](/integrations/opentelemetry) and the [reference chatbot](/integrations/reference-chatbot).

## Content policy

- `captureContent: false` disables Hue helper content and removes recognized GenAI, Vercel AI SDK, OpenInference and OpenLLMetry content, legacy GenAI content events, log bodies, status messages and exception text before Hue exports records, including records from other instrumentations on a shared provider. The exported `contentPrefixes` array lists the attribute keys, and their dotted children, that are removed; the [compatibility matrix](/sdks/compatibility) reproduces it. It does not classify every custom attribute name.
- `captureContent: true` permits supplied content. Received content is stored by Hue; the SDK does not set a retention timer. Helpers still omit exception messages and stack traces.
- `redact(value, path)` transforms supported strings in attributes, resources, event/link attributes and log bodies before Hue exports them. It must return a string. A redactor failure rejects the affected record and becomes an export issue.
- This policy applies to Hue's export path. Another exporter and arbitrary span/scope names remain your application's responsibility.

## Flush, shutdown and diagnostics

```ts
hue.checkConnection(): Promise<ProjectConnection>
hue.flush(): Promise<ExportReport>
hue.shutdown(): Promise<ExportReport>

hue.transport.getReport(): ExportReport
hue.transport.getIssues(): ExportIssue[]
hue.transport.getFailureSequence(): number
```

`checkConnection()` returns a `ProjectConnection`, `{ id, name, organizationId, slug }`, for the project associated with the key. It throws `HueConnectionError` on rejected authentication, network failure or an invalid response; `status` carries the HTTP status when Hue answered, and `cause` carries the underlying network, timeout or parsing error. Its message is fixed and safe to log. It sends no trace.

`flush()` drains traces and logs. Concurrent callers receive serialized drains that include their preceding emissions. Rejections, failed exports, queue drops and invalid acknowledgements throw `HueExportError`, whose `issues` and `report` contain sanitized diagnostics. A later non-overlapping flush reports new failures; counters remain cumulative. Overlapping calls also observe failures from shared in-flight work.

`ExportReport` contains `acceptedSpans`, `acceptedLogs`, `rejectedSpans`, `rejectedLogs`, `failedSpans`, `failedLogs`, `pendingSpans`, `pendingLogs`, `droppedSpans`, `droppedLogs`, `pendingBytes` and `instrumentationFailures`. Accepted, rejected, failed, dropped and instrumentation counts are cumulative; pending counts and bytes describe current queued/in-flight records. `getIssues()` returns the latest 128 `ExportIssue` values with `sequence`, `signal` (a `Signal`: `"traces"` or `"logs"`), `kind`, `count`, optional `status` and a sanitized `message`. Kinds are `rejected`, `failed`, `dropped`, `invalid` and `warning`. A warning with no rejection does not fail a flush.

The transport's `spanProcessor` and `logRecordProcessor` receive `RecordValue` records, the `ReadableSpan` or `ReadableLogRecord` the OpenTelemetry SDK hands to a processor. The exporter plumbing behind them is internal and not part of the published declarations; read `getReport()`, `getIssues()` and `getFailureSequence()` instead.

`shutdown()` stops new Hue helpers and flushes. It closes providers that Hue created; borrowed providers remain usable. Repeated calls share the same shutdown promise. If your application supplied the providers, close those providers and then call `transport.shutdown()` during process shutdown. Reuse a shared client across server requests.

Queues are in memory and bounded to 2,048 records per signal, including exports in flight. Export requests are sized from each record's own encoding and split at 1 MiB. Retryable failures use the OpenTelemetry retry policy; partial rejections are not retried wholesale. An acknowledgement means collector receipt, not that every span of a distributed trace has arrived. Stop producing spans before shutdown.

## Trace verification

```ts
await hue.verifyTrace(traceId, {
  expectedSpanIds: [requestSpanId],
  requiredFields: ["model"],
  timeoutMillis: 10_000,
});
```

`verifyTrace(traceId: string, options?: VerifyTraceOptions): Promise<TraceVerification>`. `VerifyTraceOptions` has `expectedSpanIds`, `requiredFields` (an array of `TraceReceiptField`: `"input"`, `"output"`, `"model"`, `"usage"` or `"session"`) and `timeoutMillis`. `TraceVerification` is `{ verified: boolean; receipt: TraceReceipt | null }`. A receipt contains `traceId`, `spanCount`, `revision`, `fields` (`Record<TraceReceiptField, boolean>`), `matchedSpanIds`, `missingSpanIds`, and `traceUrl`. `verified` requires a stored receipt, every supplied expected span, and every required field. Timeout returns `verified: false` with the latest partial receipt, or `null` if none arrived. Other failures throw exported `HueTraceVerificationError`, with `code` and optional HTTP `status`, without response bodies or credentials. A disabled client rejects with `HueConnectionError`.

Trace IDs are 32 lowercase hexadecimal characters; expected span IDs are 16. All IDs must be nonzero. Supply at most 100 unique expected span IDs and unique required field names. The timeout defaults to 10,000 ms and must be positive, finite, and at most 60,000 ms. The receipt response is limited to 64 KiB.

Missing spans or required fields keep polling until the deadline. Only recognized trace-not-found responses, HTTP 429, and HTTP 503 are retried; connection failures, unsupported endpoints, redirects, and malformed responses raise a safe typed error. Verification reads stored normalized field presence across the trace, including supported correlated logs. It does not inspect values or prove that unlisted application operations were instrumented.

[Flush the owning providers before verification](/sdks/typescript#verify-stored-trace-evidence); this method never flushes implicitly.

## Evaluation client

```ts
import { createEvaluationClient } from "@hue-run/sdk/evals";

const client = createEvaluationClient({ apiKey: process.env.HUE_API_KEY! });
```

`createEvaluationClient(options: EvaluationClientOptions): EvaluationClient` and `new EvaluationClient(options)` accept required `apiKey`, optional `baseUrl` (default `https://app.hue.run`) and optional `timeoutMillis` (default `10000`, range `100–60000`). `checkConnection()` returns the key's project. Evaluation registry writes require a **Tracing and evaluations** key.

Methods below return promises. `PageOptions` is `{ after?: string; limit?: number }`, with a supplied limit from 1 through 100. Paged responses are `Page<T>`, `{ items, nextCursor }`; pass a non-null cursor as the next `after`. IDs are UUIDs. `Identity` is `{ name, slug, description? }`. `listDatasets` and `listScorers` accept `RegistryPageOptions`, `PageOptions` plus `includeArchived?: boolean`, which includes archived identities so callers can diagnose slug conflicts explicitly.

Evaluation responses are limited to **4 MiB**. `listCases(versionId, page?)` includes case content, so a valid row limit can still produce an oversized response when cases are large. Request a smaller page, such as `{ limit: 1 }`, and follow `nextCursor`; the client does not automatically split or retry an oversized page. Request bodies are limited to 1 MiB.

### Evaluation types

`@hue-run/sdk/evals` exports these types for method inputs and results.

| `ExperimentCase` | A `DatasetCase` as an experiment sees it, with `hasExpected` (JSON `null` counts as present). |
| `CaseWrite` | Input for `addCase`; optional `environmentVersionId` selects an immutable simulated-world version for the case. |
| `Scorer` / `ScorerVersion` | A scorer and its published `versions` / an immutable published definition with `contentDigest`. |
| `ScorerDefinition` / `MetricDefinition` | The pinned definition variants / a typed metric a scorer declares. |
| `JudgeConfig` | Hosted judge configuration: `model`, `provider`, `rubric`, `bindings`, `maxOutputTokens`, `timeoutMs` and optional `temperature`. |
| `Experiment` | A frozen dataset version, a configuration and pinned scorers, with its `evaluation` run and case counts by execution state. |
| `ExperimentItem` | A case within an experiment and its latest `execution` (`null` before the first start). |
| `Execution` / `TerminalState` | One target attempt whose `state` is a `TerminalState` (`"succeeded"`, `"error"` or `"cancelled"`), `"started"` or `"uncertain"`. |
| `StartExecution` / `CompleteExecution` / `Completion` | Inputs and result of the low-level execution methods. |
| `EvaluationRun` | Scoring progress for an experiment or rescore: pinned `scorerVersions`, `itemCount` and result counts by state. |
| `EvaluationItem` | A subject within an evaluation run, with `hasOutput` and `traceSnapshotId`. |
| `Subject` | An immutable saved outcome: `executionId`, `inputs`, optional `output` and `expected`, `metadata`, `executionState`, trace evidence fields and the source case, experiment and attempt. |
| `Score` / `Result` | A scorer outcome (`scored`, `error` or `skipped`) / a score addressed to an `evaluationItemId` and `scorerVersionId`. |
| `Metric` | A reported metric value: `name`, `value` and optional `passed`; a failed metric stays `state: "scored"`. |
| `TypedError` | A sanitized `{ type, message? }`; the message is stored only when result content is persisted. |
| `ResultSummary` / `StoredResult` | A listed result with `state` / the full stored result with `metrics`, `explanation`, `evidence`, `error` and `sourceDigest`. |
| `ScoreContext` / `LocalScorer` | What a local scorer callback receives, including sealed `environment` evidence when the runner requires it / a pinned `local_code` definition with its bound callback. |
| `JudgeJob` | A hosted judge job with `state`, charge accounting and timestamps. |
| `JudgeBudget` | The project's hosted judge allowance and admission controls; credential resolution does not establish provider acceptance. |
| `RegistryPageOptions` | `PageOptions` plus `includeArchived` for `listDatasets` and `listScorers`. |
| `EnvironmentEvidenceSnapshot` / `EnvironmentEvidence` | Sealed environment evidence resolved through one target execution: `runId`, `executionId`, `environmentVersionId`, `definitionDigest`, `seed`, terminal `status` (`completed`, `abandoned` or `expired`), `stepCount`, `stateDigest`, `initialState`, `finalState` and the coverage fields / the snapshot plus its complete `steps` ordered by ordinal. |
| `SimulationMcpCapability` | Short-lived execution-scoped MCP connection for one simulated world: `url`, `token` and `expiresAt`. Never persist or expose the token. |

### Datasets and scorer definitions

| Method | Result or purpose |
| --- | --- |
| `createDataset(input: Identity)` | `Dataset`, including its initial `versions`. |
| `getDataset(id)` / `listDatasets(page?)` | A dataset / a page of dataset summaries. |
| `createDatasetVersion(datasetId, { fromVersionId? }?)` | A new editable `DatasetVersion`. |
| `getDatasetVersion(versionId)` / `listCases(versionId, page?)` | A version / a page of `DatasetCase` items. |
| `addCase(versionId, input: CaseWrite)` | `{ item, version }`; retain the updated revision. |
| `freezeDatasetVersion(versionId, expectedRevision)` | The frozen `DatasetVersion`. |
| `createScorer(input: Identity)` / `getScorer(id)` / `listScorers(page?)` | Register or retrieve scorer identities. |
| `publishScorerVersion(scorerId, definition: ScorerDefinition)` / `getScorerVersion(versionId)` | Publish or retrieve an immutable `ScorerVersion`. |

`CaseWrite` requires `expectedRevision`, `externalKey` and `inputs`; `expected` and `metadata` are optional. Omit `expected` to declare no reference; `expected: null` is a present reference. Freeze the dataset and publish scorer definitions before creating an experiment.

#### ScorerDefinition and metrics

| Definition | Required fields |
| --- | --- |
| Built-in | Use `builtins.exactMatch()`, `builtins.includes(caseSensitive)` or `builtins.jsonSchema(schema)` to create the exact versioned declaration. |
| Local code | `kind: "local_code"`, `language: "typescript"` or `"python"`, `entrypoint`, `sourceDigest`, `metrics`. `defineLocalScorer` creates the TypeScript declaration and binds the callback. |
| Manual | `kind: "manual"`, `metrics`. Completion requires the platform's human workflow. |
| Hosted judge | `kind: "llm_judge"`, `metrics`, `config`. Hosted dispatch is separate from a local run. |

Each `MetricDefinition` has a `name` and `type`: `boolean`, `text`, `number` (optional `min`/`max`), or `category` (required `categories: string[]`). Returned metrics must match the pinned definitions exactly.

Hosted `config` is a `JudgeConfig` with required `model`, `provider`, `rubric`, `bindings` (an array of `{ name, path, required }`), `maxOutputTokens` and `timeoutMs`; `temperature` is optional. A declaration identifies the requested evaluation policy; the server validates supported values and project execution settings when it is used.

### Experiments, saved subjects and results

| Method | Required inputs and result |
| --- | --- |
| `createExperiment(input)` | `{ idempotencyKey, name, datasetVersionId, scorerVersionIds, config }` → `{ id, evaluationRunId }`. |
| `getExperiment(id)` / `listExperimentItems(id, page?)` / `getExperimentCase(id, caseId)` | An `Experiment` / a page of `ExperimentItem` values / an `ExperimentCase`. |
| `startExecution(experimentId, caseId, input: StartExecution)` | Start or recover an attempt → `Execution`. |
| `getExecution(id)` / `completeExecution(id, input: CompleteExecution)` | Read an attempt / acknowledge its terminal outcome → `Completion`. |
| `getEnvironmentEvidence(executionId)` / `getEnvironmentSteps(executionId, { after?, limit? }?)` | The sealed `EnvironmentEvidenceSnapshot` linked to an execution / a `StepPage` of its sealed journal; `after` is a step ordinal (`-1` starts at the first step) and `limit` is 1–100. |
| `createSimulationMcpCapability({ runId, executionId })` | The execution-scoped generic MCP capability for one world → `SimulationMcpCapability`. `runSimulation` calls it when no provider-profile preflight is requested. |
| `finishExperiment(id, idempotencyKey)` | `{ id, finishedAt }`. |
| `createEvaluationRun(input)` | `{ idempotencyKey, name, subjectIds, scorerVersionIds }` → `{ id }`. |
| `getEvaluationRun(id)` / `listEvaluationItems(id, page?)` / `getSubject(subjectId)` | An `EvaluationRun` / a page of `EvaluationItem` values / an immutable `Subject`. |
| `submitResults(runId, { idempotencyKey, results: Result[] })` | `{ ids }`. |
| `listResults(runId, page?)` / `getResult(resultId)` | A page of `ResultSummary` values / the `StoredResult`. |

`StartExecution` requires `idempotencyKey`; optional fields are `traceExternalId`, `previousExecutionId` and `allowUncertainRetry`. `CompleteExecution` requires `idempotencyKey` and a terminal `state` (`succeeded`, `error` or `cancelled`); optional fields are `output`, `error` (a `TypedError`), `expectedTraceRevision`, `traceEvidence` (`required` or `omit`) and `omissionReason`. `Completion` contains `executionId`, `subjectId`, nullable `traceSnapshotId` and `evaluationItemId`. Use these low-level methods only with a known recovery decision; see [recovery](#recovery-errors).

Each submitted `Result` requires `evaluationItemId`, `scorerVersionId` and the `Score` fields described below; a local-code result also carries its `sourceDigest`. A scored result contains `metrics: [{ name, value, passed? }]` and a nonempty `explanation` or an `evidence` value. Error results contain `error: { type, message? }`; skipped results contain an `explanation`.

Mutations do not retry implicitly. Reuse a saved idempotency key with the same intended mutation after a lost response. `HueApiError.status` distinguishes an HTTP rejection from a connection/response failure; errors do not echo server bodies.

### Hosted judge jobs

`getJudgeBudget()` returns a `JudgeBudget` with the configured allowance and availability. `createJudgeJobs(runId, { idempotencyKey, jobs: [{ evaluationItemId, scorerVersionId }] })` returns job IDs. Inspect `JudgeJob` values with `listJudgeJobs(runId, page?)` or `getJudgeJob(jobId)`, and request cancellation with `cancelJudgeJob(jobId, reason)`.

Submitting hosted jobs is an explicit platform operation and can consume the project's allowance. SDK method availability does not establish that a hosted provider or project budget is configured. Local runners leave hosted and manual scorer pins for their owning workflows.

## Run locally and rescore

```ts
runExperiment(options: RunExperimentOptions): Promise<RunnerReport>
rescore(options: RescoreOptions): Promise<RunnerReport>
```

Both functions are exported from `@hue-run/sdk/evals`.

| Option | Required/default |
| --- | --- |
| `client` | Required `EvaluationClient`. |
| `checkpointDirectory` | Required dedicated local directory for this run. Preserve it for upload recovery; keep it out of Git. |
| `persistResultContent` | Required boolean, independent of telemetry capture. |
| `scorers` | Optional array of bound `LocalScorer` definitions/callbacks. |
| `concurrency` | Default `1`; integer `1–16`. |
| `schemaTimeoutMillis` | Default `2000`; integer `100–60000`; applies to JSON Schema validation, not arbitrary callbacks. |
| `environmentEvidence` | Optional `"required"`: resolve sealed world evidence for local scoring and historical rescoring. `runSimulation` sets it. |

`runExperiment` additionally requires `hue`, `experimentId`, `traceEvidence` and `target(inputs, { config, item, span, executionId })`. The target may return a JSON value, `undefined`, or a promise of either. Evidence must be `{ mode: "required" }` or `{ mode: "omit", reason: "..." }`. Telemetry and evaluation clients must use the same project and origin.

`rescore` additionally requires `runId` and has **no target callback**. Create its evaluation run from existing subject IDs first. Both return a `RunnerReport`, `{ runId, subjectIds, resultIds, deferredScorerVersionIds }`.

With `persistResultContent: false`, completions and checkpoints omit raw output, target error messages, scorer evidence and arbitrary explanations. Declared metric values remain stored, including text metrics. Already stored dataset inputs/references are independent of this setting. Historical scoring skips unavailable output; it does not rerun a target to reconstruct it.

### Local scorer exports

| Export | Behavior |
| --- | --- |
| `builtins.exactMatch()` | Publishable typed JSON equality definition. |
| `builtins.includes(caseSensitive = true)` | Publishable string-inclusion definition. |
| `builtins.jsonSchema(schema: JsonValue)` | Publishable JSON Schema draft 2020-12 definition. |
| `defineLocalScorer({ source, entrypoint, metrics, score })` | Returns a `LocalScorer`; source is `string` or `Uint8Array`. |
| `sourceDigest(source: string \| Uint8Array)` | SHA-256 declaration for supplied source bytes/text. |
| `scoreLocally(version, context, { scorers?, schemaTimeoutMillis? }?)` | Computes `Promise<Score>` without uploading it. |

`@hue-run/sdk/evals` uses `zod`, an optional peer dependency (4.6.5 or later), for its bounded runtime contracts; install it when you use evaluations or simulations. JSON Schema scoring uses `ajv`, a separate optional peer dependency (8.17 or later) loaded inside a worker only when `builtins.jsonSchema` scores a case; without it that scorer reports `SchemaValidatorUnavailable`. The tracing core depends only on `@opentelemetry/*` packages.

`ScoreContext` contains `inputs`, `hasOutput`, `hasExpected`, optional `output`/`expected`, `metadata`, `executionState` and, when the runner requires environment evidence, `environment` (an `EnvironmentEvidence`). With environment evidence present, a `local_code` scorer runs even when no output is stored. When required evidence cannot be read, `local_code` results record an `EnvironmentEvidenceUnavailable` error; a world marked `environment_incomplete` produces a skipped result with the fixed explanation `Environment incomplete: provider behavior is not implemented.` A `Score` is `scored` with declared metrics and explanation/evidence, `error` with a typed error, or `skipped` with an explanation. A failed quality metric is still `scored`, with `passed: false`.

Custom callbacks run locally, without a general execution timeout or side-effect cancellation. The source digest is a caller declaration, not attestation of dependencies or closures. Hosted judge pins must be dispatched through judge jobs; `scoreLocally` does not execute them.

### Recovery errors

- `UncertainExecutionError` exposes `caseId` and optional `executionId`: no durable outcome is available, so the runner refuses to repeat potentially completed work.
- `OutcomeSerializationError` exposes `executionId`: the target returned, but its outcome could not be saved as JSON. The runner does not invoke it again.
- `TargetCancelledError` is thrown when cooperative caller cancellation stops target execution; the runner records the execution as `cancelled`.
- `TargetOutcomeUncertainError` exposes `executionId`: the target or its simulated world may have committed but acknowledgement is unavailable, so a resume will not invoke the target again.
- Required trace export failures surface through `HueExportError` or recovery checks. A new empty exporter cannot prove receipt of an earlier trace.

Use one checkpoint directory per experiment or rescore run. Checkpoint files contain allowed result content and are private local files, not encrypted storage. After an upload failure, resume with the same run, directory and options so saved payloads and idempotency keys are reused. If a process crashes, confirm its recorded owner has stopped before removing the directory's `.lock` file. Removing a lock never authorizes another target invocation.

When a target's outcome is uncertain, restarting the runner will not repeat it. Investigate side effects first. The low-level `startExecution` API requires an explicit `previousExecutionId` for a replacement attempt and `allowUncertainRetry: true` to replace a still-started attempt. The convenience runner does not automatically adopt an externally created attempt; use a new experiment for an intentional fresh target run. Required evidence never silently changes to omitted evidence after an export failure.

For a runnable experiment and historical rescore, see the public [first evaluation guide](/evaluations/first-evaluation).

## Run a simulation

```ts
runSimulation(options: RunSimulationOptions): Promise<SimulationReport>
```

`runSimulation` runs an existing agent callback against one fresh hosted world per case. It owns immutable resolution, execution linkage, finalization, scoring and resumable uploads, and it is exported from `@hue-run/sdk/evals`. The environment client comes from `@hue-run/sdk/environment` and must use the same Hue origin as the evaluation client. For the workflow, see [simulations](/evaluations/simulations).

Provider-profile preflight is a control-plane contract. The provider-facade route is deployed, but official Gmail and Slack registrations remain inactive; Hue has not released hosted Gmail or Slack provider calls. The options, methods and credential types below do not establish provider parity.

| `scenario` | Required `SimulationScenario`. |
| `persistResultContent` | Required boolean for saved target and scorer content. |
| `traceEvidence` | Required `{ mode: "required" }` or `{ mode: "omit", reason }`. |
| `target(inputs, context)` | Required. Invokes the existing local agent exactly once for this attempt with a `SimulationTargetContext`; returns a JSON value, `undefined` or a promise of either. |
| `localScorers` | Optional `LocalScorer[]` bound by their declared source digests. |

| `schemaTimeoutMillis` | JSON Schema worker deadline in milliseconds. |

| `ttlSeconds` | Per-world lease in seconds, `1–86400`. |

`SimulationReport` extends `RunnerReport` with `experimentId`, the fresh experiment created for this invocation, and `runUrl`, the browser URL joining task, trace, world evidence and scoring. ### SimulationScenario

`SimulationScenario` is a union of an app-authored reference and a repository-authored definition.

| Kind | Fields |
| --- | --- |
| `{ kind: "experiment", experimentId }` | Selects an existing app-authored immutable experiment template. Each completed invocation clones its frozen dataset version, configuration and scorer-version pins into a fresh experiment. |
| `{ kind: "repository", name, slug, description?, environment, cases, scorers, config? }` | Publishes and resolves the definition. `slug` is the stable dataset slug used for immutable version resolution; `environment` is an `EnvironmentIdentity` plus its `definition: PublishableEnvironmentDefinition`; `config` is passed to every target callback. At least one case and one scorer are required, and case keys must be unique. |

`RepositorySimulationCase` is `{ externalKey, inputs, expected?, metadata? }`: a stable key unique within the scenario dataset, the JSON inputs passed to the target, an optional reference output and optional caller-owned metadata. `RepositorySimulationScorer` is an `Identity` plus `scorer`, a `ScorerDefinition` to publish or a `LocalScorer` bound to its source digest. Stable slugs reuse matching immutable content digests; changed definitions publish new versions. Unsupported or server-only scorer kinds throw `TypeError` before any write.

| Field | Meaning |
| --- | --- |

| --- | --- |

### Attempt preflight

An experiment whose `config` carries an immutable `AttemptBaselineV2` can require strict provider-profile preflight before the callback runs. `runSimulation` performs it when `requestedProviders` and `mcpSurface` are supplied; the evaluation-client methods and validators below are exported for adapters that drive it directly.

| Method | Result or purpose |
| --- | --- |
| `prepareAttempt(input: PrepareAttemptRequestV2)` | Prepares the immutable provider-profile binding for one execution → `PrepareAttemptResultV2`. The route identity is removed from the JSON body, and credential-bearing responses are validated against the request before being returned; a malformed success response throws `HueApiError` without exposing details. |
| `getAttemptBinding(bindingId)` | Coupled, secret-free V1 or V2 binding evidence → `AttemptBindingRead`. It never reacquires credentials. |
| `refreshAttemptConnection(previous: AttemptConnectionBundleV2, { idempotencyKey })` | Rotates an unexpired V2 connection while preserving its immutable binding evidence → `RefreshAttemptResultV2`. The credential generation must advance by one and the stable evidence must be unchanged. |
| `revokeAttemptConnection({ bindingId })` | Revokes an attempt binding → `RevokeAttemptResult`. A revoked connection must not be reused or refreshed. |

| Type | Meaning |
| --- | --- |
| `ActualAgentManifestV2` / `ActualAgentManifestInputV2` | Canonical caller-observed agent configuration after missing evidence is made explicit: six strict `components` (`agent`, `prompt`, `model`, `tools`, `approvals`, `orchestration`), each `{ digest: string \| null, evidence: "observed" \| "declared" \| "missing" }`, MCP `catalogs` in effective model-visible order (never sorted) and native `helperConfigurations` / the input form, in which omitted evidence normalizes to missing. |

| `AttemptBaselineV2` | Immutable V2 parity and provider baseline stored with an experiment version: `expectedAgentManifestId`, `expectedAgentManifestDigest`, `expectedAgentManifest` and `dependencyManifest`. |
| `RequestedAttemptProviderV2` | Exact provider instance and surface selection requested for an attempt: `providerInstanceKey` and `surfaceKeys` in effective order. |
| `PrepareAttemptRequestV2` / `PrepareAttemptInputV2` | Caller input to `prepareAttempt` (`schemaVersion: 2`, `idempotencyKey`, `executionId`, `environmentRunId`, `expectedAgentManifestDigest`, optional `actualManifest` and `requestedProviders`) / the canonical input after defaulting caller evidence. |
| `PreflightFindingV2` / `PreflightReportV2` | One strict parity, profile, binding or coverage finding with a stable `code`, nullable `component`, `providerInstanceKey` and `surfaceKey`, and a fixed nonsecret `message` / the credential-free decision: `status`, `evidenceSource: "caller_supplied"` and `findings`, empty when ready. |
| `ParityEvidenceV2` | Stable parity evidence stored without endpoints or credentials, including `actualAgentManifestDigest`, `dependencyManifestDigest` and `executionManifestDigest`. |
| `AttemptIdentityV2` | Stable identities shared by every credential generation of an attempt: `bindingId`, `executionId` and `environmentRunId`. |
| `AttemptConnectionBundleV2` | Credential-bearing V2 provider connections delivered only to the callback: `expiresAt`, a monotonic `credentialGeneration`, `providers` whose surfaces add an HTTPS `endpoint` and a short-lived `bearer`, and `parity`. Never persist or log it. |
| `AttemptBindingRead` | Secret-free persisted binding state, discriminated by `schemaVersion` 1 or 2 without converting V1 evidence; includes `outcome`, `credentialGeneration`, `createdAt` and `revokedAt`. |
| `PrepareAttemptReadyV2` / `PrepareAttemptIncompleteV2` / `PrepareAttemptResultV2` | Successful preparation with a finding-free report and a fresh `bundle` / inconclusive preparation with `bindingId`, its findings and the durable `gap`, after which no target or scorer may run / their union. |

| --- | --- |
| `agentManifestDigestV2(manifest)` | Computes the canonical `sha256:` digest shared by actual and expected V2 agent manifests. |

| `secretFreeBindingV2(bundle)` | Removes endpoints and bearers from a validated bundle, retaining its dependency identity as a `DependencyManifestV2`. |
| `projectMcpConnectionV2(bundle, providerInstanceKey)` | The `SimulationMcpCapability` projection of the provider's MCP surface, or `null`. This legacy `context.mcp` projection is credential-bearing and is never another source of binding truth. |

## Environment client

```ts
import { createEnvironmentClient } from "@hue-run/sdk/environment";

const environments = createEnvironmentClient({ apiKey: process.env.HUE_API_KEY! });
```

`createEnvironmentClient(options: EnvironmentClientOptions): EnvironmentClient` and `new EnvironmentClient(options)` create a typed client for authored environments, isolated runs and immutable journals.

| Option | Type | Default and behavior |
| --- | --- | --- |
| `apiKey` | `string` | Required **Tracing and evaluations** project service key sent as a bearer token; server-side only. |
| `baseUrl` | `string` | `https://app.hue.run`; the same origin rules as the tracing client. |
| `timeoutMillis` | `number` | `10000`. Per-request deadline in milliseconds, with the same range as the evaluation client. |
| `maxAttempts` | `number` | `4`; integer `1–10`. Attempts for idempotent run mutations. |

Run mutations retry on transport failure and on HTTP 408, 429, 500, 502, 503 and 504 with exponential backoff, reusing the same invocation or idempotency identity. `createEnvironment` and `publishVersion` are non-idempotent registry writes and are not retried. Failures throw `HueEnvironmentError`, whose fixed message never includes response text or credentials; `status` carries the HTTP status when Hue answered and is absent for transport, timeout or parse failure. Responses are limited to 4 MiB and request bodies to 1 MiB; a published definition may contain up to 240 KB.

### Environments and versions

| Method | Result or purpose |
| --- | --- |
| `createEnvironment(input: EnvironmentIdentity)` | `EnvironmentSummary`. Creates an environment identity; not retried. |
| `listEnvironments(page?: EnvironmentPageOptions)` / `getEnvironment(id)` | An `EnvironmentPage` of active identities / an `Environment` with its immutable version summaries. |
| `publishVersion(environmentId, definition: PublishableEnvironmentDefinition)` | `EnvironmentVersionSummary`. Publishes an immutable definition; not retried. |
| `getVersion(id)` | The full `EnvironmentVersion` with its generated action catalog. |

`EnvironmentIdentity` is `{ name, slug, description? }`; `EnvironmentSummary` adds `id` and `archivedAt` (`null` while active), and `Environment` adds `versions`. `EnvironmentVersionSummary` is `{ id, version, contentDigest, createdAt }`, where `contentDigest` is the canonical digest of the stored, defaulted definition; `EnvironmentVersion` adds `environmentId`, the stored `definition` and the generated `actions`. `EnvironmentPage` is `{ items, nextCursor }` and `EnvironmentPageOptions` is `{ after?, limit? }` with a limit from 1 through 100.

#### EnvironmentDefinition

`EnvironmentDefinition` is the complete V1 authored-world document stored as an immutable version. `EnvironmentDefinitionV1` is that same V1 document. `publishVersion` and `EnvironmentVersion.definition` accept a `PublishableEnvironmentDefinition`, the union of `EnvironmentDefinitionV1` and `EnvironmentDefinitionV2`. Narrow `definition.schemaVersion === 1` before reading V1-only fields. Use `EnvironmentDefinitionV2` only when supplying `providerInstances`.

| Field | Meaning |
| --- | --- |
| `schemaVersion: 1` | Definition schema discriminator. |
| `description?` | Human-readable world description. |
| `determinism?.clock` | Virtual clock: `startNs`, the initial virtual nanoseconds as a decimal string (default `"0"`), and `stepAdvanceNs`, the nanoseconds advanced after each recorded step (default `"1000000"`). |
| `state.collections` | Initial normalized state: collections keyed by collection, entity and field names, each field a `JsonValue`. |
| `actions` | The closed catalog of `EnvironmentActionDeclaration` values exposed by this world. |
| `provenance?` | `{ kind: "handwritten" }` (default), `{ kind: "synthetic", note? }` or `{ kind: "derived_from_trace", traceId, revision }`. |
| `metadata?` | Caller-owned immutable metadata. |

Each `EnvironmentActionDeclaration` has a unique `name`, an optional agent-visible `description`, flat `params`, `semantics` and an optional `observation` whose only V1 `projection` is `"identity"`. An `EnvironmentActionParameter` has `name`, `type` (`"string"`, `"number"`, `"boolean"` or `"string[]"`), `required` (default `true`), optional `description` and optional `enum`. `semantics.entry` is a `SemanticEntry`, a versioned deterministic semantic implemented by Hue's environment kernel: `hue.collection.get@1`, `hue.collection.list@1`, `hue.collection.search@1`, `hue.collection.create@1`, `hue.collection.update@1`, `hue.gmail.search_messages@1`, `hue.gmail.get_message@1`, `hue.gmail.get_thread@1`, `hue.gmail.create_draft@1`, `hue.gmail.update_draft@1`, `hue.slack.search@1`, `hue.slack.read_channel@1`, `hue.slack.read_thread@1`, `hue.slack.draft@1` or `hue.slack.destination@1`. `semantics.config` is an `EnvironmentSemanticConfig`: the primary `collection` plus optional `draftsCollection`, `slackActorId`, `slackWorkspaceId`, `mailboxAddress`, `idParam`, `queryParam`, `fields`, `filter` (`{ field, param }`), `limit`, `set`, `setFromParams`, `idPrefix`, `guards` (`{ field, equals, error }` entries, default `[]`) and `notFoundError` (default `"not_found"`).

Publishing generates one `ActionDefinition` per action: `name`, `description?` and `inputSchema`, an `ActionSchema`. That is the JSON Schema subset `{ type: "object", properties, required, additionalProperties: false }` whose properties are scalar types with an optional `enum` or bounded string arrays with `maxItems` and item `maxLength`. Unknown action arguments are rejected.

`EnvironmentDefinitionV2` extends that V1 document with `schemaVersion: 2` and `providerInstances: GmailProviderInstance[]`. Each `GmailProviderInstance` is `{ providerInstanceKey, providerId: "google.gmail", syntheticPrincipalId, configuration: { kind: "gmail_mailbox/v1", messagesCollection, draftsCollection, mailboxAddress } }`. Hue canonicalizes `syntheticPrincipalId` to a lowercase UUID. These bindings are immutable attempt-profile inputs; they do not establish hosted Gmail calls.

### Runs, actions and journals

| Method | Result or purpose |
| --- | --- |
| `createRun(input: CreateRunInput)` | `EnvironmentRun`. Creates or recovers one fresh isolated world using a stable idempotency key. |
| `getRun(runId)` | `RunState`, the authoritative current or sealed world state. Older servers that omit coverage fields read as `validity: "not_assessed"` and `coverageGap: null`. |
| `act(runId, input: ActionInput)` | `ActionResult`. Invokes an action; repeating an invocation identity replays its recorded result. |
| `listSteps(runId, page?: StepPageOptions)` | `StepPage`. Pages the immutable journal by step ordinal. |
| `finishRun(runId, input: FinishRunInput)` | `SealedRun`. Seals a world as `completed` or `abandoned` and freezes its evidence. |
| `recordCoverageGap(runId, input: CoverageGapInput)` | `CoverageGapResult`. Records a known coverage gap with durable identity; retries reuse the exact request. |

`CreateRunInput` requires `idempotencyKey` and `environmentVersionId`; optional fields are `executionId` (the target execution linked to this world), `seed` (32 lowercase hexadecimal characters), `maxSteps` (`1–500`) and `ttlSeconds` (`1–86400`). Invalid bounds throw `RangeError` or `TypeError` before any request. `ActionInput` is `{ invocationId, action, args? }`; omitted `args` means an empty object. `FinishRunInput` is `{ idempotencyKey, status }`, `completed` for accepted outcomes and `abandoned` for failures or cancellation. `StepPageOptions` is `{ after?, limit? }`: `after` is the last seen ordinal (`-1` starts at the first step) and `limit` is 1–100.

| Type | Meaning |
| --- | --- |
| `EnvironmentRun` | Newly created isolated world: `id`, `environmentVersionId`, `clockNs`, `stateDigest`, `maxSteps`, `expiresAt` and the closed generated `actions` catalog. |
| `ActionResult` | `runId`, zero-based `stepOrdinal`, the `observation`, normalized `effects`, `stateDigest` and `clockNs` after the action, `replayed` and `stepsRemaining`. |
| `Observation` | The recorded answer returned by the simulated world: `status` `"ok"` or `"error"` plus additional bounded fields. An error observation is a world answer, not a transport exception. |
| `Effect` | One normalized world-state effect: `kind` (`created`, `updated` or `deleted`), `collection`, `entityId` and changed `fields`. |
| `RunState` | `id`, `environmentVersionId`, `executionId` (`null` for a standalone run), `seed`, `status` (`open`, `completed`, `abandoned` or `expired`), `stepCount`, `maxSteps`, `clockNs`, `expiresAt`, `createdAt`, `sealedAt`, `stateDigest`, `finalState` after sealing and the `EnvironmentCoverage` fields. |
| `Step` / `StepPage` | One immutable journal entry: `id`, `ordinal`, `invocationId`, `action`, validated `args`, `observation`, `effects`, `mutated`, `clockNs` and `stateDigest` / `{ items, nextCursor }` with a numeric cursor. |
| `SealedRun` | `id`, requested terminal `status`, final `stepCount`, `stateDigest` and `sealedAt`. |
| `CoverageGapInput` / `CoverageGap` / `CoverageGapResult` | A durable first-fault report for known missing provider behavior (`idempotencyKey`, `provider`, `operation`, `code`, `args` bounded to 16,000 JSON bytes and a nonsecret `description`) / the stored gap with `reportedAt` and `reportedBy` (`{ kind: "project_key" \| "user", id }`) / `{ runId, validity: "environment_incomplete", coverageGap }`. |
| `EnvironmentCoverage` | `validity` (`"not_assessed"` or `"environment_incomplete"`) and `coverageGap` (`null` when none was reported). Missing fields from older servers mean `not_assessed`, never verified parity. |

### Bind local tools

```ts
bindEnvironmentTools(options: BindEnvironmentToolsOptions): Record<string, EnvironmentTool>
```

`bindEnvironmentTools` binds a run's generated catalog to plain local callables without changing the agent framework. `BindEnvironmentToolsOptions` requires `hue`, the client that records each action as tool telemetry, `client`, an environment client bound to the same Hue origin (only `act` is used), and `run`, the fresh `EnvironmentRun` whose closed catalog becomes callables. `parentContext` supplies an optional parent span context for the generated tool spans; `invocationId(action)` is an optional durable invocation-ID factory for caller-owned resume state, and without it each call uses a random UUID.

Each `EnvironmentTool` has `name`, `description?`, `inputSchema` (the action's `ActionSchema`) and `execute(args?)`, which runs the action inside `hue.tool(name, args, ...)` and resolves with the world's `Observation`. Transport failures reject with `HueEnvironmentError`.

## Managed target adapter

`createManagedTargetHandler(options: ManagedTargetOptions)` from `@hue-run/sdk/managed` returns `(request: Request) => Promise<Response>`. Required options are `machineCredential`, `target` and `flushTelemetry`; optional options are `tracer`, `baseUrl`, `maxExecutionMillis` (default 90000, at most 90000) and `finalizationMillis` (default 30000, at most 30000). Pass `tracer: hue.tracer` with a Hue-owned client; without it the handler falls back to the global tracer, its span is not recorded and every invocation returns `uncertain`.

The target receives a `ManagedTargetContext`: `executionId`, `attempt`, `input`, `config`, verified `inputFiles` (`ManagedInputFile` entries with `artifactId`, `filename`, `contentType`, `byteSize`, `sha256` and `role`, plus their `data` bytes), an AbortSignal `signal` and the `traceId` of the `ai.managed_target` span. It returns a `ManagedTargetResult`: optional `state`, `output` JSON, a safe `error` summary, `files` (`ManagedOutputFile` entries with `filename`, `contentType`, `data` and optional `primary`) and provider-reported `usage`. `ManagedInvocation` describes the protocol-version-1 request body Hue POSTs. The helper claims before execution and saves outcomes before returning. It never automatically reruns the agent. See [managed runs](/evaluations/managed-runs) for the full setup and recovery flow.

## Safe serving lifecycle

`createHueSafe(options)` accepts the same options as `createHue`, catches initialization failures and returns a disabled client with an instrumentation failure; the caller's `onExportIssue` stays attached and receives the configuration error's message as the reported issue. Pass an empty string for an unset environment key; the safe constructor handles the invalid configuration. `enabled: false` needs neither a key nor a `captureContent` choice. `flushSafe(options?: SafeLifecycleOptions)` and `shutdownSafe(options?: SafeLifecycleOptions)` return `Promise<SafeLifecycleResult>`, `{ ok: boolean; timedOut: boolean; report: ExportReport }`, without rejecting. `SafeLifecycleOptions.timeoutMillis` is the caller deadline, 1–60000 ms, default 1000. A deadline does not cancel a borrowed provider.

The report also exposes `pendingBytes`, `droppedSpans`, `droppedLogs` and `instrumentationFailures`. Dropped records are subsets of failed records; do not add those counts together. Safe `ok` reflects cumulative failures for the client lifetime. Capture/setup/cleanup failures in Hue helpers omit telemetry and preserve the original callback result/error. Async `onExportIssue` rejections are contained and callbacks are rate-limited. See [production safety](/guides/production-safety).
