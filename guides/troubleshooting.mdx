---
title: "Troubleshooting"
description: "Diagnose missing traces, content, authentication, and export failures."
---

Start by separating the application result from the telemetry result. A model request can succeed while its trace export fails, and a correctly recorded trace can contain an application error.

## The connection check fails

Confirm the key belongs to the selected project and is active. Use **Tracing only** for telemetry or receipts, or **Read and write** when the process also calls evaluation APIs. Keep service keys server-side; never use a management token.

Both SDKs default to `https://app.hue.run`. Overrides must be origins, without `/api` or OTLP paths. Hosted origins require HTTPS; loopback HTTP works locally, and TypeScript requires `allowInsecureHttp: true` for other HTTP hosts.

Report the error and project without the key or authorization header. TypeScript `HueConnectionError` includes HTTP `status` or a network, timeout or parsing `cause`.

## No trace appears

1. Verify the key with `checkConnection()` (TypeScript) or `validate_project()` (Python).
2. Confirm instrumentation: direct provider calls emit no telemetry without an integration or manual span.
3. Await flush before exit; inspect the same project. Session IDs group requests, not projects.
4. Check exporter failures, rejected records and queue limits.

An existing OpenTelemetry application should add Hue to the provider it already owns. Creating a second global provider can leave some instrumentations attached to the first one. Follow the [provider integration guide](/integrations/opentelemetry).

## A parent span is missing

Children may arrive before parents. Flush participating providers and allow ingestion to finish. A parent may be sampled out, excluded or sent elsewhere; preserve its original ID when diagnosing.

An OpenTelemetry status of `Unset` means no explicit status was recorded. It is not itself an application failure.

## A trace stays running

With TypeScript 0.7.0 or later and Python 0.4.0 or later, Hue shows **Running** while a Hue or AI span remains open (usually after 1.5 s), then resolves it when finished spans arrive. After 15 minutes without a span, log or end, it shows **No end received**. Await flush before exit; processors forwarding starts must also forward ends. Later telemetry makes it **Running** again.

## Input or output is missing

Check the explicit content setting. `captureContent: false` in TypeScript or `capture_content=False` in Python intentionally omits supported content fields in Hue helpers. Both SDKs also strip recognized GenAI, OpenInference, OpenLLMetry, Langfuse and Vercel AI SDK content attributes from every record on Hue's export path, including spans from third-party instrumentors on the same provider; the [compatibility matrix](/sdks/compatibility) lists the keys. To record inputs and outputs, set `captureContent: true` or `capture_content=True`, the recommended setting, unless an application or data policy forbids sending that content to another service.

Content must also be supplied by the instrumentation. The SDK does not reconstruct prompts, invent an output or estimate missing usage. JSON `null` is a recorded value; an absent output is different. Helper spans never record exception messages or stack traces, only `error.type` and the span status.

If you add third-party instrumentation, configure its own content controls too: unrecognized custom keys pass through, and the instrumentor may still send content to other exporters. Avoid placing private text in custom span names or arbitrary attributes, which cannot all be classified automatically.

## Streaming spans end too early

Keep the request span open while the stream is consumed, including tool execution and the final output. Awaiting only the initial stream object does not mean generation has finished.

In a serverless application, await the telemetry flush in the framework's supported after-response lifecycle. Do not shut down a shared provider after every request. Shut it down when the application stops.

## Flush reports a failure

TypeScript `flush()` throws `HueExportError` for rejected or failed export work. Python `force_flush()` returns `False` for an observed export failure, dropped record, instrumentation omission or timeout. Use the bounded safe variants in serving application lifecycles; see [production safety](/guides/production-safety). Inspect their sanitized status reports; do not discard those results.

In-memory queues can lose records on termination, overflow or sampling. A timeout does not prove rejection. Hue deduplicates exact completed-span or log replays, but rerunning work or changing IDs creates records; inspect partial-batch rejections before retrying.

OTLP requests are bounded. The SDK splits batches; oversized helper content is omitted as an instrumentation failure, while raw external records remain subject to receiver limits. Keep binary files out of span attributes; file storage has a separate lifecycle.

## The example throws `Cannot use import statement outside a module`

Node.js treats `.js` and `.ts` files as CommonJS unless the nearest `package.json` contains `"type": "module"`. Run `npm pkg set type=module` in the example directory, or name the file `first-trace.mjs` / `trace.mts`, then run it again. A CommonJS application on Node.js 22.12 or later can instead load the package with `require("@hue-run/sdk")`.

## Installation reports a dependency conflict

See the [compatibility matrix](/sdks/compatibility). SDK core supports AI SDK 6 via `hueExperimentalTelemetry(hue)`; `hueTelemetry` requires AI SDK 7. Python accepts OpenTelemetry `>=1.40,<2` (1.44.0 certified; 1.40.0 tested floor). Keep existing instrumentation and use a standard OTLP exporter outside the matrix; do not force incompatible installs.

## A JSON Schema evaluator reports `SchemaValidatorUnavailable`

The validator is optional in both SDKs. Run `npm install ajv` (8.17 or later) for `builtins.jsonSchema` in TypeScript, or `pip install 'hue-run[evals]'` for `builtin_scorers.json_schema` in Python; without it the Python helper raises `ImportError`. Other built-in evaluators do not need these packages. Separately, importing `@hue-run/sdk/evals` needs the optional `zod` peer (`npm install zod`, 4.6.5 or later).

## Listing eval-set cases fails for a large page

Evaluation clients cap responses at 4 MiB. A valid page of full cases can exceed that cap when inputs or references are large. Request a smaller explicit page limit and follow `nextCursor`, for example `client.listCases(versionId, { limit: 10 })` or `client.list_cases(version_id, limit=10)`. The local runner reads summaries and individual cases and does not use this full-case page path.

A response-size or connection failure does not prove that a mutation was rejected. Preserve its idempotency key and inspect the outcome before retrying application work.

## The trace is present but the evaluation fails

Check which outcome failed: the original application execution, the evaluator's execution, or the quality assessment. A boolean `false` is a valid scored result. Historical rescoring assesses frozen evidence and does not rerun your application.

## The MCP server rejects the agent

The MCP server accepts a **Read** or **Read and write** project key, or a Hue sign-in connection. For authentication, connection and tool-list issues, see [MCP troubleshooting](/agents/mcp-server#troubleshooting); for trace fields, limits and errors, see [Investigate production](/agents/investigate-production#limits-and-errors).

## Tracing is disabled or data is being dropped

Check `HUE_TRACING_ENABLED`, package versions, initialization failures and pending bytes and records. Safe initialization can disable tracing while application work succeeds. `429` means the minute allocation was exhausted; `503` can mean saturation, timeout or unavailable persistence. Respect `Retry-After`; do not repeat business work. See [production safety](/guides/production-safety#ingestion-limits).
