---
title: "Troubleshoot tracing"
description: "Diagnose project authentication, missing spans or content, streaming lifetime, and export failures."
---

Start by separating the application result from the telemetry result. A model request can succeed while its trace export fails, and a correctly recorded trace can contain an application error.

## The connection check fails

Confirm that the key belongs to the selected Hue project and has not been revoked. Use **Tracing only** for tracing and known-trace receipts, or **Read and write** when this process also calls evaluation APIs. Keep the project service key in the server process. Do not use a management token or place the key in browser code.

Both SDKs default to `https://app.hue.run`. If you override `baseUrl` or `base_url`, supply an origin. Do not append `/api` or the OTLP endpoint. The SDK adds its own paths. Hosted origins require HTTPS; loopback HTTP is supported for local development, and TypeScript accepts plain HTTP to another host only with `allowInsecureHttp: true`.

Report the error and project identity without printing the key or request authorization header. TypeScript's `HueConnectionError` carries the HTTP `status` when Hue answered and the underlying network, timeout or parsing error as `cause`.

## No trace appears

1. Verify the key with `checkConnection()` in TypeScript or `validate_project()` in Python.
2. Confirm that the operation is instrumented. A direct provider call emits no telemetry unless its integration or a manual span records it.
3. Finish the operation and await the SDK's flush before the process exits.
4. Inspect the same project in Hue. A session ID groups requests; it does not select the destination project.
5. Check exporter failures, rejected-record counts and queue limits.

An existing OpenTelemetry application should add Hue to the provider it already owns. Creating a second global provider can leave some instrumentations attached to the first one. Follow the [provider integration guide](/integrations/opentelemetry).

## A parent span is missing

Spans can arrive in separate batches, and children may arrive before their parent. Flush every participating provider and allow ingestion to complete. A parent can also be sampled out, excluded by instrumentation, or sent to a different collector. Preserve the original parent ID when diagnosing this; changing it would change the trace relationship.

An OpenTelemetry status of `Unset` means no explicit status was recorded. It is not itself an application failure.

## A trace stays running

With TypeScript SDK 0.7.0 or Python SDK 0.4.0 or later, Hue shows a trace as **Running** while one of its Hue or AI spans is still open, usually from about 1.5 s after that span begins, and it resolves in place when the finished spans arrive. When 15 minutes pass with no new span or log and no end has arrived, Hue shows **No end received** instead. Either a span is still running, or the process stopped before it exported its finished spans. Await the SDK's flush before the process exits. If a wrapping processor forwards span starts to Hue, it must also forward the ends of those spans. Any later span or log makes the trace running again.

## Input or output is missing

Check the explicit content setting. `captureContent: false` in TypeScript or `capture_content=False` in Python intentionally omits supported content fields in Hue helpers. Both SDKs also strip recognized GenAI, OpenInference, OpenLLMetry and Vercel AI SDK content attributes from every record on Hue's export path, including spans from third-party instrumentors on the same provider; the [compatibility matrix](/sdks/compatibility) lists the keys. To record inputs and outputs, set `captureContent: true` or `capture_content=True`, the recommended setting, unless an application or data policy forbids sending that content to another service.

Content must also be supplied by the instrumentation. The SDK does not reconstruct prompts, invent an output or estimate missing usage. JSON `null` is a recorded value; an absent output is different. Helper spans never record exception messages or stack traces, only `error.type` and the span status.

If you add third-party instrumentation, configure its own content controls too: unrecognized custom keys pass through, and the instrumentor may still send content to other exporters. Avoid placing private text in custom span names or arbitrary attributes, which cannot all be classified automatically.

## Streaming spans end too early

Keep the request span open while the stream is consumed, including tool execution and the final output. Awaiting only the initial stream object does not mean generation has finished.

In a serverless application, await the telemetry flush in the framework's supported after-response lifecycle. Do not shut down a shared provider after every request. Shut it down when the application stops.

## Flush reports a failure

TypeScript `flush()` throws `HueExportError` for rejected or failed export work. Python `force_flush()` returns `False` for an observed export failure, dropped record, instrumentation omission or timeout. Use the bounded safe variants in serving application lifecycles; see [production safety](/guides/production-safety). Inspect their sanitized status reports; do not discard those results.

Queues are bounded and held in memory. Process termination, queue overflow or sampling can lose records. A timeout does not prove the receiver rejected a request. Hue deduplicates exact completed-span and log replays, but rerunning application work or generating new IDs creates new records. Do not blindly retry an entire partially accepted batch; inspect its rejected-record counts and cause.

The receiver accepts bounded OTLP requests. The SDK splits batches, but oversized helper content is omitted and recorded as an instrumentation failure. Application work still runs; raw external records remain subject to receiver limits. Keep binary files out of span attributes; file storage and document evaluation have a separate lifecycle.

## The example throws `Cannot use import statement outside a module`

Node.js treats `.js` and `.ts` files as CommonJS unless the nearest `package.json` contains `"type": "module"`. Run `npm pkg set type=module` in the example directory, or name the file `first-trace.mjs` / `trace.mts`, then run it again. A CommonJS application on Node.js 22.12 or later can instead load the package with `require("@hue-run/sdk")`.

## Installation reports a dependency conflict

Check the [compatibility matrix](/sdks/compatibility). `@hue-run/sdk` core installs alongside AI SDK 6; pass `hueExperimentalTelemetry(hue)` as `experimental_telemetry` there, because the `hueTelemetry` adapter requires AI SDK 7 and throws a `TypeError` on AI SDK 6. Python accepts OpenTelemetry `>=1.40,<2` (1.44.0 is the certified combination and 1.40.0 the tested floor), so `hue-run` installs next to instrumentation packages on another OpenTelemetry 1.x release. Keep the application's existing instrumentation and use a standard OTLP exporter when its versions fall outside the tested SDK matrix; do not force an incompatible install.

## A JSON Schema scorer reports `SchemaValidatorUnavailable`

The validator is optional in both SDKs. Run `npm install ajv` (8.17 or later) for `builtins.jsonSchema` in TypeScript, or `pip install 'hue-run[evals]'` for `builtin_scorers.json_schema` in Python; without it the Python helper raises `ImportError`. Other built-in scorers do not need these packages. Separately, importing `@hue-run/sdk/evals` at all needs the optional `zod` peer (`npm install zod`, 4.6.5 or later).

## Listing dataset cases fails for a large page

Evaluation clients cap responses at 4 MiB. A valid page of full cases can exceed that cap when inputs or references are large. Request a smaller explicit page limit and follow `nextCursor`, for example `client.listCases(versionId, { limit: 10 })` or `client.list_cases(version_id, limit=10)`. The local runner reads summaries and individual cases and does not use this full-case page path.

A response-size or connection failure does not prove that a mutation was rejected. Preserve its idempotency key and inspect the outcome before retrying application work.

## The trace is present but the evaluation fails

Check which outcome failed: the original application execution, the scorer's execution, or the quality assessment. A boolean `false` is a valid scored result. Historical rescoring assesses frozen evidence and does not rerun your application.

## The MCP server rejects the agent

The [Hue MCP server](/agents/mcp-server) accepts a **Read** or **Read and write** project key, or a connection made by signing in with Hue. An unauthenticated `401` starts browser sign-in for an OAuth connection; for an existing connection, it can mean a missing, expired or revoked credential. Follow the [MCP troubleshooting guide](/agents/mcp-server#troubleshooting) for the remedy that matches your authentication method, then [verify the connection](/agents/mcp-server#verify-the-connection).

An unknown-tool error means the tool is not registered for this connection. Write tools are hidden for a **Read** key, an earlier sign-in approved with **Read**, and a URL with `?read_only=true`. Earlier names such as `list_datasets` and `get_experiment` are retired; find the current name for each in [retired tool names](/agents/mcp-server#retired-tool-names).

Results marked `truncated: true` were cut to the `max_chars` budget; lower `limit` or `max_spans`, raise `max_chars`, or fetch one object at a time. Recorded prompts and outputs are absent unless a tool is called with `include_content: true` and the application captured content. An empty search does not prove nothing happened; widen `since` or drop filters.

A `check_state` of `null` means trace checks do not apply to that trace: no version is active, trace-check consent is off, or the trace predates the version's activation. `list_trace_checks` shows the active version and whether consent is on. Empty `get_trace_check_results` for a recent window have the same causes, or the results are still pending; `get_trace_check_summary` counts pending traces. Intent buckets stay `pending` until the project publishes a taxonomy with AI intent classification on; `get_intent_taxonomy` and `get_intent_summary`'s `consent` show both. An `attention_state` of `null` means the trace is still running, has not been assessed yet, or comes from an evaluation run, which is never assessed. See [Investigate production](/agents/investigate-production#data-model).

## Tracing is disabled or data is being dropped

Check `HUE_TRACING_ENABLED` if your integration uses the documented kill switch, installed package versions, initialization failure counters, and pending bytes/record counts. Safe initialization intentionally returns a disabled client when setup fails, so application success alone does not establish tracing. HTTP 429 means the project's minute allocation was exhausted; 503 can mean admission saturation, a timeout or unavailable persistence. Respect `Retry-After`; do not repeat business work to regenerate a trace. See [production safety](/guides/production-safety#ingestion-limits).
