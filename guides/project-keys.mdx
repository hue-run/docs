---
title: "Project keys"
description: "Configure server-side authentication and verify which project receives your data."
---

Use a project service key for SDK requests and OpenTelemetry exports. Create it in **Settings → Integrations & API keys** within the project you want to use.

## Configure the application

Store the key as `HUE_API_KEY` in your server environment or secret manager. Pass it to the SDK constructor, as shown in the [quickstart](/quickstart). Hue constructors do not automatically load environment files.

For direct HTTP requests, authentication uses `Authorization: Bearer <project-service-key>`. The key determines the destination project. Resource attributes, observed user IDs and session IDs cannot select a different project.

## Understand access

A key either reads the project, reads and writes it, or only sends traces:

| Preset | Use it for | Access |
| --- | --- | --- |
| **Read** | A coding agent on the [Hue MCP server](/agents/mcp-server) | Reads project traces and recorded content, evaluations, review, intents, managed and local runs, artifacts, members, and keys. It cannot send telemetry or change project data. |
| **Read and write** | A trusted MCP client, CI job, evaluation worker, or source-capture process that also changes project data | Everything **Read** reaches, plus MCP writes, tracing, source capture, and evaluation, artifact, simulation, environment, and managed-run APIs. Append `?read_only=true` to the MCP URL to hide writes. Billing stays in Settings. |
| **Tracing only** | Application telemetry, connection checks, and known-trace receipts | Sends traces and logs. It cannot browse project data or use evaluation APIs. |

Choose **Tracing only** for a production application and store it as `HUE_API_KEY`: if it leaks, it can send telemetry but cannot read your traces, list members, or create keys. Create a separate **Read** key for a coding agent and configure it as `HUE_MCP_KEY` in the agent's MCP client, never in the application. Use **Read and write** only for a process that should change project data, such as an evaluation worker or an agent that authors evaluations, and keep it off production servers.

Keys created with earlier presets keep their access. **Coding agent (read-only)** and **Coding agent (read + evaluations)** keys now appear as **Read** and **Read and write**. **Tracing and evaluations** and **Source capture only** keys appear with a _(legacy)_ label; they keep working, but new keys use **Read and write** instead. Creating a new restricted key does not narrow an older credential.

Treat every key as a server credential. Keep it out of browser bundles, logs, source control and prompts. Owners and admins can create and revoke keys. A newly invited member needs an owner or admin to supply a key through the team's secret store.

A service key does not represent a signed-in Hue user. Review claim and submit on the [MCP server](/agents/mcp-server) bind to the key's creating verified member. Org invites and role changes stay in the application session. Trace browsing goes through that MCP server with a **Read** or **Read and write** key; the SDKs do not expose a general trace-search API.

## Verify and rotate

Call `hue.checkConnection()` in TypeScript or `hue.validate_project()` in Python. These send a project lookup without a trace and return the project identity. Confirm it matches the project you intend to use before exporting data.

When replacing a key, configure the replacement in the server's secret store, verify the connection, then revoke the old key in project settings. Never include either credential in a support report. A successful connection check validates project access; the first-trace check separately verifies instrumentation and delivery.

## Connection settings

Both SDKs default to `https://app.hue.run`. Omit `baseUrl` in TypeScript and `base_url` in Python for Hue Cloud. You do not need to choose or discover a different endpoint for a normal Hue Cloud integration.

For local development or another configured Hue deployment, pass a different origin through `baseUrl` in TypeScript or `base_url` in Python. If your application uses `HUE_BASE_URL`, read it explicitly and pass it to the constructor. SDKs do not load environment files automatically.

Supply an origin without credentials, an API path, query parameters or a fragment. HTTPS is required except for loopback HTTP. SDKs append their own paths; a standard OTLP exporter instead needs the full [signal endpoint](/integrations/opentelemetry).
