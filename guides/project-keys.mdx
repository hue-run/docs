Use a project service key for SDK requests and OpenTelemetry exports. Create it in **Settings → Integrations & API keys** within the project you want to use.

## Start without an account

[One-command setup](/guides/agent-setup) can provision a bounded metadata-only trial before you have a Hue account. Its anonymous credential is installation-scoped: it sends setup traces and verifies known receipts within the displayed limits, but it cannot export logs, capture content, browse traces, use evaluations or MCP, change settings, or act as a signed-in member.

Setup stores the credential in an ignored owner-only local file and never prints it. A short-lived, single-use private handoff lets a human link the installation later. New customers without an invitation use this private claim flow to verify their identity and adopt the trial project. It does not open unrestricted signup or change existing invitation and staff access. An existing user must explicitly select an organization where they are an owner or admin. Ordinary members cannot transfer the project into an organization.

Successful adoption or transfer preserves accepted telemetry and receipt history and revokes the anonymous value on the server. Rerun the local command to reconcile and atomically install the replacement setup-scoped credential. The linkage command verifies on `/api/v1/setup/traces/{traceId}/receipt` that the old value is refused before reporting success. Create ordinary **Tracing only**, MCP, or evaluation-capable keys separately after linkage; claim does not widen the setup credential.

The account-managed presets below apply after linkage or to a project you already own.

## Configure the application

Store the key as `HUE_API_KEY` in your server environment or secret manager. Pass it to the SDK constructor, as shown in the [quickstart](/quickstart). Hue constructors do not automatically load environment files.

For direct HTTP requests, authentication uses `Authorization: Bearer <project-service-key>`. The key determines the destination project. Resource attributes, observed user IDs and session IDs cannot select a different project.

## Understand access

Choose the preset that matches one caller:

| Preset | Use it for | Access |
| --- | --- | --- |
| **Tracing only** | Application telemetry, connection checks, and known-trace receipts | Sends traces and logs. It cannot browse project data or use evaluation APIs. |
| **Tracing and evaluations** | An application or CI process that traces and also manages datasets, scorers, experiments, simulations, environments, or managed runs | Includes tracing plus evaluation-family API access. It cannot browse arbitrary traces. |
| **Coding agent (read-only)** | The [Hue MCP server](/agents/mcp-server) | Reads project traces, evaluations, review, intents, managed and local runs, artifacts, members, and keys. It cannot send telemetry or change project data. |
| **Coding agent (read + evaluations)** | A trusted MCP client that should also write project data | Combines coding-agent reads with MCP writes for those surfaces, plus evaluation-family API access. Append `?read_only=true` to hide writes. Billing stays in Settings. |

Choose **Tracing only** for an application that only exports telemetry and store it as `HUE_API_KEY`. Choose **Tracing and evaluations** only when that process also uses evaluation APIs. Create a separate coding-agent key for the MCP server and configure it as `HUE_MCP_KEY` in the agent's MCP client, never in the application. Use **Coding agent (read-only)** unless the agent should write project data; then use **Coding agent (read + evaluations)**. Existing keys keep their access; creating a new restricted key does not narrow an older credential.

Treat either key as a server credential. Keep it out of browser bundles, logs, source control and prompts. Owners and admins can create and revoke keys. A newly invited member needs an owner or admin to supply a key through the team's secret store.

A service key does not represent a signed-in Hue user. Review claim and submit on the [MCP server](/agents/mcp-server) bind to the key's creating verified member. Org invites and role changes stay in the application session. Trace browsing for coding agents goes through that MCP server with a coding-agent key; the SDKs do not expose a general trace-search API.

## Verify and rotate

Call `hue.checkConnection()` in TypeScript or `hue.validate_project()` in Python. These send a project lookup without a trace and return the project identity. Confirm it matches the project you intend to use before exporting data.

When replacing a key, configure the replacement in the server's secret store, verify the connection, then revoke the old key in project settings. Never include either credential in a support report. A successful connection check validates project access; the first-trace check separately verifies instrumentation and delivery.

## Connection settings

Both SDKs default to `https://app.hue.run`. Omit `baseUrl` in TypeScript and `base_url` in Python for Hue Cloud. You do not need to choose or discover a different endpoint for a normal Hue Cloud integration.

For local development or another configured Hue deployment, pass a different origin through `baseUrl` in TypeScript or `base_url` in Python. If your application uses `HUE_BASE_URL`, read it explicitly and pass it to the constructor. SDKs do not load environment files automatically.

Supply an origin without credentials, an API path, query parameters or a fragment. HTTPS is required except for loopback HTTP. SDKs append their own paths; a standard OTLP exporter instead needs the full [signal endpoint](/integrations/opentelemetry).
