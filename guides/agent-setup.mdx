<Visibility for="humans">
  **Setting up Hue yourself?** Copy this prompt into your coding agent, such as Claude Code, Cursor or Codex, from your application's repository. The rest of this page is written for the agent.

  ```text Prompt wrap
  Set up Hue in this project. Use curl to read https://docs.hue.run/guides/agent-setup.md and follow it, and show me the plan before you change anything.
  ```

  Your agent shows you its plan and asks you to create a **Read and write** API key in Hue and store it yourself, so the key never goes into the chat. The key sends traces and runs evaluations. The agent then adds tracing, verifies a real request and connects the Hue MCP server. You sign in to Hue to approve that connection after you restart the agent, or in Codex and Conductor when you run the command the agent gives you; Cursor, VS Code, Windsurf and Gemini CLI use the same key instead.

  Don't have a Hue account yet? The Hue team sets up accounts: email [founders@hue.run](mailto:founders@hue.run) or book a time at [https://calendar.notion.so/meet/akethini/hue](https://calendar.notion.so/meet/akethini/hue).

  Prefer to set it up by hand? Start with [Installation](/installation).
</Visibility>

<Note>
  **If you are a coding agent:** this page is the complete setup; you don't need the documentation index above it. Start by checking whether the project already has a Hue key, as step 1 describes: check only that it is present and never read its value. Then, in your first reply, list the steps below that apply and, if step 1 applies, include its message to the user. Wait for the user before you install packages or change files. If the user has no Hue account yet, change nothing.

  These steps need network access to docs.hue.run, app.hue.run, mcp.hue.run and the npm or PyPI registry. If your sandbox blocks a command, ask the user to approve it instead of skipping the step. If the user pastes a key into the chat, don't use it or repeat it; suggest they delete that key in Hue and store a new one as step 1 describes.

## 1. Get your Hue API key

This setup uses one **Read and write** project key, stored as `HUE_API_KEY`. It sends traces, checks what Hue stored and runs evaluations. Claude Code, Codex and Conductor connect to the [Hue MCP server](/agents/mcp-server) in step 4 by signing in with Hue and need no key. A client that connects with a key instead reads the same key as `HUE_MCP_KEY`: Cursor, VS Code, Windsurf and Gemini CLI, a client that runs without a browser or must keep access past a sign-in's 30 days, and any client when the user asks for a key.

First find how the application already provides local secrets, without reading any values: an ignored env file it loads (such as `.env.local` or `.env`), or a secret manager that injects variables into commands (such as Doppler, 1Password or Infisical). If that workflow already provides a **Read and write** key as `HUE_API_KEY`, and as `HUE_MCP_KEY` when the client connects with a key, go to step 2. An existing `HUE_API_KEY` may be a **Tracing only** key; ask the user which preset it is. If it is **Read and write** but the client connects with a key and `HUE_MCP_KEY` is missing, ask the user to add `HUE_MCP_KEY` with the same value, then go to step 2.

Otherwise, tell the user, in this wording or close to it:

> Hue needs a **Read and write** API key from your Hue account. You create and store it yourself, so please don't paste it into this chat.
>
> 1. Sign in at https://app.hue.run, select the project that should receive this application's traces, open **Settings → Integrations & API keys** (https://app.hue.run/settings/integrations) and create a **Read and write** key. Members ask an owner or admin for one.
> 2. Store it as `HUE_API_KEY` in your secret manager, or run this in your own terminal from the repository root and paste the key at its hidden prompt: `npx --yes --package @hue-run/sdk@0.11.4 hue login --gitignore`
> 3. Tell me when it's stored. You don't need to run the next steps it prints; I'll do those.
>
> Don't have a Hue account yet? The Hue team sets up accounts: email founders@hue.run or book a time at https://calendar.notion.so/meet/akethini/hue. When your account is ready, paste the setup prompt again.

For a client that connects with a key, say "Store it as `HUE_API_KEY` and `HUE_MCP_KEY`" in item 2.

Don't run `hue login` yourself: it waits for the key at a hidden prompt. Never print, log or commit the key, and wait until the user says it's stored.

`hue login` checks the key against Hue, writes it to `.env.hue` as both `HUE_API_KEY` and `HUE_MCP_KEY`, and adds the file to `.gitignore` if it isn't ignored yet. It refuses a **Read** or **Tracing only** key and never prints the key. If the application loads another ignored env file, add `--env-path` with that file's path to the command in your message; add `--force` if the file already holds a different `HUE_API_KEY` or `HUE_MCP_KEY`.

No Node.js? The user skips the command and adds a `HUE_API_KEY=` line with the key to an ignored env file in an editor, and a `HUE_MCP_KEY=` line with the same key for a client that connects with a key.

## 2. Check the key

If the user ran `hue login` and it printed `Stored the key`, it has already checked the key. It also printed the key's project (`Evaluations access accepted for project "<name>"`): ask the user to confirm that is the project they intended, then go to step 3. Otherwise run this check without echoing the key. It sends the key only to app.hue.run and prints the key's project, not the key:

```sh
curl -s -w "\n%{http_code}\n" -H "Authorization: Bearer $HUE_API_KEY" https://app.hue.run/api/v1/projects/current
```

Load `HUE_API_KEY` the same way the application loads its environment, and wrap the command in `sh -c '…'` so the variable is expanded only after it is loaded. For example, use the secret manager's runner (`doppler run -- sh -c '…'`), `npx dotenv-cli -e <env-file> -- sh -c '…'` in a Node project or `uv run --env-file <env-file> -- sh -c '…'` in a uv project, where `<env-file>` is the file the key is in, such as `.env.local` or `.env.hue`.

This check sends no telemetry. `200` means the key works: tell the user the project `name` in the response and continue once they confirm it is the intended project. If it isn't, they create a key in the right project and store it again. `401` means the key is missing, mistyped or revoked: ask the user to check it, or create a new one and store it again, then check again. If the user can't sign in to Hue, they don't have an account yet: share the "Don't have a Hue account yet?" line from the step 1 message.

## 3. Add tracing

Use curl to read [Hue's skill](https://docs.hue.run/skill.md) on this site and follow it from **Choose the integration** through **Verify delivery** for the application's language and framework. Its **Get a Hue API key** section is already done. Hold its **Handoff** and come back here for step 4. The skill covers installing the SDK, choosing a capture policy, isolating serving requests from Hue and verifying a real request.

Set this up for complete traces. Hue can only show and evaluate what a trace records, so in the plan you show the user, recommend content capture (`captureContent: true` in TypeScript, `capture_content=True` in Python) and say that it sends prompts, responses and tool inputs and outputs to Hue. The user's go-ahead authorizes it under the skill's capture rule. If they decline, or an existing application policy forbids sending that content to another service, use metadata-only capture. Keep redaction and credential filtering either way. Instrument every request path that calls a model or tool, with model and tool child spans and the application's session identifier, not only the request you verify.

If the application already uses Langfuse or another OpenTelemetry destination, follow [Keep Langfuse and add Hue](/integrations/opentelemetry#keep-langfuse-and-add-hue). Add the second processor where the existing provider is constructed, preserve the existing AI SDK integration, and verify the same controlled request in both destinations. Do not upgrade the framework merely to add an exporter.

The SDKs don't load env files, so run the application through the same workflow as the check, for example its existing env loading, `node --env-file=<env-file>`, `uv run --env-file <env-file>` or the secret manager's runner, and keep reading `HUE_API_KEY` from the environment in code.

Keep the **Read and write** key on development machines. Before the application runs on a production server, tell the user to create a separate **Tracing only** key for that server's secret store; production code reads it from the same `HUE_API_KEY` variable.

## 4. Connect the Hue MCP server

This is the last step because most clients load a new MCP server only when they start. From the repository root, run the command for the user's client; for a Codex or Conductor sign-in, the user runs it.

Claude Code, Codex and Conductor sign in with Hue. The command is this, where `<client>` is `claude-code`, `codex` or `conductor`:

```sh
npx --yes --package @hue-run/sdk@0.11.4 hue mcp install --client <client> --auth oauth
```

Run it yourself for `claude-code`. Don't run it yourself for `codex` or `conductor`: it runs `codex mcp add`, which opens the Hue sign-in in the browser at once and waits up to 5 minutes for the user to approve it. Give the user the command in your final message instead, to run from the repository root in their own terminal.

Cursor, VS Code, Windsurf and Gemini CLI connect with the key as `HUE_MCP_KEY`. Run this, where `<client>` is `cursor`, `vscode`, `windsurf` or `gemini`:

```sh
npx --yes --package @hue-run/sdk@0.11.4 hue mcp install --client <client>
```

`hue mcp install` configures these four clients with a key only. If VS Code, Windsurf or Gemini CLI supports MCP sign-in, you can instead connect it with the sign-in settings in the **Any MCP client** tab of [Connect your client](/agents/mcp-server#connect-your-client); Hue does not accept Cursor's sign-in.

A sign-in connection can read and write every active project in the organization the user approves, within their role, for 30 days. When Claude Code, Codex or Conductor connects with a key for a reason step 1 names, run the key command for `claude-code`, `codex` or `conductor` with `--auth key`: without it, the command can sign these clients in instead, since sign-in is their default. That connection reads `HUE_MCP_KEY`, which `hue login` already stored; otherwise the user adds it as step 1 describes. For read-only access, the user creates a **Read** key and stores it as `HUE_MCP_KEY` instead, in the secret manager or with `npx --yes --package @hue-run/sdk@0.11.4 hue login --keys coding-agent --force --gitignore` (with the same `--env-path`, if step 1 used one), which replaces only `HUE_MCP_KEY` in the env file; then run the key command for the client, with `--auth key` for `claude-code`, `codex` or `conductor`.

With `--auth oauth`, the command writes only the server URL. With a key, it writes a server named `hue` that references `HUE_MCP_KEY` and never the key itself. `.mcp.json` (Claude Code) and `.cursor/mcp.json` (Cursor) are safe to commit; with a key, each teammate then needs their own key. For Codex and Conductor, the command runs `codex mcp add`, which writes `~/.codex/config.toml`, and for Conductor also `claude mcp add --scope user`; if your sandbox blocks that, ask the user to approve it. VS Code prompts for the key when the server starts, and for Windsurf the command prints a snippet to merge into the file it names. Without Node.js, use the instructions for the user's client in [Connect your client](/agents/mcp-server#connect-your-client); for a client without its own tab there, such as VS Code, Windsurf or Gemini CLI, use the **Any MCP client** tab's project-key settings.

The user restarts the client to load the server, so finish with one message that gives the user:

1. Your summary, in the form of the skill's **Handoff**. You have just configured the MCP server, so leave out the handoff's offer to connect it.
2. How to restart the client and finish connecting:
   - With `--auth oauth`, there is no key to load. The user restarts the client and completes sign-in with its authentication action. In Claude Code: `claude --continue`, approving the `hue` server when asked, then `/mcp`, select `hue` and choose **Authenticate**. In Codex: the user first runs the install command you gave them, in a terminal where they can use a browser, and approves the sign-in it opens. If that sign-in did not finish, they run `codex mcp login hue` once, as the command then says, rather than `codex mcp add` again. Then `codex resume --last`. In Conductor: the user first runs the install command the same way, then opens **MCP status** from the plug icon or `/mcp-status`, refreshes and uses **hue**'s authentication action, then starts a new agent session if the Hue tools don't appear. On Hue's consent page, the user checks the organization and chooses **Allow**. Add that if sign-in doesn't complete or the Hue tools don't load, you can connect with the key instead; then run the key command for the client with `--auth key` and give the user the key restart below. For Codex, run `codex mcp remove hue` first; for Conductor, run `claude mcp remove hue -s user` and `codex mcp remove hue` first.
   - With a key, load the key into the shell that starts the client, for example with `set -a; . ./.env.hue; set +a` for the env file the key is in, or start the client through the secret manager's runner. Then restart it from that shell: `claude --continue` for Claude Code, approving the `hue` server when asked; `codex resume --last` for Codex; or quit Cursor, reopen it with `cursor .` and turn on **hue** in its MCP settings. Restart any other client from that shell.
3. The prompt to send after the restart: `Use Hue MCP: call list_projects and confirm which project to inspect. Then call get_project_context and show its 5 most recent error traces with links. For an organization connection, pass the project's id or slug as project_id on each call after list_projects.`
4. What they can ask next, for example "What needs attention in the last 24 hours, and why?". [Investigate production](/agents/investigate-production) has the tool sequences for those questions.
5. Optionally, that they can keep the Hue skill in the project with `npx skills add hue-run/hue-sdk --skill hue`.
