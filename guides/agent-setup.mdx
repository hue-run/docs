The public Hue installation skill covers TypeScript, Python and existing OpenTelemetry setups. It is maintained in the [SDK repository](https://github.com/hue-run/hue-sdk) and mirrored here.

## Start your coding agent

Open your application in Codex, Claude Code, Cursor, or your preferred coding agent, then paste:

```text
Read https://docs.hue.run/skill.md?v=0.2.1 and use the Hue installation skill to add
tracing to this application. Also read https://docs.hue.run/guides/production-safety
and https://docs.hue.run/quickstart, then read the compatibility
and integration guides for this app's stack. Preserve app behavior,
model providers, streaming lifetime, and existing OpenTelemetry ownership.

Use TypeScript SDK >=0.1.5 or Python >=0.1.3. Verify the installed package;
do not use unreleased APIs or force incompatible dependency installation.
Initialize one safe client per serving process and wire an environment kill
switch. Start with metadata-only capture unless our team has already approved
content capture. Preserve existing redaction and third-party capture controls.
Use a tracing-only project key from the server secret store. Never print it.

Keep connection checks and strict receipt verification in a separate setup
command. Do not block application readiness or responses on Hue, or rerun
business operations when tracing fails. Use bounded safe lifecycle methods.
Test a collector outage, oversized capture, failed redactor and original agent
error: outputs/errors must be preserved and tools must execute exactly once.

Run relevant checks, exercise a real app request, flush its owning providers,
and verify its trace, known spans and expected field presence with the receipt API.
Inspect captured content/redaction in Hue if available; otherwise give me the
trace link. Report test evidence, installed versions, capture choice and any
remaining configuration or integration limits.
```

Hue is currently invite-only: your organization is provisioned by Hue, and its owner accepts the invitation, signs up and verifies their email. An owner or admin then creates a **Tracing only** key in **Settings → Integrations & API keys**. Configure `HUE_API_KEY` through your normal [secret workflow](/guides/project-keys); do not paste it into chat.

## Install the skill for future sessions

From your application directory, run:

```bash
npx skills add hue-run/hue-sdk --skill hue
```

The same skill is served at `https://docs.hue.run/skill.md` if your installer prefers a URL. Select the coding agent you use and follow the installer's prompts. Restart or reload your coding agent if it requires that to discover newly installed skills, then ask it to use the **Hue** skill. You can inspect the [public skill file](https://docs.hue.run/skill.md?v=0.2.1) before installing it.

Hosting the skill does not automatically load it into every agent. The startup prompt above explicitly asks the agent to read it; installing the skill makes it available to supported agents in later sessions. Neither step adds a dependency on the docs site to your running application.

## Connect the Hue MCP server

The skill teaches the agent how to integrate tracing. The [Hue MCP server](/agents/mcp-server) additionally lets it read your project's traces, spans, sessions, datasets and experiment results and verify delivery itself, from Claude Code, Cursor, Codex, VS Code and other MCP clients. It uses a separate **Coding agent (read-only)** key configured as `HUE_MCP_KEY` in the agent's MCP client, never in the application. Skill 0.2.1 uses the server's `verify_trace` and `get_trace` tools when they are connected and falls back to receipt evidence otherwise.

## What the agent still needs

- Access to your application code, its existing runtime and package manager.
- A provisioned Hue project and a tracing-only key configured through your server's secret workflow.
- Access from the server to Hue's telemetry endpoint, and permission to exercise an appropriate request for verification.
- Optionally, a coding-agent key in its MCP client so it can confirm stored traces and read evaluation results without your help.

The skill guides dependency checks, safe initialization, metadata-only capture by default, streaming lifetime, outage tests and stored trace verification. Wrapping an entry point alone does not automatically instrument its internal model and tool calls. The agent should use your framework's instrumentation or wrap those operations explicitly, and report any unsupported integration or missing access.

## Verify the result

The SDK guides explain [TypeScript trace verification](/sdks/typescript#verify-stored-trace-evidence) and [Python trace verification](/sdks/python#verify-stored-trace-evidence). A receipt confirms stored evidence; inspecting the trace checks the captured values and redaction.

Prefer manual integration? Follow the [quickstart](/quickstart) or use your [existing OpenTelemetry setup](/integrations/opentelemetry).
