Send a real trace to Hue with a local text transformation. No model provider or model credits are needed.

<Tip>
  Using a coding agent? [Agent setup](/guides/agent-setup) installs the SDK, adds tracing and connects the Hue MCP server for you.
</Tip>

<Note>
  This is a strict setup diagnostic: it intentionally fails if Hue is unavailable. For serving applications, use [TypeScript production setup](/sdks/typescript#production-setup) or [Python production setup](/sdks/python#production-setup).
</Note>

## Prerequisites

You need a Hue project and **Node.js 22 or 24** or **Python 3.10+**.

<Note>
To run these examples against a local OpenTelemetry Collector, follow [Send through a Collector](/integrations/opentelemetry#send-through-a-collector).
</Note>

Don't have a Hue account yet? The Hue team sets up accounts: email [founders@hue.run](mailto:founders@hue.run) or book a time at [https://calendar.notion.so/meet/akethini/hue](https://calendar.notion.so/meet/akethini/hue).

## 1. Create a project key

In [Hue](https://app.hue.run), select your project and open **Settings → Integrations & API keys** to create a **Tracing only** service key. Keep the key in your server environment.

Store the key as `HUE_API_KEY` in your server environment or secret manager.

See [Project keys](#project-keys) for access levels and rotation.

Requires Node.js 22 or 24 (Node.js 26 also runs in CI) or Bun 1.4. Run the command in your application's directory. For a new example, create a directory and run `npm init -y && npm pkg set type=module` first so that `import` statements work in `.js` and `.ts` files.

## 3. Configure your environment

In the same terminal, set:

```bash
export HUE_API_KEY=your_project_service_key
export HUE_CAPTURE_CONTENT=true
```

`HUE_CAPTURE_CONTENT=true` records prompts, responses, and tool inputs and outputs alongside timing and errors; set it to `false` for metadata-only traces. See capture settings for [TypeScript](/sdks/typescript#content-capture) and [Python](/sdks/python#content-capture).

## 4. Record a request

<Tabs>
  <Tab title="TypeScript / JavaScript">
    Create `first-trace.mjs`:

    ```javascript
    import { createHue } from "@hue-run/sdk";
    
    const apiKey = process.env.HUE_API_KEY;
    const capture = process.env.HUE_CAPTURE_CONTENT ?? "true";
    if (!apiKey || !["true", "false"].includes(capture)) {
      throw new Error("Set HUE_API_KEY and HUE_CAPTURE_CONTENT=true (recommended) or false");
    }
    
    const hue = createHue({
      apiKey,
      serviceName: "hue-first-trace",
      captureContent: capture === "true", // true records inputs and outputs; false sends metadata only.
    });
    
    try {
      await hue.checkConnection(); // Verify the key before sending a trace.
      let traceId;
      // Group the request and its tool call in one trace.
      const output = await hue.withSpan(
        "first-trace",
        async (span) => {
          traceId = span.traceId;
          const result = await hue.tool("uppercase", "Hello Hue", () => "Hello Hue".toUpperCase());
          span.setOutput(result);
          return result;
        },
        { input: "Hello Hue", sessionId: "hue-quickstart" },
      );
      await hue.flush(); // Wait for Hue to acknowledge the trace.
      console.log({ output, traceId });
    } finally {
      await hue.shutdownSafe({ timeoutMillis: 1000 }); // Do not replace the original diagnostic error.
    }
    ```

    Run `node first-trace.mjs`.
  </Tab>
  <Tab title="Python">
    Create `first_trace.py`:

    ```python
    import os
    from hue_sdk import Hue
    
    api_key = os.environ.get("HUE_API_KEY")
    capture = os.environ.get("HUE_CAPTURE_CONTENT", "true")
    if not api_key or capture not in ("true", "false"):
        raise ValueError("Set HUE_API_KEY and HUE_CAPTURE_CONTENT=true (recommended) or false")
    
    hue = Hue(
        api_key=api_key,
        service_name="hue-first-trace",
        capture_content=capture == "true",  # True records inputs and outputs; False sends metadata only.
    )
    
    try:
        hue.validate_project()  # Verify the key before sending a trace.
        # Group the request and its tool call in one trace.
        with hue.context(session_id="hue-quickstart"):
            with hue.span("first-trace") as span:
                span.set_input("Hello Hue")
                with hue.tool("uppercase") as tool:
                    tool.set_input("Hello Hue")
                    output = "Hello Hue".upper()
                    tool.set_output(output)
                span.set_output(output)
                trace_id = span.trace_id
        # Wait for Hue to acknowledge the trace before exiting.
        if not hue.force_flush():
            raise RuntimeError("Hue export failed; inspect hue.export_status")
        print({"output": output, "traceId": trace_id})
    finally:
        hue.shutdown_safe(timeout_millis=1000)  # Preserve any original diagnostic error.
    ```

    Run `python first_trace.py` in the activated environment.
  </Tab>
</Tabs>

The program checks the key before sending data, prints `HELLO HUE` and a trace ID after a successful flush, then shuts down the SDK. A rejected export causes the program to fail.

## 5. Inspect the trace

In the same Hue project, open **Traces** and match the printed trace ID. You should see:

- A root span named `first-trace` and a tool child named `execute_tool uppercase`.
- Session `hue-quickstart` and the recorded timing.
- Input `Hello Hue` and output `HELLO HUE`. With `HUE_CAPTURE_CONTENT=false`, the trace shows no input or output.

Export acknowledgement confirms receiver acceptance. Inspecting the stored trace verifies the complete setup.

## Project keys

Use a project service key for SDK requests and OpenTelemetry exports. Pass it to the SDK constructor. Hue constructors do not automatically load environment files.

For direct HTTP requests, authentication uses `Authorization: Bearer <project-service-key>`. The key determines the destination project. Resource attributes, observed user IDs and session IDs cannot select a different project.

### Access levels

A key either reads the project, reads and writes it, or only sends traces:

| Preset | Use it for | Access |
| --- | --- | --- |
| **Read** | A coding agent on the [Hue MCP server](/agents/mcp-server) | Reads project traces and recorded content, attention states, trace checks, evaluations, reviewed cases, intents, managed and local runs, artifacts, members, and keys, which covers production [recipes](/agents/mcp-tools#recipes). It cannot send telemetry or change project data. |
| **Read and write** | A trusted MCP client, CI job, evaluation worker, or source-capture process that also changes project data | Everything **Read** reaches, plus MCP writes, tracing, source capture, and evaluation, artifact, simulation, environment, and managed-run APIs. Append `?read_only=true` to the MCP URL to hide writes. Billing stays in Settings. |
| **Tracing only** | Application telemetry, connection checks, and known-trace receipts | Sends traces and logs. It cannot browse project data or use evaluation APIs. |

Choose **Tracing only** for a production application and store it as `HUE_API_KEY`: if it leaks, it can send telemetry but cannot read your traces, list members, or create keys. For key-based MCP access, configure the key as `HUE_MCP_KEY` in the agent's MCP client, never in the application. A **Read** key is enough for an agent that inspects the project and investigates production. Use **Read and write** only for a process that should change project data, such as an evaluation worker or an agent that authors evaluations, and keep it off production servers. On a development machine, one **Read and write** key can serve as both the evaluation `HUE_API_KEY` and `HUE_MCP_KEY`; `hue login` stores it under both names. Create separate keys when you want to revoke either use alone. The [MCP connection guide](/agents/mcp-server) also covers signing in without a key.

The [MCP access-level reference](/agents/mcp-tools#access-levels) lists the tools each access level exposes.

A service key does not represent a signed-in Hue user. Owner- and admin-only tools on the [MCP server](/agents/mcp-server) check the key's creating verified member, or for a sign-in connection the member who approved it. Org invites and role changes stay in the application session. Trace browsing goes through that MCP server with a **Read** or **Read and write** key or by signing in with Hue; the SDKs do not expose a general trace-search API.

Treat every key as a server credential. Keep it out of browser bundles, logs, source control and prompts. Owners and admins can create and revoke keys. A newly invited member needs an owner or admin to supply a key through the team's secret store. To connect an MCP client, any member can instead [sign in with Hue](/agents/mcp-server#sign-in-with-hue) without a key.

### Legacy presets

Keys created with earlier presets keep their access. **Coding agent (read-only)** and **Coding agent (read + evaluations)** keys now appear as **Read** and **Read and write**. **Tracing and evaluations** and **Source capture only** keys appear as **Tracing and evaluations (legacy)** and **Source capture (legacy)**; they keep working for their original APIs but cannot read project data through the MCP server, and new keys use **Read and write** instead. Creating a new restricted key does not narrow an older credential.

### Verify and rotate

Call `hue.checkConnection()` in TypeScript or `hue.validate_project()` in Python. These send a project lookup without a trace and return the project identity. Confirm it matches the project you intend to use before exporting data.

When replacing a key, configure the replacement in the server's secret store, verify the connection, then revoke the old key in project settings. Never include either credential in a support report. A successful connection check validates project access; the first-trace check separately verifies instrumentation and delivery.

## Connection settings

Both SDKs default to `https://app.hue.run`. Omit `baseUrl` in TypeScript and `base_url` in Python for Hue Cloud. You do not need to choose or discover a different endpoint for a normal Hue Cloud integration.

For local development or another configured Hue deployment, pass a different origin through `baseUrl` in TypeScript or `base_url` in Python. If your application uses `HUE_BASE_URL`, read it explicitly and pass it to the constructor. SDKs do not load environment files automatically.

Supply an origin without credentials, an API path, query parameters or a fragment. HTTPS is required except for loopback HTTP. SDKs append their own paths; a standard OTLP exporter instead needs the full [signal endpoint](/integrations/opentelemetry).
