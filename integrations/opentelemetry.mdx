Send existing OpenTelemetry records to Hue with an OTLP/HTTP exporter or Collector; no Hue-specific model wrapper is needed.

## Provider ownership

Your provider owns instrumentation and propagation; Hue stores what it sends.

- Hue never replaces global providers, propagators or context managers. Set `service.name`, `service.version` and `deployment.environment.name`; keep your sampler and W3C propagation. Run traces are labeled separately, hidden from production searches by default and linked from their run.
- Hue observes only instrumented calls; it does not proxy model providers, patch libraries or infer spans.
- Hue SDK `captureContent: false` or `capture_content=False` strips recognized content attributes, including third-party spans; custom keys pass through. Python `redactor` changes helper values; TypeScript `redact` runs on export. Other exporters and Collectors need their own controls.
- Hue processors send a separate provider copy; existing exporters and filters are unchanged. Test each destination with synthetic content.

## Configure the endpoint

Use a **Tracing only** key from **Settings → Integrations & API keys**; it determines the project. An attribute cannot select a project. Use **Read and write** only for evaluation APIs.

| Setting | Value |
| --- | --- |
| Trace endpoint | `https://app.hue.run/api/v1/otlp/v1/traces` |
| Log endpoint | `https://app.hue.run/api/v1/otlp/v1/logs` |
| Transport | OTLP over HTTP, protobuf or standard OTLP JSON |
| Authorization header | `Authorization: Bearer ` followed by your project service key |
| Optional compression | gzip |

Set complete signal endpoints; do not append another `/v1/traces` or `/v1/logs`. Keep authorization in server environment/secret storage.

Routes accept OTLP, not arbitrary JSON. Metrics and OTLP gRPC are unsupported. Logs provide trace-correlated evidence, not general log search.

        BatchSpanProcessor(

### Send through a Collector

Hue SDKs post to `<origin>/api/v1/otlp/v1/traces` and `/logs`. Add a separate receiver so standard exporters keep `/v1/traces` and `/v1/logs`. Disable [live-span placeholders](/reference/typescript#live-spans); generic receivers would forward them.

```yaml
receivers:
  otlp: # Standard exporters keep the default paths.
    protocols:
      http:
        endpoint: 127.0.0.1:4318
  otlp/hue-sdk: # The Hue SDKs post to their own paths.
    protocols:
      http:
        endpoint: 127.0.0.1:4319
        traces_url_path: /api/v1/otlp/v1/traces
        logs_url_path: /api/v1/otlp/v1/logs
```

```ts
const hue = createHue({ apiKey, serviceName: "my-agent", captureContent: true, baseUrl: "http://127.0.0.1:4319", liveSpans: false });
```

```python
hue = Hue(api_key=api_key, base_url="http://127.0.0.1:4319", service_name="my-agent", capture_content=True, live_spans=False)
```

The Collector replaces the SDK key, so `apiKey` / `api_key` can be a non-empty placeholder. Skip SDK checks and receipts; the Collector cannot answer. Without `liveSpans: false`, placeholders are sent once, then TypeScript warns or Python sets `export_status.live_spans_rejected` and stops.

## Existing JavaScript providers

Pass `redact` when creating the transport to scrub exported content; see [Redaction](/guides/redaction#existing-providers).

To keep provider ownership while using Hue content controls and diagnostics, attach its processors during construction. [Install the TypeScript package](/quickstart#typescript) and these dependencies:

```sh
bun add @opentelemetry/sdk-trace@2.11.0 @opentelemetry/sdk-logs@0.222.0 @opentelemetry/resources@2.11.0
```

Save as `otel.ts`. In an existing app, add processors to existing provider construction and retain global registration and propagation.

```ts
import { createHue, createHueTransport } from "@hue-run/sdk";
import { TracerProvider } from "@opentelemetry/sdk-trace";
import { LoggerProvider } from "@opentelemetry/sdk-logs";
import { resourceFromAttributes } from "@opentelemetry/resources";

const apiKey = process.env.HUE_API_KEY;
if (!apiKey) throw new Error("Set HUE_API_KEY in your server environment.");

const transport = createHueTransport({
  apiKey,
  serviceName: "existing-otel-demo",
  captureContent: true, // Keep recorded prompts, responses and tool inputs/outputs.
});
const resource = resourceFromAttributes({ "service.name": "existing-otel-demo" });
// Add Hue processors when constructing your application's providers.
const tracerProvider = new TracerProvider({
  resource,
  spanProcessors: [transport.spanProcessor],
});
const loggerProvider = new LoggerProvider({
  resource,
  processors: [transport.logRecordProcessor],
});
// Reuse these providers for Hue helpers and your existing instrumentation.
const hue = createHue({ transport, tracerProvider, loggerProvider });

try {
  await hue.checkConnection();
  const span = tracerProvider.getTracer("example.instrumentation").startSpan("example.work");
  try {
    span.setAttribute("example.operation", "verification");
    console.log("Trace ID:", span.spanContext().traceId);
  } finally {
    span.end();
  }
  // Export after the span ends, then inspect the delivery counters.
  console.log("Delivery counters:", await hue.flush());
} finally {
  try {
    await hue.shutdown();
  } finally {
    await Promise.allSettled([tracerProvider.shutdown(), loggerProvider.shutdown()]);
    await transport.shutdown();
  }
}
```

Run `node otel.ts` after setting your environment. An export rejection makes the command fail rather than reporting successful delivery. Hue does not register or replace a global tracer, logger, or context manager. An instrumentor that only uses global providers still needs your application's normal OpenTelemetry initialization.

Your providers own the resource in this mode: set `service.name`, `deployment.environment.name` and similar attributes on them. `resourceAttributes` on the transport options is ignored and reported as a `warning` issue. The Python SDK attaches the same way through `tracer_provider=` and `logger_provider=`; a provider Hue creates for the other signal reuses the borrowed provider's resource. See the [Python guide](/sdks/python#existing-opentelemetry-provider).

## Use with Langfuse

Keep Langfuse's instrumentation/exporter. Add Hue's processor to that provider at construction; preserve resources, sampling, propagation, processors and filters. See [Langfuse's OpenTelemetry guidance](https://langfuse.com/faq/all/existing-otel-setup).

For example, this is the change to an existing `NodeSDK` setup after installing `@hue-run/sdk` and saving the [email callback](/guides/redaction#typescript-example) as `redaction.ts`; keep the rest of that application's initialization:

```diff
+ import { createHueTransport } from "@hue-run/sdk";
+ import { redactEmails } from "./redaction.ts";

  const langfuseSpanProcessor = new LangfuseSpanProcessor();
+ let hueTransport: ReturnType<typeof createHueTransport> | undefined;
+ try {
+   hueTransport = createHueTransport({
+     apiKey: process.env.HUE_API_KEY ?? "",
+     enabled: process.env.HUE_TRACING_ENABLED !== "false",
+     serviceName: "my-agent",
+     captureContent: true,
+     redact: redactEmails,
+   });
+ } catch {
+   // Keep existing tracing available. Do not log the key or exception object.
+   try { console.warn("Hue tracing initialization failed"); } catch {}
+ }

  const sdk = new NodeSDK({
    spanProcessors: [
      langfuseSpanProcessor,
+     ...(hueTransport ? [hueTransport.spanProcessor] : []),
    ],
  });
```

This is an attachment example, not a replacement bootstrap or version certification. Create the optional transport inside a fail-open boundary and append only on success. Use framework processor configuration when it owns the provider; see [production setup](/sdks/typescript#production-setup).

Keep Langfuse AI SDK instrumentation: SDK 6 uses `experimental_telemetry`; SDK 7 uses its registered integration. Per-call `hueTelemetry()` replaces global integrations for that call. See [Langfuse setup](https://langfuse.com/integrations/frameworks/vercel-ai-sdk) and [compatibility](/sdks/compatibility).

Langfuse's `mask` hook does not redact Hue's copy. Apply policy to both exports, then inspect synthetic content in both. See [Langfuse masking](https://langfuse.com/docs/observability/features/masking) and [Hue capture policy](/guides/redaction#retention).

Hue reads Langfuse attributes directly. `langfuse.observation.type`, `.model.name`, `.usage_details`, `.input`, `.output`, `langfuse.session.id` and `langfuse.user.id` fill Hue fields when GenAI attributes are absent; GenAI wins. `langfuse.trace.name` names traces without request text; `langfuse.release` supplies `release` absent `service.version`. Metadata, environment, tags and levels stay raw; OpenTelemetry status marks failure. See the [field glossary](/agents/mcp-tools#field-glossary).

TypeScript `0.13.0` or Python `0.7.0+` strip recognized Langfuse content in metadata-only mode; earlier SDKs need producer or Collector controls. Metadata and custom fields pass through. Verify each independent capture policy; see [compatibility](/sdks/compatibility).

Test a real request with model and tool spans, preserved IDs and parentage and both exporters flushed by the host deadline. Check content and fields in both destinations. Hue's [trace receipt](/sdks/typescript#verify) checks span and field presence, not payload correctness or Langfuse delivery; also test errors and cancellation.

Exporters cannot recover truncated data. Instrument reductions when analysis needs original and retained results.

## Flush streamed responses in Next.js

In AI SDK 7, add Hue processors to existing providers at startup and retain the `hue` client/providers for the server lifetime.

The standalone diagnostic fails on setup errors. In serving apps, guard optional setup and use [production-safe initialization](/sdks/typescript#production-setup). `createHueSafe({ transport, tracerProvider, loggerProvider })` cannot catch `createHueTransport(...)` errors, so guard that call too.

In the route, import `consumeStream` from `ai` and `after` from `next/server`, and import the server-lifetime `hue` client from your telemetry module. Replace a standalone `after(flushTelemetry)` with this option inside your existing `createAgentUIStreamResponse` call:

```ts
consumeSseStream: ({ stream }) => {
  // Start reading immediately so generation can finish after the response returns.
  const consumed = consumeStream({ stream });
  after(async () => {
    try {
      // Wait for stream completion before exporting the final spans.
      await consumed;
    } finally {
      const delivery = await hue.flushSafe({ timeoutMillis: 1000 });
      if (!delivery.ok) {
        // Diagnostics must also be unable to break application cleanup.
        try {
          console.warn("Hue telemetry flush incomplete", {
            timedOut: delivery.timedOut,
            ...delivery.report,
          });
        } catch {}
      }
    }
  });
},
```

The reader starts immediately so completion and abort callbacks finish before export. Keep `request.signal` on generation; callbacks stay unchanged.

`hue.flushSafe()` flushes borrowed providers or transport, returns counters and waits at most one second. Timeout does not cancel third-party work; `transport.flush()` is strict.

Log delivery counters to an independent, non-throwing sink. Do not shut down shared transport per request. See the [AI SDK stream-abort guide](https://ai-sdk.dev/docs/troubleshooting/stream-abort-handling).

## Agent attributes

Hue preserves original resource, scope, status, events, links, dropped counts, typed attributes, and external trace and span IDs. It derives AI fields alongside those records using versioned normalization profiles.

Supported profile families include generic OpenTelemetry, GenAI conventions, OpenInference, OpenLLMetry, Vercel AI SDK 6 and 7, and Langfuse. A profile family is not a guarantee that every package version or API surface has been tested. The TypeScript adapter is verified with AI SDK and OTel pairs `7.0.99 / 1.0.99` and `7.0.100 / 1.0.100`.

Prefer current GenAI attributes when your instrumentation supports them, including `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`, and `gen_ai.usage.output_tokens`. Preserve unavailable fields as absent. Do not submit `0` for unknown usage or `null` for an output that was never captured.

A child can arrive before its parent, and a correlated log can arrive before its span. Preserve the same trace ID and the correct parent and span IDs across services. Root-span completion does not prove that the whole distributed trace has arrived. Evaluations use a pinned evidence revision.

## Attributes for coding agents

A coding agent that reads your traces over the [Hue MCP server](/agents/mcp-tools) can only filter and group by what the spans record. These attributes make its answers precise:

- **Mark failures.** Set OpenTelemetry status to `ERROR`; `error.type` or Langfuse `level` alone does not mark failure.
- **Record users and sessions.** Set stable `user.id` (or `enduser.id` / `langfuse.user.id`) across spans and sub-agents; suffixed IDs no longer group with the parent. Set `session.id` or `gen_ai.conversation.id` on the root. Langfuse propagates user IDs with TypeScript `propagateAttributes({ userId }, …)` or Python `propagate_attributes(user_id=…)`.
- **Name task types.** Set stable `hue.trace.name` or `langfuse.trace.name`; descriptive root span names also support query filtering.
- **Trace tools.** Set `gen_ai.tool.name` and, when captured, `gen_ai.tool.call.arguments` and `gen_ai.tool.call.result`.
- **Link sub-agents.** Propagate context within a trace or link a child root to its parent handoff span.
- **Record releases.** Set resource `service.version` (or `langfuse.release`) to compare deployments.
- **Separate environments.** Send development and staging to a separate project with its own **Tracing only** key.

## Trace checks and request timing

[Trace checks](/agents/mcp-tools#trace-checks) assess delegation, scope and omitted output; request timing measures time to a useful answer. They use recorded attributes and events, not inferred data, and require owner or admin consent plus an activated tested version. Run traces are excluded.

### Mark the root span

Put request attributes, timing events and the manifest on the request's root span. Hue reads them from the span carrying `hue.trace_checks`, or the parentless root when no manifest exists.

| Attribute | Value |
| --- | --- |
| `hue.request.id` | A non-empty string of up to 200 characters, unique per user request. |
| `hue.request.owner` | `true` on the one trace that owns the request. Sub-agent and background traces leave it out. |
| `hue.request.origin` | `foreground` when a user waits for the answer, `background` otherwise. Only foreground requests count toward request timing. |
| `hue.request.start_source` | Where the wait starts: `speech_end`, `submission` or `server_received` (the default). |
| `hue.request.clock_verified` | `true` when client timestamps are trustworthy. `speech_end` and `submission` need it; on `server_received`, a value other than `true` drops playback timing. |
| `hue.agent.release` | Optional release label of up to 200 characters, which `get_trace_check_summary` filters as `release`. |
| `gen_ai.request.model` | Optional model label, which `get_trace_check_summary` filters as `model`. |

Record root timing events with `hue.request.id`; Hue reads the earliest of each name and at most 128 events.

| Event | Records |
| --- | --- |
| `hue.request.speech_ended`, `hue.request.submitted`, `hue.request.received` | The start of the wait, matching `hue.request.start_source`. After a client start, a recorded `hue.request.received` must not precede it. |
| `hue.response.first` | The first response of any kind, such as an acknowledgement. |
| `hue.response.useful` | The first useful answer, available on the server. |
| `hue.response.playback_useful` | The first useful answer, played or shown to the user. |
| `hue.request.completed` | The end of the request. |
| `hue.request.interrupted` | The user interrupted; later responses do not count. |

Define useful answers; acknowledgements do not count. `first_useful_answer_ms` uses playback time when present, otherwise server time. Out-of-order events are incomplete.

```ts
import { SpanStatusCode, trace } from "@opentelemetry/api";

// The globally registered provider, as NodeSDK or provider.register() sets it.
// With a standalone provider, call provider.getTracer("support-agent") instead.
const tracer = trace.getTracer("support-agent");

export function handleRequest(input: string) {
  return tracer.startActiveSpan("agent.support_reply", async (root) => {
    const requestId = crypto.randomUUID();
    const mark = (name: string) => root.addEvent(name, { "hue.request.id": requestId });
    root.setAttributes({
      "hue.request.id": requestId,
      "hue.request.owner": true,
      "hue.request.origin": "foreground",
      "hue.agent.release": process.env.APP_RELEASE ?? "development",
    });
    mark("hue.request.received");
    try {
      const reply = await runAgent(input, { onFirstToken: () => mark("hue.response.first") });
      mark("hue.response.useful");
      return reply;
    } catch (error) {
      // A failed request is an error span; its timing then has no useful answer.
      root.setStatus({ code: SpanStatusCode.ERROR });
      throw error;
    } finally {
      mark("hue.request.completed");
      root.end();
    }
  });
}
```

Mark `hue.response.useful` when the answer is ready, not when sending a placeholder.

The example assumes `agent.support_reply` is root. If not, put attributes and events and the manifest on the active root Hue reads.

### Declare agent boundaries

Put one manifest on the root span's `hue.trace_checks` attribute: a JSON object or string up to 64,000 characters. It declares the request and every boundary; Hue infers none.

```json
{
  "version": 1,
  "requestKind": "task",
  "request": { "spanId": "<root span id>", "field": "attributes", "path": ["app.user_request"], "start": 0, "end": 64 },
  "authorization": [],
  "boundaries": [
    { "kind": "action", "spanId": "<tool span id>", "content": { "spanId": "<tool span id>", "field": "attributes", "path": ["gen_ai.tool.call.arguments"], "start": 0, "end": 120 } },
    { "kind": "delegation", "spanId": "<handoff span id>", "parent": { "spanId": "<root span id>", "field": "attributes", "path": ["app.user_request"], "start": 0, "end": 64 }, "content": { "spanId": "<handoff span id>", "field": "attributes", "path": ["app.delegated_task"], "start": 0, "end": 88 } }
  ],
  "linkedTraces": [{ "traceId": "<sub-agent trace id>", "parentSpanId": "<handoff span id>" }],
  "complete": true
}
```

- `requestKind` is `task` (requires an `action` boundary) or `conversation`. `request` identifies the whole user request; `authorization` identifies up to eight whole earlier messages authorizing extra work.
- `boundaries` lists up to 32 agent actions (`action_scope`), delegations (`delegation_scope`, parent task given to the delegating agent), or pre-use tool-output reductions (`output_omission`). A reduction points to its task, full original and retained outputs, code, next decision and later use. Delegation checks read the request plus each action and handoff.
- Each boundary's span carries the `hue.agent.role` attribute (`orchestrator` or `subagent`).
- Each boundary in the manifest names its span with `spanId`, plus `traceId` for a span in a linked trace.
- `linkedTraces` lists up to four child traces and their handoff spans. `complete: true` declares all request boundaries.

An `output_reduction` boundary has this shape, for code that trimmed a tool's result before the agent read it:

```json
{
  "kind": "output_reduction",
  "spanId": "<reduction span id>",
  "task": { "spanId": "<reduction span id>", "field": "attributes", "path": ["app.reduction_task"], "start": 0, "end": 40 },
  "original": { "spanId": "<tool span id>", "field": "attributes", "path": ["gen_ai.tool.call.result"], "start": 0, "end": 5120 },
  "retained": { "spanId": "<reduction span id>", "field": "attributes", "path": ["app.retained_output"], "start": 0, "end": 900 },
  "code": { "spanId": "<reduction span id>", "field": "attributes", "path": ["app.reduction_code"], "start": 0, "end": 300 },
  "decision": { "spanId": "<next model span id>", "field": "attributes", "path": ["app.decision"], "start": 0, "end": 200 },
  "use": { "spanId": "<reply span id>", "field": "attributes", "path": ["app.final_reply"], "start": 0, "end": 480 }
}
```

The `original` and `retained` references cover the whole output; `task`, `code`, `decision` and `use` identify the reduction purpose, code and downstream use.

A source reference names a 16-hex `spanId` (and linked `traceId`), `field` (`input`, `output` or `attributes`), key/index `path`, and half-open UTF-16 `start` and `end` offsets in the exact recorded string (max 8,000 chars). A string attribute (`field: "attributes"`, path=key) keeps offsets exact; use its length for a whole-value reference. The model reads only referenced text, up to 16,000 chars per check.

Checks read the manifest and named spans and, in linked traces, the first span plus handoff continuation—not every trace span. Trace size is not the cap: at most 128 spans are read, each with attributes, input and output up to 64 KiB. Missing or invalid manifests or over-limit evidence yield `unavailable`; delegation is `not_applicable` without task actions or handoffs, and other checks when no boundary is declared.

## Content capture

Capture and redact content in your instrumentation or Collector; Hue cannot reconstruct omitted data. For SDK capture options, see the [TypeScript](/sdks/typescript) and [Python](/sdks/python) guides.

## Collector responses

Keep requests at or below 4 MiB on the wire and 8 MiB after decompression. An individual OTLP value can contain up to 1 MiB. Hue cuts oversized text values at a UTF-8 character boundary and replaces oversized structured values with a truncation marker. The `hue.truncated` attribute lists the affected keys. Oversized requests return HTTP 413.

Hue indexes up to 10,000 spans and 20,000 correlated logs per trace. Records beyond those index limits remain stored in the trace's evidence segments and counted on the trace.

An otherwise valid batch can receive an OTLP partial-success response containing rejected-record counts. Configure your exporter monitoring to inspect that response; HTTP 200 alone does not prove that every record was accepted. Hue SDKs surface those failures through their flush APIs. Partial rejection must not trigger a blind replay of the whole batch.

Exact completed-span replays are deduplicated within the project. A different payload for the same completed span ID is rejected. Logs have no universal event ID, so exact duplicate records collapse; include their actual timestamps and correlation data. These rules do not make the client's in-memory queue durable.
