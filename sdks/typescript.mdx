Use the Hue TypeScript SDK to trace your server-side application, tools, and model integrations. Your application continues to call the model provider directly.

For option defaults and method signatures, see the [TypeScript API reference](/reference/typescript). Check the [compatibility matrix](/sdks/compatibility) before adding Hue to an existing application.

## Install

Use Node.js 22 or 24, or Bun 1.4. [Install the TypeScript SDK](/quickstart#typescript), then configure your key below. The package is ESM; CommonJS applications on Node.js 22.12 or later load it with `require("@hue-run/sdk")`. Check the [compatibility matrix](/sdks/compatibility) if your application already uses AI SDK or OpenTelemetry. Besides the core entry point, the package exposes `@hue-run/sdk/ai-sdk`, `@hue-run/sdk/evals`, `@hue-run/sdk/environment` and `@hue-run/sdk/managed`. Since TypeScript 0.16.0, `@hue-run/sdk/evals` includes `zod` as a regular dependency; [simulations](/evaluations/simulations) use it together with `@hue-run/sdk/environment`.

## Configure your project

Create a **Tracing only** project service key in **Settings → Integrations & API keys**. Put it in your server environment as `HUE_API_KEY`. Keep environment files out of Git and never expose this key to a browser.

**Tracing only** covers ingestion, connection checks, and known-trace receipt verification. Use **Read and write** when the same process also creates eval sets, evaluators, runs, simulations, environments or managed runs. See [Project keys](/quickstart#project-keys) for access and rotation.

Hue Cloud is the default destination; no base URL is needed. See [connection settings](/quickstart#connection-settings) when using another origin. HTTPS is required except for loopback HTTP. `allowInsecureHttp: true` permits plain HTTP to another host, such as a docker-compose or in-cluster collector, and records a one-time warning issue because the key then travels unencrypted. The SDK reads no `OTEL_EXPORTER_OTLP_*` environment variables; pass configuration explicitly.

`serviceName`, `serviceVersion` and `resourceAttributes` (for example `{ "deployment.environment.name": "production" }`) describe the deployment on a client that owns its providers; `serviceName` and `serviceVersion` take precedence over same-named keys. When you attach Hue to your own providers, they own the resource and `resourceAttributes` is ignored with a warning issue.

## Send your first trace

Save this as `trace.ts` in a package whose `package.json` contains `"type": "module"` (or name the file `trace.mts`). It traces a deterministic uppercase tool; it makes no model call.

```ts
import { createHue, HueExportError } from "@hue-run/sdk";

async function main() {
  const apiKey = process.env.HUE_API_KEY;
  if (!apiKey) throw new Error("Set HUE_API_KEY in your server environment.");

  const hue = createHue({
    apiKey,
    serviceName: "uppercase-demo",
    captureContent: true, // Record inputs and outputs alongside timing and metadata.
    onExportIssue: (issue) => {
      console.error("Hue export issue", issue.kind, issue.signal, issue.count);
    },
  });

  try {
    await hue.checkConnection(); // Verify which project the key belongs to.
    // The tool call becomes a child of this request span.
    await hue.withSpan(
      "demo.run",
      async (run) => {
        const result = await hue.tool("uppercase", "hello", () => "hello".toUpperCase());
        run.setOutput(result);
        console.log("Trace ID:", run.traceId);
      },
      { sessionId: "demo-session", input: "hello" },
    );
    const report = await hue.flush(); // Confirm delivery before the process exits.
    console.log("Acknowledged spans:", report.acceptedSpans);
  } finally {
    await hue.shutdownSafe({ timeoutMillis: 1000 });
  }
}

try {
  await main();
} catch (error) {
  if (error instanceof HueExportError) {
    console.error("Hue did not acknowledge all telemetry", error.report);
  } else {
    console.error("The example failed. Check your connection and server configuration.");
  }
  process.exitCode = 1;
}
```

Run it with your environment already configured:

```sh
node trace.ts
```

Open **Traces** in the project that owns the key. The root span and its `execute_tool uppercase` child share the printed trace ID. With `captureContent: true`, both spans show the input `hello` and the output `HELLO` alongside timing and identity metadata.

`checkConnection()` rejects with `HueConnectionError` when the key or origin is wrong. Its fixed message is safe to log; `status` carries the HTTP status when Hue answered, and `cause` carries the underlying network, timeout or parsing error.

## Content capture

For a copyable email-masking callback and guidance on custom field rules, follow [Redaction](/guides/redaction).

`captureContent` defaults to `true` for an enabled client; set it to `false` to opt out. Use `true`: Hue can only show and evaluate what a trace records. Use `false` for metadata-only capture when you'd rather not send content, or when an application or data policy forbids sending it to another service. A disabled client (`enabled: false`) exports nothing and defaults it to `false`.

- `true`, the recommended setting, captures content you provide to supported helpers and instrumentations: prompts and messages, responses and tool inputs and outputs, alongside model, usage, timing and errors. Hue stores received content under your project’s [retention policy](/guides/redaction#retention). Before export, the SDK scrubs credentials in recorded tool definitions and uploads binary media and text media over 64 KiB in recorded messages; see the [content policy](/reference/typescript#content-policy).
- `false` disables Hue helper content and removes recognized GenAI, Vercel AI SDK, OpenInference, and OpenLLMetry content fields before Hue exports them, including spans from other instrumentations on a shared provider. It also removes log bodies, status descriptions and exception text. The exported `contentPrefixes` array lists the removed keys.
- `redact(value, path)` can transform supported strings before export. Redactor and capture failures omit unsafe content and increment instrumentation failure counters without changing application results.

Helper spans record a failed callback's `error.type` (the error's `name`), an ERROR status and an `exception` event carrying only the type. Exception messages and stack traces are never recorded, whatever `captureContent` is; keep them in application logs.

Queued records snapshot supported values when a span ends or a log is emitted, so later caller mutation cannot increase the retained queue size or change exported data. Resource attributes still awaiting detection are omitted with a sanitized warning; later records include them once detection finishes. Await resource detection before instrumentation if those attributes are required.

Custom attribute names cannot be classified automatically. Keep secrets and unnecessary user content out of span names, identifiers, resource metadata, and arbitrary attributes. The setting applies to Hue's export path, not another exporter in your application.

Missing usage stays missing: the SDK does not estimate tokens or cost. Captured JSON `null`, `false`, `0`, and an empty string remain distinct from absent content.

## Images, documents and audio

Hue stores the bytes of images, documents and audio apart from the records that mention them, named by SHA-256. The record keeps each file's digest in its place and lists the upload in its `hue.blobs` attribute. Files reach Hue in four ways:

| You have | Use | The record carries |
| --- | --- | --- |
| Files inline in the messages and values your code or framework already records | Nothing: [automatic capture](#automatically-captured-media) | The part in digest form, keyed `<attribute>#<JSON pointer>` |
| A file to place at a position in a value you record | [`Attachment`](#attach-a-file-anywhere) | A GenAI `blob` part in digest form, keyed `<attribute>#<JSON pointer>` |
| A file the work read, received or produced, outside any recorded value | [`recordFile`](#record-a-file) with `upload: true` | A `hue.file` event, keyed `event:hue.file:<sha256>` |
| Files a case's agent and evaluators receive | [Case files](#files-in-evaluation-cases) | Files pinned on the case, not in a trace |

Every upload needs `captureContent: true` and a project key, never a setup credential (`hue_setup_…`). `redact` runs first: nothing it removes is uploaded, and a value it rewrites uploads as rewritten. Uploads share the export's upload budget, and a file used more than once in a trace is stored once. A file that cannot be uploaded falls back without failing the export and counts in `uploadFallbacks` in `hue.transport.getReport()`. See [Images, audio and documents](/integrations/opentelemetry#images-audio-and-documents) for what the trace view previews, and [Read recorded media back](#read-recorded-media-back) to get the bytes again.

### Automatically captured media

With `captureContent: true`, the SDK finds files inline in these attributes of a span, uploads their bytes under the span's trace and leaves each file's digest in its place:

- **Messages and values:** `gen_ai.input.messages`, `gen_ai.output.messages`, `ai.prompt.messages`, `ai.prompt`, `input.value` and `output.value` (what `withSpan` records), `traceloop.entity.input` and `traceloop.entity.output`, and Langfuse's `langfuse.observation.input`, `langfuse.observation.output`, `langfuse.trace.input` and `langfuse.trace.output`.
- **Tool arguments and results:** `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result`, `ai.toolCall.args`, `ai.toolCall.result`, `tool.parameters`, `tool_arguments` and `tool_response`.
- **Metadata:** `metadata`, `langfuse.observation.metadata` and `langfuse.trace.metadata` (whole, or one `.<key>` per attribute), and `ai.telemetry.metadata.<key>`.
- **Indexed messages:** OpenLLMetry's `gen_ai.prompt.<n>.content` and `gen_ai.completion.<n>.content` when the value is the JSON of a parts list, and OpenInference's flattened `llm.input_messages.<n>.message.contents.<m>.message_content.image.image.url` and its `llm.output_messages` counterpart.

Inside those values the SDK recognizes GenAI `blob` parts, AI SDK `file` and `image` parts, OpenAI Chat image, file and audio parts and an assistant message's `audio`, Responses `input_image`, `input_file` and `computer_screenshot`, Anthropic base64 sources, Gemini `inlineData` and `inline_data`, Vertex `media`, Bedrock image and document sources, and any whole string that is a `data:` URL declaring a media type. Files inside a tool call's JSON-encoded `arguments` and a tool result's JSON string are found too.

Each uploaded file takes one of these forms:

- A provider part loses its byte field and carries `sha256` and `size`, keyed at the part, for example `gen_ai.input.messages#/0/parts/1`. An OpenAI assistant message's `audio` loses `audio.data`, and the message carries the digest.
- A whole `data:` URL string becomes a GenAI `blob` part, `{"type":"blob","mime_type":"image/png","modality":"image","sha256":"<64 hex>","size":68}`, keyed at the string. A text data URL up to 64 KiB stays inline.
- A file inside a JSON-encoded tool string takes the digest form inside the string. No JSON pointer can address inside a string, so Hue matches it by digest.
- Text media over 64 KiB of decoded bytes keeps a UTF-8-safe 16 KiB prefix in its content field, keyed at that field, for example `gen_ai.input.messages#/0/parts/1/content`. Smaller text stays inline. A text file that a GenAI `blob`, Vertex `media`, or AI SDK `file` or `image` part holds as bare base64 is decoded first, as Hue reads it: over 64 KiB of decoded bytes, it uploads and takes the digest form at the part, like binary media.

Only the file's own value, or the members of the part that held it, change; the rest of the recorded JSON text is kept byte for byte. A record lists at most 64 files in `hue.blobs`: its inline media first, in reading order, then its attachments and uploaded files. A file that is not uploaded keeps its digest without an entry in `gen_ai.input.messages`, `gen_ai.output.messages` and `ai.prompt.messages`; in any other attribute it keeps its bytes inline, under the ordinary value limit.

The SDK leaves these as recorded:

- Remote URLs, provider file IDs, S3 references and Langfuse media tokens. Neither the SDK nor Hue fetches them.
- A file more than ten levels below a value's root, attribute JSON nested past 32 levels or holding an integer past 2^53 (Hue keeps such JSON as text), and an OpenInference `input.value` or `output.value` whose record declares it `text/plain`.
- In a log record, text past 8 Mi UTF-16 code units in one attribute or 16 Mi in one record; such a value follows the ordinary value limit.

A span's own attribute past those bounds, such as a model call that carries minutes of base64 audio, is still read for files when it is exported, without parsing or copying the whole value. Each base64 or `data:` URL string in it that is longer than 16 Ki code units and written without escapes is decoded, hashed and uploaded a 1 MiB slice at a time, up to 1 GB, and takes the same digest form as above. The rest of the value's JSON must fit within 8 Mi code units; a value past that follows the ordinary value limit.

With `captureContent: false`, the SDK inspects and uploads nothing.

Log records correlated with a span upload their media the same way: the `gen_ai.client.inference.operation.details` record `recordMessages()` writes, and any `gen_ai.*` event with a structured body. The log record lists its files in its own `hue.blobs`, keyed `body#<JSON pointer>` into the body, for example `body#/gen_ai.input.messages/0/parts/1`. A log record that cannot upload, such as one not correlated with a span, keeps the older rule: a file over 64 KiB in a recorded message becomes its digest, and other files keep their bytes. Resources, links and span events never upload; in their recorded messages, media up to 64 KiB stays as recorded and larger media becomes its digest.

An entry's `name` comes from the part's file name, name or title when it is valid: nonblank after trimming, at most 256 UTF-16 code units and well-formed Unicode, with no C0 control characters (U+0000–U+001F) or DEL (U+007F). An invalid name stays in the message and is left out of the entry. Data URLs and fields the provider encodes as base64 are decoded before hashing, so a part's digest matches `recordFile`'s digest of the same bytes. Another string with a declared textual media type is hashed as UTF-8: `YWJj` hashes as those four characters.

### Attach a file anywhere

Wrap a file in an `Attachment` and put it in any value Hue records: a `withSpan()` input or output, `model()` messages, a tool's arguments or result, `recordMessages()` messages, or a `withSpan()` attribute (`SpanOptions.attributes`).

```ts
import { readFile } from "node:fs/promises";
import { Attachment } from "@hue-run/sdk";

const png = await readFile("scan.png");
await hue.withSpan(
  "review contract",
  (span) => {
    span.setInput({
      question: "Which clauses changed?",
      contract: new Attachment({ path: "contract.pdf", contentType: "application/pdf" }),
    });
  },
  { attributes: { metadata: { scan: new Attachment({ data: png, contentType: "image/png" }) } } },
);
```

Give exactly one of `data` (bytes, or a base64 string or `data:` URL) and `path`, a `contentType` and an optional `name`. `data`, limited to 25 MiB, and a file up to 25 MiB given by `path` are read and hashed when the attachment is created and stay in memory until export, within the 128 MiB held for values awaiting upload. A larger file given by `path`, up to 1 GB, is hashed when the attachment is created and streamed from disk when it uploads, so it is never held in memory. Keep such a file in place and unchanged until the client flushes: a file that changed or is gone by then is not uploaded and counts in `uploadFallbacks` in `hue.transport.getReport()`.

At its position the attachment is recorded as a GenAI `blob` part in digest form, `{"type":"blob","mime_type":"application/pdf","modality":"document","sha256":"<64 hex>","size":48213,"name":"contract.pdf"}`, with `modality` read from the content type. Export uploads the bytes, keyed `<attribute>#<JSON pointer to the part>`: `input.value#/contract` and `metadata#/scan` above, or `body#/gen_ai.input.messages/0/parts/1` in a `recordMessages()` log record. An attribute value that is an attachment, or a JSON object or array OpenTelemetry cannot hold, is recorded as JSON text. Put files under `metadata` for Hue to list them as the span's metadata files. A value that is still over the 1 MiB inline limit with its attachments as digest parts uploads whole and keeps only its first 16 KiB inline: the attachments' bytes are stored, and `client.media.fetch({ traceId, sha256 })` reads them by digest, but readers do not place them at their positions in the value.

With `captureContent: false` or a setup credential (`hue_setup_…`), no bytes leave the process: a metadata attribute keeps the part without its name, and content values are not recorded. A part that `redact` removes or rewrites is not uploaded. A part that cannot be uploaded, or that sits more than 10 levels deep in its value, keeps its digest and counts in `uploadFallbacks` in `hue.transport.getReport()`. Creating an attachment never fails: one without exactly one of `data` and `path`, with unreadable or oversized data, or with an invalid content type is recorded as `null` and counted as an instrumentation failure. An invalid name alone is omitted and counted.

### Record a file

To record a file your application reads or produces, such as the audio of a voice turn, call `recordFile` inside a span:

```ts
await hue.withSpan("voice turn", async () => {
  hue.recordFile({
    role: "input",
    mediaType: "audio/wav",
    path: "turns/0042-user.wav",
    name: "user.wav",
    upload: true,
  });
  hue.recordFile({
    role: "output",
    mediaType: "audio/wav",
    path: "turns/0042-reply.wav",
    name: "reply.wav",
    upload: true,
  });
});
```

Give the file as `data` (bytes, up to **25 MiB**, held in memory until export) or `path` (a file on disk, up to **1 GB**; a file over 25 MiB is streamed from disk when it uploads, as an [attachment given by path](#attach-a-file-anywhere) is). All uploads of one export share six export timeouts, 60 seconds at the default `timeoutMillis` of 10,000, so a 1 GB file needs about 17 MB/s; raise `timeoutMillis` (up to 60,000) for slower links. Record audio in a format the trace view plays, such as WAV, MP3 or Opus; [wrap raw PCM in a WAV header](/integrations/opentelemetry#attach-a-voice-turn) first. `upload` defaults to `false`. With `upload: true`, content capture and an ordinary project key, export uploads the bytes and adds an entry keyed `event:hue.file:<sha256>` to the same span. The `hue.file` event still records the digest, role, media type and size, and its name follows the rule above: an invalid name is left out and counted as an instrumentation failure. An upload that is not made counts in `uploadFallbacks` in `hue.transport.getReport()`. A span's own string attributes have a separate **1,000,000,000-byte (1 GB)** upload limit.

### Read recorded media back

The evaluation client's `media` reads a recorded file back by its digest. Use a **Read** or **Read and write** key; reading a trace snapshot's pinned copy needs **Read and write**.

```ts
import { createEvaluationClient } from "@hue-run/sdk/evals";

const client = createEvaluationClient({ apiKey: process.env.HUE_API_KEY! });

// One file by digest; pass the span that recorded it when you know it.
const file = await client.media.fetch({ traceId, spanId, sha256 });
console.log(file.contentType, file.fileName, file.size, file.bytes.length);

// Every digest part of a recorded value, written back in its own field.
const recorded = JSON.parse(attributes["gen_ai.input.messages"]);
const { value: messages, failures } = await client.media.resolve(recorded, { traceId, spanId });
```

`client.media.fetch({ traceId, sha256 })` asks Hue for the five-minute link the [trace file endpoint](/integrations/opentelemetry#download-files-from-a-trace) returns, downloads it without the project key and refuses bytes whose SHA-256 is not the digest. A failure raises `MediaFetchError` with a `reason`: `not_found`, `missing` (listed but never uploaded, or erased), `unavailable`, `forbidden` (the key cannot read recorded content; a snapshot's copy needs **Read and write**), `too_large` (over `maxBytes`, 64 MiB by default), `digest_mismatch` or `failed`. `{ snapshotId, sha256 }` reads a snapshot's pinned copy, which carries no media type or name. `fetch` also reads a file that a producer without the SDK recorded inline, as a `data:` URL or base64 part of up to 1 MiB; pass `spanId` for one in a log record.

`client.media.resolve(value, { traceId })` downloads each distinct digest once and returns a new value, leaving the input unchanged. With `as: "dataUrl"`, the default, each part gets a `data:` URL where its field takes one and bare base64 where its convention requires it, so the messages can be sent to the provider again; `as: "bytes"` writes the bytes. A part whose file cannot be read stays as it is and is listed in `failures` with its JSON pointer and reason. Text over 64 KiB that the record keeps as its first 16 KiB is never written back: pass the record's `hue.blobs` entries as `blobs`, and such a part is listed as `prefix_only`, with the SHA-256 that `fetch` reads the whole file by. Parts inside JSON-encoded strings and Langfuse media tokens are left as they are. See the [reference](/reference/typescript#recorded-media) for every option.

### Files in evaluation cases

`addCase` and `addEvalSetCase` pin up to 32 input files on a case with `files`. Name an artifact the project already holds as `{ artifactId, role }`, or give the file as `{ role, filename, contentType, bytes }` or `{ role, filename, contentType, path }`. The client checks an uploaded file against the artifact policy (one of the [`outputContentTypes`](/reference/typescript#file-based-cases), a name of 1 to 255 UTF-16 code units, 1 byte to 25 MiB) and uploads it as a verified artifact before the case; sending the same case again reuses it. A file outside the policy, or a `path` that cannot be read, throws `TypeError` or `RangeError` before any request. A file given by `path` is hashed when the case is checked and read again when it uploads, one file at a time; if it changed after the check or can no longer be read, none of its bytes are uploaded, the write throws `TypeError` and the case is not written. Files uploaded before it stay as artifacts, which sending the case again reuses.

Before an execution starts, `runExperiment` downloads the case's pinned files and checks each one's size and SHA-256. The target receives the agent-visible files (`source`, `attached_template`, `attached_reference` and `original`) as `context.files`; `org_template` and `evaluator_reference` files reach only evaluators. Recorded messages copied into a case's inputs keep their files as digest parts, and `rehydrateMedia(inputs, files)` writes the case's files back into them by SHA-256:

```ts
import { rehydrateMedia } from "@hue-run/sdk/evals";

// A runExperiment target: send the recorded model call again with the case's real files.
async function target(inputs, { files }) {
  const { value } = await rehydrateMedia(inputs, files);
  return callModel(value);
}
```

| Langfuse | Braintrust | Hue |
| --- | --- | --- |
| Traces already recorded in a Langfuse project | | [`hue import langfuse`](/sdks/cli#import-traces-from-langfuse), run with your Langfuse keys |
| Base64 data URIs in an observation's input, output or metadata | | [Automatic capture](#automatically-captured-media), for the attributes and shapes listed there |
| `LangfuseMedia` | `Attachment` | [`Attachment`](#attach-a-file-anywhere), at the same position |

| | `JSONAttachment` | Nothing: a span's own string attribute over the inline limit uploads whole, up to 1,000,000,000 bytes |

## Model spans and context

When you call a provider SDK directly, `hue.model(model, callback, options)` creates the GenAI client span for that call. The span is named `{operation} {model}` (`operation` defaults to `chat`) and carries `gen_ai.operation.name`, `gen_ai.request.model` and `gen_ai.provider.name`. Inside the callback, `setInput` and `setOutput` record `gen_ai.input.messages` and `gen_ai.output.messages` when `captureContent` is true; use the OpenTelemetry GenAI message shape (`{ role, parts: [{ type: "text", content }] }`). `setUsage` records provider-reported token counts; unknown usage stays absent.

```ts
const response = await hue.model(
  "gpt-5-mini",
  async (span) => {
    span.setInput(
      messages.map((message) => ({
        role: message.role,
        parts: [{ type: "text", content: message.content }],
      })),
    );
    const response = await openai.chat.completions.create({ model: "gpt-5-mini", messages });
    span.setOutput(
      response.choices.map((choice) => ({
        role: choice.message.role,
        parts: [{ type: "text", content: choice.message.content ?? "" }],
        finish_reason: choice.finish_reason,
      })),
    );
    span.setUsage({
      inputTokens: response.usage?.prompt_tokens,
      outputTokens: response.usage?.completion_tokens,
    });
    return response;
  },
  { provider: "openai" },
);
```

Like `withSpan`, the options come after the callback and also accept `name`, `sessionId`, `userId`, `workspaceId`, `input` and `parentContext`. Pass `systemInstructions` and `tools` when you send them separately from the messages. For tools the provider runs itself, such as OpenAI hosted MCP or web search, call [`hue.recordProviderToolCalls(response)`](/reference/typescript#provider-executed-tools) inside the callback. `hue.recordMessages({ input, output })` inside the callback emits a correlated `gen_ai.client.inference.operation.details` log record that inherits the request metadata; pass `operation`, `provider` and `model` explicitly outside a `model()` span. Use either span attributes or the log record for a given content event.

Across processes, call `hue.inject(carrier)` inside the producing span and pass `hue.extract(carrier)` as `parentContext` in the worker. Both carry W3C `traceparent` only, never the API key or baggage, and `inject()` keeps propagating the application's own trace context when the client is disabled. Hue registers no global propagator or context manager. When your application has registered a context manager, `withSpan`, `tool` and `model` also make their span the active OpenTelemetry span while the callback runs, so spans from instrumentations that use the global API parent under it.

## Vercel AI SDK

The `hueTelemetry` adapter requires AI SDK 7 and an OTel integration 1 peer. Installed-package tests cover pairs `7.0.99 / 1.0.99` and `7.0.100 / 1.0.100`. Install one matching pair when using the integration:

```sh
bun add ai@7.0.99 @ai-sdk/otel@1.0.99
```

Import `hueTelemetry` from `@hue-run/sdk/ai-sdk` and pass `telemetry: hueTelemetry(hue)` to your agent or generation call. The helper forwards your explicit content choice to `recordInputs` and `recordOutputs`. Consume a streaming response inside the surrounding `hue.withSpan` callback, then flush after it finishes. See the [Example chatbot](/integrations/reference-chatbot) for a complete streaming application.

For AI SDK 6, import `hueExperimentalTelemetry` from `@hue-run/sdk` and pass `experimental_telemetry: hueExperimentalTelemetry(hue)` to each call. It needs no `@ai-sdk/otel` peer; the generated spans parent under `withSpan`, inherit session and user identifiers, and record prompts and responses only when `captureContent` is true. `hueTelemetry` reads the installed `ai` major version once per process and throws a `TypeError` below 7. Do not upgrade an application's AI SDK only to add tracing.

If your app already registers a global AI SDK integration, preserve it and attach Hue to the same OpenTelemetry provider. A per-call `telemetry` integration replaces the global AI SDK integration for that call. Follow [existing OpenTelemetry](/integrations/opentelemetry) when you need multiple exporters.

## Verify

Finish a real application request and retain its trace ID and known span IDs. End its spans, flush the provider that owns them, then flush Hue. When borrowing a provider, flush that provider first. Verification does not run the app, invoke a model, or flush telemetry.

```ts
await hue.flush();
const confirmation = await hue.verifyTrace(requestTraceId, {
  expectedSpanIds: [requestSpanId],
  requiredFields: ["model"],
  timeoutMillis: 10_000,
});
if (!confirmation.verified) {
  throw new Error("Expected trace evidence did not arrive before the deadline.");
}
console.log(confirmation.receipt?.traceUrl);
```

Only require fields the request should emit and your capture policy permits. Supported names are `input`, `output`, `model`, `usage`, and `session`. With content capture, add `input` and `output` to confirm the request's content arrived. Omit them for metadata-only capture, and omit `usage` when the instrumentation does not report it.

The receipt reports stored field presence, span counts, and missing expected spans. It contains no captured values. A successful result confirms the conditions you requested; inspect the trace in Hue to check the content and redaction. See the [verification API](/reference/typescript#trace-verification) for limits and failures.

## Production setup

Keep tracing best effort in a serving application: an outage should reduce observability, not prevent an answer. Hue follows OpenTelemetry's [runtime error containment](https://opentelemetry.io/docs/specs/otel/error-handling/) and [bounded-resource principles](https://opentelemetry.io/docs/specs/otel/performance/). Use a **Tracing only** project service key for application requests; use **Read and write** only when the same process also calls evaluation APIs, and keep that key off production servers.

The SDK suppresses its own export traffic from OpenTelemetry instrumentation. Snapshot boundaries reject unsupported values; TypeScript also handles Proxies and typed bytes without bypassing queue budgets. Verify your dependency and instrumentor combination in CI.

### Verify setup outside request handling

Run the strict [quickstart](/quickstart), connection check and [trace receipt verification](#verify) during setup, not in readiness or customer requests.

Create one client per serving process with the safe constructor and background export. Use safe lifecycle methods at the lifecycle boundary; never rerun an agent after a telemetry error because tools may have caused side effects.

```ts
import { createHueSafe, type JsonValue } from "@hue-run/sdk";

export const hue = createHueSafe({
  apiKey: process.env.HUE_API_KEY ?? "",
  serviceName: "customer-agent",
  captureContent: process.env.HUE_CAPTURE_CONTENT !== "false", // Content is on unless explicitly disabled.
  enabled: process.env.HUE_TRACING_ENABLED !== "false",
  maxQueueBytes: 8 * 1024 * 1024,
});

// Call your existing agent exactly once. Preserve its result and exceptions.
export async function handleRequest(input: JsonValue) {
  return hue.withSpan("agent.request", async (span) => {
    const result = await existingAgent(input);
    span.setOutput(result);
    return result;
  }, { input });
}

// At process shutdown, after stopping new requests:
export async function shutdownTracing() {
  return hue.shutdownSafe({ timeoutMillis: 1000 });
}
// Register shutdownTracing in your shutdown hook; observe its result without throwing.
```

`existingAgent` is your function. Register shutdown in the process hook. For serverless, flush in the supported after-response lifecycle; do not shut down shared providers per request.

### Failure behavior

Hue omits unsafe content or redactor failures, records instrumentation failure and preserves application results and errors. Safe initialization returns a disabled client on setup failure; helpers still execute application work.

Safe lifecycle methods return failure results. A timeout neither proves delivery nor cancels an in-flight request. `createHue`, checks, verification and strict lifecycle methods remain diagnostic and may fail.

Queues limit records and bytes, including in-flight records. `maxQueueBytes` defaults to 8 MiB shared by traces and logs. Separately, the SDK can hold up to 128 MiB of over-limit strings in a span's own attributes and recorded media and explicitly requested file uploads while they await upload; log records, other events, links and resources do not upload. This bounds queued telemetry, not process RSS. Overflow drops telemetry and updates counters without retrying business work.

Network retries are bounded. Shutdown counts discards; process kill, full queues, disabled clients and exporter failures can lose telemetry. There is no disk spool or delivery guarantee.

In-process code cannot prevent termination, OOM, stalls or third-party hooks. Keep redactors fast and offline. Safe construction cannot catch import or dependency failures, so verify startup in CI or guard the integration.

### Kill switch and monitoring

The snippets read `HUE_TRACING_ENABLED`; set it to `false` and restart to bypass Hue without changing application code. It is not a remote flag. Strict constructors also accept `enabled: false`; a disabled client needs neither a key nor capture settings.

Inspect `hue.transport.getReport()` for failures, drops, pending bytes and exports. Counters are cumulative; pending bytes and records are current gauges. Emit only sanitized counts and status, never credentials, content or raw provider exceptions, and do not send health signals only through Hue.

Before rollout, test your real entry point against a loopback receiver that returns 503, rejects its key, delays its response and exceeds queue capacity. Verify that each tool runs once, results and errors match an uninstrumented request, and shutdown meets your deadline. Start with a small canary.

### Delivery failures

`flush()` drains traces and logs. Partial rejection, malformed acknowledgement, queue overflow, and export failure raise `HueExportError`. Its report contains cumulative accepted, rejected, failed, and pending counts; `hue.transport.getIssues()` returns recent sanitized issues.

Transient HTTP 500 responses are retried within the existing retry and timeout budgets. A 429 `Retry-After` keeps records queued for up to 60 seconds; a longer wait is reported as a failed export. Check `uploadedValues` and `uploadFallbacks` in `hue.transport.getReport()`; upload fallbacks are warnings and do not fail a flush. A partially rejected batch is not resent wholesale, and a later successful flush does not erase earlier failures from cumulative counters.

Stop starting operations before shutdown. End active spans, await `flush()`, and await `shutdown()` before the process exits. The queues are in memory and cannot recover records after process termination.
