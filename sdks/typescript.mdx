Use the Hue TypeScript SDK to trace your server-side application, tools, and model integrations. Your application continues to call the model provider directly.

For option defaults and method signatures, see the [TypeScript API reference](/reference/typescript). Check the [compatibility matrix](/sdks/compatibility) before adding Hue to an existing application.

## Install

Use Node.js 22 or 24, or Bun 1.4. [Install the TypeScript SDK](/quickstart#typescript), then configure your key below. The package is ESM; CommonJS applications on Node.js 22.12 or later load it with `require("@hue-run/sdk")`. Check the [compatibility matrix](/sdks/compatibility) if your application already uses AI SDK or OpenTelemetry. Besides the core entry point, the package exposes `@hue-run/sdk/ai-sdk`, `@hue-run/sdk/evals`, `@hue-run/sdk/environment` and `@hue-run/sdk/managed`. `@hue-run/sdk/evals` needs the optional `zod` peer (`npm install zod`, 4.6.5 or later); [simulations](/evaluations/simulations) use it together with `@hue-run/sdk/environment`.

## Configure your project

Create a **Tracing only** project service key in **Settings → Integrations & API keys**. Put it in your server environment as `HUE_API_KEY`. Keep environment files out of Git and never expose this key to a browser.

**Tracing only** covers ingestion, connection checks, and known-trace receipt verification. Use **Read and write** when the same process also creates eval sets, evaluators, runs, simulations, environments or managed runs. See [Project keys](/quickstart#project-keys) for access and rotation.

Hue Cloud is the default destination; no base URL is needed. See [connection settings](/quickstart#connection-settings) when using another origin. HTTPS is required except for loopback HTTP. `allowInsecureHttp: true` permits plain HTTP to another host, such as a docker-compose or in-cluster collector, and records a one-time warning issue because the key then travels unencrypted. The SDK reads no `OTEL_EXPORTER_OTLP_*` environment variables; pass configuration explicitly.

`serviceName`, `serviceVersion` and `resourceAttributes` (for example `{ "deployment.environment.name": "production" }`) describe the deployment on a client that owns its providers; `serviceName` and `serviceVersion` take precedence over same-named keys. When you attach Hue to your own providers, they own the resource and `resourceAttributes` is ignored with a warning issue.

## Send your first trace

Save this as `trace.ts` in a package whose `package.json` contains `"type": "module"` (or name the file `trace.mts`). It traces a deterministic uppercase tool; it makes no model call.

```ts
import { createHue, HueExportError } from "@hue-run/sdk";

async function main() {
  const apiKey = process.env.HUE_API_KEY;
  if (!apiKey) throw new Error("Set HUE_API_KEY in your server environment.");

  const hue = createHue({
    apiKey,
    serviceName: "uppercase-demo",
    captureContent: true, // Record inputs and outputs alongside timing and metadata.
    onExportIssue: (issue) => {
      console.error("Hue export issue", issue.kind, issue.signal, issue.count);
    },
  });

  try {
    await hue.checkConnection(); // Verify which project the key belongs to.
    // The tool call becomes a child of this request span.
    await hue.withSpan(
      "demo.run",
      async (run) => {
        const result = await hue.tool("uppercase", "hello", () => "hello".toUpperCase());
        run.setOutput(result);
        console.log("Trace ID:", run.traceId);
      },
      { sessionId: "demo-session", input: "hello" },
    );
    const report = await hue.flush(); // Confirm delivery before the process exits.
    console.log("Acknowledged spans:", report.acceptedSpans);
  } finally {
    await hue.shutdownSafe({ timeoutMillis: 1000 });
  }
}

try {
  await main();
} catch (error) {
  if (error instanceof HueExportError) {
    console.error("Hue did not acknowledge all telemetry", error.report);
  } else {
    console.error("The example failed. Check your connection and server configuration.");
  }
  process.exitCode = 1;
}
```

Run it with your environment already configured:

```sh
node trace.ts
```

Open **Traces** in the project that owns the key. The root span and its `execute_tool uppercase` child share the printed trace ID. With `captureContent: true`, both spans show the input `hello` and the output `HELLO` alongside timing and identity metadata.

`checkConnection()` rejects with `HueConnectionError` when the key or origin is wrong. Its fixed message is safe to log; `status` carries the HTTP status when Hue answered, and `cause` carries the underlying network, timeout or parsing error.

## Content capture

For a copyable email-masking callback and guidance on custom field rules, follow [Redaction](/guides/redaction).

`captureContent` defaults to `true` for an enabled client; set it to `false` to opt out. Use `true`: Hue can only show and evaluate what a trace records. Use `false` for metadata-only capture when you'd rather not send content, or when an application or data policy forbids sending it to another service. A disabled client (`enabled: false`) exports nothing and defaults it to `false`.

- `true`, the recommended setting, captures content you provide to supported helpers and instrumentations: prompts and messages, responses and tool inputs and outputs, alongside model, usage, timing and errors. Hue stores received content under your project’s [retention policy](/guides/redaction#retention). Before export, the SDK scrubs credentials in recorded tool definitions and uploads inline files over 64 KiB in recorded messages; see the [content policy](/reference/typescript#content-policy).
- `false` disables Hue helper content and removes recognized GenAI, Vercel AI SDK, OpenInference, and OpenLLMetry content fields before Hue exports them, including spans from other instrumentations on a shared provider. It also removes log bodies, status descriptions and exception text. The exported `contentPrefixes` array lists the removed keys.
- `redact(value, path)` can transform supported strings before export. Redactor and capture failures omit unsafe content and increment instrumentation failure counters without changing application results.

Helper spans record a failed callback's `error.type` (the error's `name`), an ERROR status and an `exception` event carrying only the type. Exception messages and stack traces are never recorded, whatever `captureContent` is; keep them in application logs.

Queued records snapshot supported values when a span ends or a log is emitted, so later caller mutation cannot increase the retained queue size or change exported data. Resource attributes still awaiting detection are omitted with a sanitized warning; later records include them once detection finishes. Await resource detection before instrumentation if those attributes are required.

Custom attribute names cannot be classified automatically. Keep secrets and unnecessary user content out of span names, identifiers, resource metadata, and arbitrary attributes. The setting applies to Hue's export path, not another exporter in your application.

Missing usage stays missing: the SDK does not estimate tokens or cost. Captured JSON `null`, `false`, `0`, and an empty string remain distinct from absent content.

## Model spans and context

When you call a provider SDK directly, `hue.model(model, callback, options)` creates the GenAI client span for that call. The span is named `{operation} {model}` (`operation` defaults to `chat`) and carries `gen_ai.operation.name`, `gen_ai.request.model` and `gen_ai.provider.name`. Inside the callback, `setInput` and `setOutput` record `gen_ai.input.messages` and `gen_ai.output.messages` when `captureContent` is true; use the OpenTelemetry GenAI message shape (`{ role, parts: [{ type: "text", content }] }`). `setUsage` records provider-reported token counts; unknown usage stays absent.

```ts
const response = await hue.model(
  "gpt-5-mini",
  async (span) => {
    span.setInput(
      messages.map((message) => ({
        role: message.role,
        parts: [{ type: "text", content: message.content }],
      })),
    );
    const response = await openai.chat.completions.create({ model: "gpt-5-mini", messages });
    span.setOutput(
      response.choices.map((choice) => ({
        role: choice.message.role,
        parts: [{ type: "text", content: choice.message.content ?? "" }],
        finish_reason: choice.finish_reason,
      })),
    );
    span.setUsage({
      inputTokens: response.usage?.prompt_tokens,
      outputTokens: response.usage?.completion_tokens,
    });
    return response;
  },
  { provider: "openai" },
);
```

Like `withSpan`, the options come after the callback and also accept `name`, `sessionId`, `userId`, `workspaceId`, `input` and `parentContext`. Pass `systemInstructions` and `tools` when you send them separately from the messages. For tools the provider runs itself, such as OpenAI hosted MCP or web search, call [`hue.recordProviderToolCalls(response)`](/reference/typescript#provider-executed-tools) inside the callback. `hue.recordMessages({ input, output })` inside the callback emits a correlated `gen_ai.client.inference.operation.details` log record that inherits the request metadata; pass `operation`, `provider` and `model` explicitly outside a `model()` span. Use either span attributes or the log record for a given content event.

Across processes, call `hue.inject(carrier)` inside the producing span and pass `hue.extract(carrier)` as `parentContext` in the worker. Both carry W3C `traceparent` only, never the API key or baggage, and `inject()` keeps propagating the application's own trace context when the client is disabled. Hue registers no global propagator or context manager. When your application has registered a context manager, `withSpan`, `tool` and `model` also make their span the active OpenTelemetry span while the callback runs, so spans from instrumentations that use the global API parent under it.

## Vercel AI SDK

The `hueTelemetry` adapter requires AI SDK 7 and an OTel integration 1 peer. Installed-package tests cover pairs `7.0.99 / 1.0.99` and `7.0.100 / 1.0.100`. Install one matching pair when using the integration:

```sh
bun add ai@7.0.99 @ai-sdk/otel@1.0.99
```

Import `hueTelemetry` from `@hue-run/sdk/ai-sdk` and pass `telemetry: hueTelemetry(hue)` to your agent or generation call. The helper forwards your explicit content choice to `recordInputs` and `recordOutputs`. Consume a streaming response inside the surrounding `hue.withSpan` callback, then flush after it finishes. See the [Example chatbot](/integrations/reference-chatbot) for a complete streaming application.

For AI SDK 6, import `hueExperimentalTelemetry` from `@hue-run/sdk` and pass `experimental_telemetry: hueExperimentalTelemetry(hue)` to each call. It needs no `@ai-sdk/otel` peer; the generated spans parent under `withSpan`, inherit session and user identifiers, and record prompts and responses only when `captureContent` is true. `hueTelemetry` reads the installed `ai` major version once per process and throws a `TypeError` below 7. Do not upgrade an application's AI SDK only to add tracing.

If your app already registers a global AI SDK integration, preserve it and attach Hue to the same OpenTelemetry provider. A per-call `telemetry` integration replaces the global AI SDK integration for that call. Follow [existing OpenTelemetry](/integrations/opentelemetry) when you need multiple exporters.

## Verify

Finish a real application request and retain its trace ID and known span IDs. End its spans, flush the provider that owns them, then flush Hue. When borrowing a provider, flush that provider first. Verification does not run the app, invoke a model, or flush telemetry.

```ts
await hue.flush();
const confirmation = await hue.verifyTrace(requestTraceId, {
  expectedSpanIds: [requestSpanId],
  requiredFields: ["model"],
  timeoutMillis: 10_000,
});
if (!confirmation.verified) {
  throw new Error("Expected trace evidence did not arrive before the deadline.");
}
console.log(confirmation.receipt?.traceUrl);
```

Only require fields the request should emit and your capture policy permits. Supported names are `input`, `output`, `model`, `usage`, and `session`. With content capture, add `input` and `output` to confirm the request's content arrived. Omit them for metadata-only capture, and omit `usage` when the instrumentation does not report it.

The receipt reports stored field presence, span counts, and missing expected spans. It contains no captured values. A successful result confirms the conditions you requested; inspect the trace in Hue to check the content and redaction. See the [verification API](/reference/typescript#trace-verification) for limits and failures.

## Production setup

Keep tracing best effort in a serving application: an outage should reduce observability, not prevent an answer. Hue follows OpenTelemetry's [runtime error containment](https://opentelemetry.io/docs/specs/otel/error-handling/) and [bounded-resource principles](https://opentelemetry.io/docs/specs/otel/performance/). Use a **Tracing only** project service key for application requests; use **Read and write** only when the same process also calls evaluation APIs, and keep that key off production servers.

The SDK suppresses its own export traffic from OpenTelemetry instrumentation. Snapshot boundaries reject unsupported values; TypeScript also handles Proxies and typed bytes without bypassing queue budgets. Verify your dependency and instrumentor combination in CI.

### Verify setup outside request handling

Run the strict [quickstart](/quickstart), connection check and [trace receipt verification](#verify) during setup, not in readiness or customer requests.

Create one client per serving process with the safe constructor and background export. Use safe lifecycle methods at the lifecycle boundary; never rerun an agent after a telemetry error because tools may have caused side effects.

```ts
import { createHueSafe, type JsonValue } from "@hue-run/sdk";

export const hue = createHueSafe({
  apiKey: process.env.HUE_API_KEY ?? "",
  serviceName: "customer-agent",
  captureContent: process.env.HUE_CAPTURE_CONTENT !== "false", // Content is on unless explicitly disabled.
  enabled: process.env.HUE_TRACING_ENABLED !== "false",
  maxQueueBytes: 8 * 1024 * 1024,
});

// Call your existing agent exactly once. Preserve its result and exceptions.
export async function handleRequest(input: JsonValue) {
  return hue.withSpan("agent.request", async (span) => {
    const result = await existingAgent(input);
    span.setOutput(result);
    return result;
  }, { input });
}

// At process shutdown, after stopping new requests:
export async function shutdownTracing() {
  return hue.shutdownSafe({ timeoutMillis: 1000 });
}
// Register shutdownTracing in your shutdown hook; observe its result without throwing.
```

`existingAgent` is your function. Register shutdown in the process hook. For serverless, flush in the supported after-response lifecycle; do not shut down shared providers per request.

### Failure behavior

Hue omits unsafe content or redactor failures, records instrumentation failure and preserves application results and errors. Safe initialization returns a disabled client on setup failure; helpers still execute application work.

Safe lifecycle methods return failure results. A timeout neither proves delivery nor cancels an in-flight request. `createHue`, checks, verification and strict lifecycle methods remain diagnostic and may fail.

Queues limit records and bytes, including in-flight records. `maxQueueBytes` defaults to 8 MiB shared by traces and logs; separately, the SDK can hold up to 128 MiB of large values and inline files awaiting upload. This bounds queued telemetry, not process RSS. Overflow drops telemetry and updates counters without retrying business work.

Network retries are bounded. Shutdown counts discards; process kill, full queues, disabled clients and exporter failures can lose telemetry. There is no disk spool or delivery guarantee.

In-process code cannot prevent termination, OOM, stalls or third-party hooks. Keep redactors fast and offline. Safe construction cannot catch import or dependency failures, so verify startup in CI or guard the integration.

### Kill switch and monitoring

The snippets read `HUE_TRACING_ENABLED`; set it to `false` and restart to bypass Hue without changing application code. It is not a remote flag. Strict constructors also accept `enabled: false`; a disabled client needs neither a key nor capture settings.

Inspect `hue.transport.getReport()` for failures, drops, pending bytes and exports. Counters are cumulative; pending bytes and records are current gauges. Emit only sanitized counts and status, never credentials, content or raw provider exceptions, and do not send health signals only through Hue.

Before rollout, test your real entry point against a loopback receiver that returns 503, rejects its key, delays its response and exceeds queue capacity. Verify that each tool runs once, results and errors match an uninstrumented request, and shutdown meets your deadline. Start with a small canary.

### Delivery failures

`flush()` drains traces and logs. Partial rejection, malformed acknowledgement, queue overflow, and export failure raise `HueExportError`. Its report contains cumulative accepted, rejected, failed, and pending counts; `hue.transport.getIssues()` returns recent sanitized issues.

Transient HTTP 500 responses are retried within the existing retry and timeout budgets. A 429 `Retry-After` keeps records queued for up to 60 seconds; a longer wait is reported as a failed export. Check `uploadedValues` and `uploadFallbacks` in `hue.transport.getReport()`; upload fallbacks are warnings and do not fail a flush. A partially rejected batch is not resent wholesale, and a later successful flush does not erase earlier failures from cumulative counters.

Stop starting operations before shutdown. End active spans, await `flush()`, and await `shutdown()` before the process exits. The queues are in memory and cannot recover records after process termination.
