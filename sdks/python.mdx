Use the Hue Python SDK to trace your application with OpenTelemetry spans and correlated logs. Provider requests stay in your application.

For option defaults and method signatures, see the [Python API reference](/reference/python). Check the [compatibility matrix](/sdks/compatibility), including the accepted OpenTelemetry range, before adding Hue to an existing application.

## Install

Use Python 3.10 or later. [Install the Python SDK](/quickstart#python), then configure your key below. Tests cover Python 3.10 and 3.14 with OpenTelemetry 1.44.0, the certified combination, and OpenTelemetry 1.40.0, the declared floor; the SDK accepts `>=1.40,<2`.

## Configure your project

Create a **Tracing only** project service key in **Settings → API keys** and set `HUE_API_KEY` in your server environment. Keep it out of browser code and Git.

**Tracing only** covers ingestion, connection checks, and known-trace receipt verification. Use **Read and write** when the same process also creates eval sets, evaluators, runs or managed runs. See [Project keys](/quickstart#project-keys) for access and rotation. The SDK connects to Hue Cloud by default. Other origins are covered in [connection settings](/quickstart#connection-settings).

Pass the key as the `api_key=` keyword. The first positional parameter is `base_url`, so a bare key in that position raises `TypeError` naming `api_key=`; existing `Hue(base_url, api_key)` calls keep working. The constructor reads no environment variables.

## Send your first trace

Save this as `trace.py`. It traces a deterministic addition tool without making a model call.

```python
import os
from hue_sdk import Hue

hue = Hue(
    api_key=os.environ["HUE_API_KEY"],
    service_name="addition-demo",
    capture_content=True,  # Record inputs and outputs alongside timing and metadata.
)

try:
    hue.validate_project()  # Verify which project the key belongs to.
    # Keep related requests in the same conversation.
    with hue.context(session_id="demo-session"):
        with hue.span("demo.run") as run:
            run.set_input({"a": 2, "b": 2})
            with hue.tool("add") as tool:
                tool.set_input({"a": 2, "b": 2})
                result = 2 + 2
                tool.set_output(result)
            run.set_output(result)
            print("Trace ID:", run.trace_id)

    # Confirm delivery before the process exits.
    if not hue.force_flush(timeout_millis=30_000):
        print("Export counters:", hue.export_status)
        raise RuntimeError("Hue did not acknowledge all telemetry.")
finally:
    hue.shutdown_safe(timeout_millis=1000)
```

Run it with your environment already configured:

```sh
.venv/bin/python trace.py
```

Open **Traces** in the project that owns the key. The root span and its `execute_tool add` child share the printed trace ID. Both show the input `{"a": 2, "b": 2}` and the output `4` because this example captures content.

## Content capture

For a copyable email-masking callback and guidance on custom field rules, follow [Redaction](/guides/redaction).

`capture_content` defaults to `True`; set it to `False` to opt out. Use `True`, the recommended setting: Hue can only show and evaluate what a trace records. `True` captures content supplied through Hue's input, output, tool, and inference-log helpers, such as prompts and messages, responses and tool inputs and outputs. Use `False` for metadata-only capture when you'd rather not send content, or when an application or data policy forbids sending it to another service; it omits that content before it enters an OpenTelemetry queue. Received content is stored under your project’s [retention policy](/guides/redaction#retention).

With `capture_content=False`, Hue also strips recognized GenAI, OpenInference, OpenLLMetry and Vercel AI SDK content attributes, legacy `gen_ai.*` message events, log bodies and status descriptions from every record it exports, including spans from third-party instrumentors on the same provider. The [compatibility matrix](/sdks/compatibility) lists the keys, which are identical to TypeScript's `contentPrefixes`. The setting does not classify arbitrary attribute names, span names, session IDs or another exporter's records, and unrecognized custom keys pass through. Configure an instrumentor's own content controls before enabling it; it may also send content to other exporters.

For helper content, `redactor(field, value)` receives a detached copy and can return a redacted JSON value before serialization. Mutating that copy does not change application inputs or results, even if the redactor then raises. When uploads are available, snapshots and redactors accept supported values up to 1 GB and 1,048,576 visited values and keys; otherwise the snapshot is bounded to 4 MiB, depth 64 and 65,536 values and keys. Unsupported or over-budget values and redactor failures increment instrumentation failure counters without raising into application work. The callback must handle your nested data format and avoid side effects through globals or captured references; it is not applied to arbitrary external OpenTelemetry records.

The helpers always exclude exception messages and stacks, retaining error type and status. A context manager records an escaping error and rethrows it.

## Images, documents and audio

Hue stores the bytes of images, documents and audio apart from the records that mention them, named by SHA-256. The record keeps each file's digest in its place and lists the upload in its `hue.blobs` attribute. Files reach Hue in four ways:

| You have | Use | The record carries |
| --- | --- | --- |
| Files inline in the messages and values your code or framework already records | Nothing: [automatic capture](#automatically-captured-media) | The part in digest form, keyed `<attribute>#<JSON pointer>` |
| A file to place at a position in a value you record | [`Attachment`](#attach-a-file-anywhere) | A GenAI `blob` part in digest form, keyed `<attribute>#<JSON pointer>` |
| A file the work read, received or produced, outside any recorded value | [`record_file`](#record-a-file) with `upload=True` | A `hue.file` event, keyed `event:hue.file:<sha256>` |
| Files a case's agent and evaluators receive | [Case files](#files-in-evaluation-cases) | Files pinned on the case, not in a trace |

Every upload needs `capture_content=True` and a project key, never a setup key (`hue_setup_…`). The redactor runs first: nothing it removes is uploaded, and a value it rewrites uploads as rewritten. Uploads share the export's upload budget, and a file used more than once in a trace is stored once. A file that cannot be uploaded falls back without failing the export and counts in `hue.export_status.upload_fallbacks`. See [Images, audio and documents](/integrations/opentelemetry#images-audio-and-documents) for what the trace view previews, and [Read recorded media back](#read-recorded-media-back) to get the bytes again.

### Automatically captured media

With `capture_content=True`, the SDK finds files inline in these attributes of a span, uploads their bytes under the span's trace and leaves each file's digest in its place:

- **Messages and values:** `gen_ai.input.messages`, `gen_ai.output.messages`, `ai.prompt.messages`, `ai.prompt`, `input.value` and `output.value` (what `span()` records), `traceloop.entity.input` and `traceloop.entity.output`, and Langfuse's `langfuse.observation.input`, `langfuse.observation.output`, `langfuse.trace.input` and `langfuse.trace.output`.
- **Tool arguments and results:** `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result`, `ai.toolCall.args`, `ai.toolCall.result`, `tool.parameters`, `tool_arguments` and `tool_response`.
- **Metadata:** `metadata`, `langfuse.observation.metadata` and `langfuse.trace.metadata` (whole, or one `.<key>` per attribute), and `ai.telemetry.metadata.<key>`.
- **Indexed messages:** OpenLLMetry's `gen_ai.prompt.<n>.content` and `gen_ai.completion.<n>.content` when the value is the JSON of a parts list, and OpenInference's flattened `llm.input_messages.<n>.message.contents.<m>.message_content.image.image.url` and its `llm.output_messages` counterpart.

Inside those values the SDK recognizes GenAI `blob` parts, AI SDK `file` and `image` parts, OpenAI Chat image, file and audio parts and an assistant message's `audio`, Responses `input_image`, `input_file` and `computer_screenshot`, Anthropic base64 sources, Gemini `inlineData` and `inline_data`, Vertex `media`, Bedrock image and document sources, and any whole string that is a `data:` URL declaring a media type. Files inside a tool call's JSON-encoded `arguments` and a tool result's JSON string are found too.

Each uploaded file takes one of these forms:

- A provider part loses its byte field and carries `sha256` and `size`, keyed at the part, for example `gen_ai.input.messages#/0/parts/1`. An OpenAI assistant message's `audio` loses `audio.data`, and the message carries the digest.
- A whole `data:` URL string becomes a GenAI `blob` part, `{"type":"blob","mime_type":"image/png","modality":"image","sha256":"<64 hex>","size":68}`, keyed at the string. A text data URL up to 64 KiB stays inline.
- A file inside a JSON-encoded tool string takes the digest form inside the string. No JSON pointer can address inside a string, so Hue matches it by digest.
- Text media over 64 KiB of decoded bytes keeps a UTF-8-safe 16 KiB prefix in its content field, keyed at that field, for example `gen_ai.input.messages#/0/parts/1/content`. Smaller text stays inline. A text file that a GenAI `blob`, Vertex `media`, or AI SDK `file` or `image` part holds as bare base64 is decoded first, as Hue reads it: over 64 KiB of decoded bytes, it uploads and takes the digest form at the part, like binary media.

Only the file's own value, or the members of the part that held it, change; the rest of the recorded JSON text is kept byte for byte. A record lists at most 64 files in `hue.blobs`: its inline media first, in reading order, then its attachments and uploaded files. A file that is not uploaded keeps its digest without an entry in `gen_ai.input.messages`, `gen_ai.output.messages` and `ai.prompt.messages`; in any other attribute it keeps its bytes inline, under the ordinary value limit.

The SDK leaves these as recorded:

- Remote URLs, provider file IDs, S3 references and Langfuse media tokens. Neither the SDK nor Hue fetches them.
- A file more than ten levels below a value's root, attribute JSON nested past 32 levels or holding an integer past 2^53 (Hue keeps such JSON as text), and an OpenInference `input.value` or `output.value` whose record declares it `text/plain`.
- In a log record, text past 8 Mi UTF-16 code units in one attribute or 16 Mi in one record; such a value follows the ordinary value limit.

A span's own attribute past those bounds, such as a model call that carries minutes of base64 audio, is still read for files when it is exported, without parsing or copying the whole value. Each base64 or `data:` URL string in it that is longer than 16 Ki code units and written without escapes is decoded, hashed and uploaded a 1 MiB slice at a time, up to 1 GB, and takes the same digest form as above. The rest of the value's JSON must fit within 8 Mi code units; a value past that follows the ordinary value limit.

With `capture_content=False`, the SDK inspects and uploads nothing.

Log records correlated with a span upload their media the same way: the `gen_ai.client.inference.operation.details` record `log_inference()` writes, and any `gen_ai.*` event with a structured body. The log record lists its files in its own `hue.blobs`, keyed `body#<JSON pointer>` into the body, for example `body#/gen_ai.input.messages/0/parts/1`. A log record that cannot upload, such as one not correlated with a span, keeps the older rule: a file over 64 KiB in a recorded message becomes its digest, and other files keep their bytes. Resources, links and span events never upload; in their recorded messages, media up to 64 KiB stays as recorded and larger media becomes its digest.

An entry's `name` comes from the part's file name, name or title when it is valid: nonblank after trimming, at most 256 UTF-16 code units and well-formed Unicode, with no C0 control characters (U+0000–U+001F) or DEL (U+007F). An invalid name stays in the message and is left out of the entry. Data URLs and fields the provider encodes as base64 are decoded before hashing, so a part's digest matches `record_file`'s digest of the same bytes. Another string with a declared textual media type is hashed as UTF-8: `YWJj` hashes as those four characters.

### Attach a file anywhere

Wrap a file in an `Attachment` and put it in any value Hue records: a `span()` input or output, `model()` messages, a tool's arguments or result, `log_inference()` messages, or a span attribute passed to `span(attributes=...)` or `set_attribute`.

```python
from pathlib import Path

from hue_sdk import Attachment

png = Path("scan.png").read_bytes()
with hue.span(
    "review contract",
    attributes={"metadata": {"scan": Attachment(png, content_type="image/png")}},
) as span:
    span.set_input(
        {
            "question": "Which clauses changed?",
            "contract": Attachment(path="contract.pdf", content_type="application/pdf"),
        }
    )
```

Give exactly one of `data` (bytes, or a base64 string or `data:` URL) and `path`, a `content_type` and an optional `name`. `data`, limited to 25 MiB, and a file up to 25 MiB given by `path` are read and hashed when the attachment is created and stay in memory until export, within the 128 MiB held for values awaiting upload. A larger file given by `path`, up to 1 GB, is hashed when the attachment is created and streamed from disk when it uploads, so it is never held in memory. Keep such a file in place and unchanged until the client flushes: a file that changed or is gone by then is not uploaded and counts in `hue.export_status.upload_fallbacks`.

At its position the attachment is recorded as a GenAI `blob` part in digest form, `{"type":"blob","mime_type":"application/pdf","modality":"document","sha256":"<64 hex>","size":48213,"name":"contract.pdf"}`, with `modality` read from the content type. Export uploads the bytes, keyed `<attribute>#<JSON pointer to the part>`: `input.value#/contract` and `metadata#/scan` above, or `body#/gen_ai.input.messages/0/parts/1` in a `log_inference()` log record. An attribute value that is an attachment, or a JSON object or array OpenTelemetry cannot hold, is recorded as JSON text. Put files under `metadata` for Hue to list them as the span's metadata files. A value that is still over the 1 MiB inline limit with its attachments as digest parts uploads whole and keeps only its first 16 KiB inline: the attachments' bytes are stored, and `client.media.fetch(trace_id=..., sha256=...)` reads them by digest, but readers do not place them at their positions in the value.

With `capture_content=False` or a setup key (`hue_setup_…`), no bytes leave the process: a metadata attribute keeps the part without its name, and content values are not recorded. A part that the redactor removes or rewrites is not uploaded. A part that cannot be uploaded, or that sits more than 10 levels deep in its value, keeps its digest and counts in `hue.export_status.upload_fallbacks`. Creating an attachment never fails: one without exactly one of `data` and `path`, with unreadable or oversized data, or with an invalid content type is recorded as `None` and counted as an instrumentation failure. An invalid name alone is omitted and counted.

### Record a file

To record a file your application reads or produces, such as the audio of a voice turn, call `record_file` on its span:

```python
with hue.span("voice turn") as span:
    span.record_file(
        role="input",
        media_type="audio/wav",
        path="turns/0042-user.wav",
        name="user.wav",
        upload=True,
    )
    span.record_file(
        role="output",
        media_type="audio/wav",
        path="turns/0042-reply.wav",
        name="reply.wav",
        upload=True,
    )
```

Give the file as `data` (bytes, up to **25 MiB**, held in memory until export) or `path` (a file on disk, up to **1 GB**; a file over 25 MiB is streamed from disk when it uploads, as an [attachment given by path](#attach-a-file-anywhere) is). All uploads of one export share six export timeouts, 60 seconds at the default `export_timeout_seconds` of 10, so a 1 GB file needs about 17 MB/s; raise `export_timeout_seconds` for slower links. Record audio in a format the trace view plays, such as WAV, MP3 or Opus; [wrap raw PCM in a WAV header](/integrations/opentelemetry#attach-a-voice-turn) first. `upload` defaults to `False`. With `upload=True`, content capture and an ordinary project key, export uploads the bytes and adds an entry keyed `event:hue.file:<sha256>` to the same span. The `hue.file` event still records the digest, role, media type and size, and its name follows the rule above: an invalid name is left out and counted as an instrumentation failure. An upload that is not made counts in `hue.export_status.upload_fallbacks`. A span's own string attributes have a separate **1,000,000,000-byte (1 GB)** upload limit.

### Read recorded media back

The evaluation client's `media` reads a recorded file back by its digest. Use a **Read** or **Read and write** key; reading a trace snapshot's pinned copy needs **Read and write**.

```python
import json
import os

from hue_sdk.evals import EvaluationClient

client = EvaluationClient(api_key=os.environ["HUE_API_KEY"])

# One file by digest; pass the span that recorded it when you know it.
file = client.media.fetch(trace_id=trace_id, span_id=span_id, sha256=sha256)
print(file.content_type, file.file_name, file.size, len(file.data))

# Every digest part of a recorded value, written back in its own field.
recorded = json.loads(attributes["gen_ai.input.messages"])
resolved = client.media.resolve(recorded, trace_id=trace_id, span_id=span_id)
messages, failures = resolved.value, resolved.failures
```

`client.media.fetch(trace_id=..., sha256=...)` asks Hue for the five-minute link the [trace file endpoint](/integrations/opentelemetry#download-files-from-a-trace) returns, downloads it without the project key and refuses bytes whose SHA-256 is not the digest. A failure raises `MediaFetchError` with a `reason`: `not_found`, `missing` (listed but never uploaded, or erased), `unavailable`, `forbidden` (the key cannot read recorded content; a snapshot's copy needs **Read and write**), `too_large` (over `max_bytes`, 64 MiB by default), `digest_mismatch` or `failed`. `snapshot_id=` in place of `trace_id=` reads a snapshot's pinned copy, which carries no media type or name. `fetch` also reads a file that a producer without the SDK recorded inline, as a `data:` URL or base64 part of up to 1 MiB; pass `span_id=` for one in a log record.

`client.media.resolve(value, trace_id=...)` downloads each distinct digest once and returns a new value, leaving the input unchanged. With `as_="data_url"`, the default, each part gets a `data:` URL where its field takes one and bare base64 where its convention requires it, so the messages can be sent to the provider again; `as_="bytes"` writes the bytes. A part whose file cannot be read stays as it is and is listed in `failures` with its JSON pointer and reason. Text over 64 KiB that the record keeps as its first 16 KiB is never written back: pass the record's `hue.blobs` entries as `blobs`, and such a part is listed as `prefix_only`, with the SHA-256 that `fetch` reads the whole file by. Parts inside JSON-encoded strings and Langfuse media tokens are left as they are. See the [reference](/reference/python#recorded-media) for every option.

### Files in evaluation cases

`add_case` and `add_eval_set_case` pin up to 32 input files on a case with `files=`. Name an artifact the project already holds as `CaseFileWrite(role=..., artifact_id=...)`, or give the file as `CaseFileWrite(role=..., filename=..., content_type=..., data=...)` or with `path=` instead of `data=`. The client checks an uploaded file against the artifact policy (one of the [22 artifact content types](/reference/typescript#file-based-cases), a name of 1 to 255 UTF-16 code units, 1 byte to 25 MiB) and uploads it as a verified artifact before the case; sending the same case again reuses it. A file outside the policy, or a `path` that cannot be read, raises `ValueError` before any request. A file given by `path` is hashed when the case is checked and read again when it uploads, one file at a time; if it changed after the check or can no longer be read, none of its bytes are uploaded, the write raises `ValueError` and the case is not written. Files uploaded before it stay as artifacts, which sending the case again reuses.

Before an execution starts, `run_experiment` downloads the case's pinned files and checks each one's size and SHA-256. The target receives the agent-visible files (`source`, `attached_template`, `attached_reference` and `original`) as `context.files`; `org_template` and `evaluator_reference` files reach only evaluators. Recorded messages copied into a case's inputs keep their files as digest parts, and `rehydrate_media(inputs, files)` writes the case's files back into them by SHA-256:

```python
from hue_sdk.evals import rehydrate_media

# A run_experiment target: send the recorded model call again with the case's real files.
def target(inputs, context):
    messages = rehydrate_media(inputs["messages"], context.files).value
    return call_model(messages)
```

## Model metadata and correlation

Use `hue.model(model, provider=...)` for a model operation. Report known token counts with `span.set_usage(input_tokens=..., output_tokens=...)`; leave unavailable counts as `None`. Hue does not estimate missing usage.

Use `hue.context(session_id=..., user_id=...)` around related helpers. These are observed application identifiers, not Hue account identities. `Hue.inject(headers)` and `Hue.extract(headers)` support W3C trace-context propagation across services.

`span.log_inference(input=..., output=...)` emits a log correlated with that span. Use logs or span attributes for a given content event instead of storing identical copies in both. With capture enabled, an explicit `None` field keeps its key with an empty value, distinct from an absent field. With capture disabled, `log_inference` emits no record.

## Verify

Finish a real application request and retain its trace ID and known span IDs. End its spans, flush the provider that owns them, then flush Hue. When borrowing a provider, flush that provider first. Verification does not run the app, invoke a model, or flush telemetry.

```python
if not hue.force_flush():
    raise RuntimeError("Hue did not acknowledge the telemetry.")
confirmation = hue.verify_trace(
    request_trace_id,
    expected_span_ids=[request_span_id],
    required_fields=["model"],
    timeout_millis=10_000,
)
if not confirmation.verified:
    raise RuntimeError("Expected trace evidence did not arrive before the deadline.")
print(confirmation.receipt.trace_url)
```

Only require fields the request should emit and your capture policy permits. Supported names are `input`, `output`, `model`, `usage`, and `session`. With content capture, add `input` and `output` to confirm the request's content arrived. Omit them for metadata-only capture, and omit `usage` when the instrumentation does not report it.

The receipt reports stored field presence, span counts, and missing expected spans. It contains no captured values. A successful result confirms the conditions you requested; inspect the trace in Hue to check the content and redaction. See the [verification API](/reference/python#trace-verification) for limits and failures.

## Production setup

Keep tracing best effort in a serving application: an outage should reduce observability, not prevent an answer. Hue follows OpenTelemetry's [runtime error containment](https://opentelemetry.io/docs/specs/otel/error-handling/) and [bounded-resource principles](https://opentelemetry.io/docs/specs/otel/performance/). Use a **Tracing only** project service key for application requests; use **Read and write** only when the same process also calls evaluation APIs, and keep that key off production servers.

The Python SDK suppresses its own export traffic from OpenTelemetry instrumentation. If its suppression key is unavailable, Hue warns once and exports without it while its queues still ignore export work. Verify your dependency and instrumentor combination in CI.

### Verify setup outside request handling

Run the strict [quickstart](/quickstart), connection check and [trace receipt verification](#verify) during setup, not in readiness or customer requests.

Create one client per serving process with the safe constructor and background export. Initialize after fork, once per serving process. Use safe lifecycle methods at the lifecycle boundary; never rerun an agent after a telemetry error because tools may have caused side effects.

```python
import os
from hue_sdk import create_hue_safe

# Initialize after fork, once per serving process.
hue = create_hue_safe(
    api_key=os.environ.get("HUE_API_KEY"),
    service_name="customer-agent",
    capture_content=os.environ.get("HUE_CAPTURE_CONTENT") != "false",  # Content is on unless explicitly disabled.
    enabled=os.environ.get("HUE_TRACING_ENABLED") != "false",
    max_queue_bytes=8 * 1024 * 1024,
)

def handle_request(inputs):
    with hue.span("agent.request") as span:
        span.set_input(inputs)
        result = existing_agent(inputs)
        span.set_output(result)
        return result

# At process shutdown, after stopping new requests:
def shutdown_tracing():
    return hue.shutdown_safe(timeout_millis=1000)
# Register shutdown_tracing in your shutdown hook; observe its result without raising.
```

`existing_agent` is your function. Register shutdown in the process hook. For serverless, flush in the supported after-response lifecycle; do not shut down shared providers per request.

### Failure behavior

Hue omits unsafe content or redactor failures, records instrumentation failure and preserves application results and errors. Safe initialization returns a disabled client on setup failure; helpers still execute application work.

Python redactors receive detached copies. When uploads are available, snapshots and redactors accept supported helper values up to 1 GB and 1,048,576 visited values and keys; otherwise snapshots are bounded to 4 MiB, depth 64 and 65,536 values and keys. Keep redactors deterministic and side-effect free.

Safe lifecycle methods return failure results. A timeout neither proves delivery nor cancels an in-flight request. `Hue`, checks, verification and strict lifecycle methods remain diagnostic and may fail.

Queues limit records and bytes, including in-flight records. `max_queue_bytes` defaults to 8 MiB per signal. Separately, the SDK can hold up to 128 MiB of over-limit strings in a span's own attributes and recorded media and explicitly requested file uploads while they await upload; log records, other events, links and resources do not upload. This bounds queued telemetry, not process RSS. Overflow drops telemetry and updates counters without retrying business work.

Network retries are bounded. Python keeps one worker per signal; an OS-blocked call can outlive the wait and retain one encoded request (up to 1 MiB) outside queue counters. Shutdown counts discards; process kill, full queues, disabled clients and exporter failures can lose telemetry. There is no disk spool or delivery guarantee.

HTTP 429 `Retry-After` responses keep records queued for up to 60 seconds; a longer wait is reported as a failed export. Upload fallbacks increment `upload_fallbacks` and create warnings without failing `force_flush()`.

In-process code cannot prevent termination, OOM, stalls or third-party hooks. Keep redactors fast and offline. Safe construction cannot catch import or dependency failures, so verify startup in CI or guard the integration.

### Kill switch and monitoring

The snippets read `HUE_TRACING_ENABLED`; set it to `false` and restart to bypass Hue without changing application code. It is not a remote flag. Strict constructors also accept `enabled=False`; a disabled client needs neither a key nor capture settings.

Inspect `hue.export_status` for failures, drops, pending bytes, `uploaded_values` and `upload_fallbacks`. Counters are cumulative; pending bytes and records are current gauges. Emit only sanitized counts and status, never credentials, content or raw provider exceptions, and do not send health signals only through Hue.

Before rollout, test your real entry point against a loopback receiver that returns 503, rejects its key, delays its response and exceeds queue capacity. Verify that each tool runs once, results and errors match an uninstrumented request, and shutdown meets your deadline. Start with a small canary.

### Flush and shutdown

`force_flush()` drains both signals and returns a boolean. It returns `False` for a timeout or any recorded failed export batch, dropped record or instrumentation failure during this client's lifetime. Check `hue.export_status` for cumulative trace and log failure counts. HTTP errors, malformed acknowledgements, and OTLP partial rejections are failures; receiver error bodies are not echoed.

A flush timeout bounds your wait, not the ongoing network request. Both signals share the remaining deadline, including time spent waiting behind another flush. Drain coordination is released when that budget expires, so a timed-out flush does not impose a fresh wait on later calls. Background exports and shutdown cleanup can continue.

Before planned application shutdown, finish traced work and keep the process alive long enough to confirm completion. Repeated `shutdown()` calls wait for the same cleanup and report current failures and drops. Spans ending or external records emitted after Hue shuts down count as dropped, including records from a borrowed provider; new Hue helpers are no-ops. A context manager calls shutdown on exit, but you still need an explicit checked flush when your command's exit status must reflect delivery failure.

The SDK uses official OTLP HTTP exporters with protobuf encoding and their retry policy. Export requests are gzip-compressed and carry a `hue-sdk-python/<version>` User-Agent ahead of the exporter's own token. Partial rejections are not retried wholesale. Queues are in memory, so process termination and overflow can lose records. A successful flush is not proof that every application operation was instrumented.

## Existing OpenTelemetry provider

Pass your OpenTelemetry SDK tracer provider as `tracer_provider=provider`, and an existing SDK `LoggerProvider` as `logger_provider=provider` when the application already owns one. Hue adds its processors without setting the global providers. A provider Hue creates for the other signal reuses the borrowed provider's resource, so spans and correlated logs report one `service.name`; `service_name` applies only when Hue creates both providers. An instrumentor that accepts a provider can use `hue.tracer_provider` explicitly. Use one Hue client per provider lifecycle; OpenTelemetry has no public processor-removal API.

Hue shutdown leaves borrowed providers and their other processors usable. Your application remains responsible for those providers and their instrumentations.

## Evaluate locally

Import the built-in evaluator bundle as `from hue_sdk.evals import builtin_scorers`. `builtins` remains an alias, but shadows the standard-library module in files that import it. `builtin_scorers.json_schema` needs `pip install 'hue-run[evals]'`; otherwise the helper raises `ImportError` and stored schema evaluators report `SchemaValidatorUnavailable`. The tracing core depends only on OpenTelemetry packages and `requests`. See [First evaluation](/evaluations/first-evaluation) and the [Python API reference](/reference/python#run-locally-and-rescore).

## Managed runs

Expose a protected route around your existing application function with the [managed target adapter](/evaluations/managed-runs). Hue dispatches frozen cases, saves real output files and verifies trace evidence; your application retains its provider, tools and existing telemetry. Local evaluation runners remain available.
